Naive Bayes: Voting with Probabilities

Naive Bayes classifies by asking, for each class, "how likely is this point if it belonged to you?" — then picks the winner. Its one bold simplification (pretend the features are independent) makes the math trivially fast, and it works shockingly well.

▸ Do this
Drag the test point around. Each class scores it with its own bell curves; the higher combined score wins.
◈ You'll see
The background shows the predicted class everywhere; the curved boundary is where the two classes' probabilities tie. The ellipses are each class's fitted Gaussian.
—score · blue class
—score · orange class
shaded = predicted class · ellipses = per-class Gaussians · white dot = draggable test point
Drag the white test point to classify it.
What's happening: for each class we fit a simple probability model — here a Gaussian per feature, using the class's mean and variance — and estimate the class prior from how common it is. To classify a point x we use Bayes' rule: score(class) = log P(class) + Σ log P(featureᵢ | class), summing the per-feature log-likelihoods (that sum is the "naive" independence assumption). Whichever class scores higher wins, and the tie line is the decision boundary. Because it just estimates a few means and variances, Naive Bayes trains in one pass and shrugs off high-dimensional data — which is why it's a classic baseline for spam filters and text.
