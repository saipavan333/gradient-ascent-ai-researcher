Saliency: What Is the Model Looking At?

A model gives an answer — but why? A saliency map highlights which input pixels actually pushed the decision, by asking how much each one contributed. It's a first window into interpretability: seeing where the model's attention really lands.

Paint pixels on the left (click-drag) to build an input. The right panel lights up the pixels the model relied on.
◈ You'll see
Only pixels in the region the model cares about drive the score up; painting elsewhere barely moves it and stays dark in the saliency map. That's the model's "gaze" made visible.

Paint some pixels and watch the saliency map.
What's happening: the model scores the image with s = σ(Σᵢ wᵢ·xᵢ + b) — a weight wᵢ for every pixel. The saliency of a pixel is its contribution wᵢ·xᵢ (the classic "input × gradient" method; for this linear model the gradient of the score w.r.t. pixel i is just wᵢ). Pixels the model was trained to care about have large weights, so painting them lights up the saliency map and drives the score; painting ignored pixels changes little and stays dark. Real saliency does the same for deep nets by back-propagating the output to the input — a quick, imperfect check of whether a model is "looking" at the right evidence or exploiting a spurious shortcut.
