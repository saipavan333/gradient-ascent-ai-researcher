Huffman Coding: Shortest Codes for Common Symbols

If some letters appear far more often than others, why give them all equal-length codes? Huffman coding builds the provably shortest possible prefix code by a beautifully simple rule: repeatedly merge the two rarest symbols. Frequent symbols end up near the top of the tree with short codes.

What's happening: we treat each symbol as a leaf weighted by its frequency, then repeatedly take the two lowest-weight nodes and merge them under a new parent whose weight is their sum, until one tree remains. Labelling each left/right branch 0/1 and reading root→leaf gives every symbol a prefix code (no code is a prefix of another, so the stream decodes unambiguously). Because rare symbols get merged first they sink deep (long codes) while frequent symbols stay shallow (short codes), and the result is provably optimal among prefix codes. Its average length lands between the entropy H (the hard lower bound from information theory) and H+1 bit. This is source coding & compression.
