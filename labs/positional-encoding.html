Positional Encoding

A transformer sees all tokens at once, so it has no built-in sense of order — "dog bites man" and "man bites dog" would look identical. Positional encoding fixes this by stamping each position with a unique fingerprint of sine and cosine waves, letting the model recover where every token sits.

▸ Do this
Slide to pick a position. Its encoding is one row of the heatmap; the lower curve shows how similar it is to every other position.
◈ You'll see
Every position gets a distinct wave pattern (low dimensions wiggle fast, high ones slow). Similarity peaks at the chosen position and falls off smoothly — so the model can read relative distance.
heatmap: rows = positions, columns = dimensions · lower panel: similarity of the chosen position to all others
Slide the position to inspect its encoding.
What's happening: for position pos and dimension i, the encoding is PE(pos, 2i) = sin(pos ⁄ 10000^{2i/d}) and PE(pos, 2i+1) = cos(pos ⁄ 10000^{2i/d}). Each dimension is a wave of a different wavelength — fast on the left, geometrically slower to the right — so stacking them gives every position a unique code (top heatmap). The magic is that the dot product between two positions' codes depends mainly on their distance (bottom curve peaks at the selected position and decays), which means a linear layer can recover relative offsets — the reason sinusoids are used instead of raw position numbers. This vector is simply added to each token's embedding. This is Positional encoding.
