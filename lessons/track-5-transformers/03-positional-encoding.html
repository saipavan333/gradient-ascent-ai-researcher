Positional encodings

Attention has a surprising blind spot: it treats a sentence as a bag of words, with no sense of order. "Dog bites man" and "man bites dog" look identical to it. Positional encodings fix this by stamping each token with where it sits — restoring the sequence to the sequence model.

We have quietly ignored something huge. Everything attention does — dot products, softmax, weighted sums — works on a set of tokens, not a sequence. Shuffle the words and you get exactly the same computation, just reordered. That means a raw transformer literally cannot tell "dog bites man" from "man bites dog," even though those sentences mean opposite things. For a model of language, that is fatal. This lesson adds the missing ingredient — a way to tell each token where it stands — using nothing more exotic than sine and cosine waves.

💡 Intuition: give every word a "where am I" stamp

Why is attention order-blind? Look back at the machinery. The attention weight between token \(i\) and token \(j\) depends only on their content vectors, never on where they sit. So if you permute (reshuffle) the input tokens, every pairwise comparison is the same — you just relabel who is who. Mathematically, attention is permutation-equivariant: reorder the input, and the output simply reorders to match, carrying no new information about position.

\[ \operatorname{Attention}(PX) = P\,\operatorname{Attention}(X) \quad\text{for any permutation } P \] (1)

In words: shuffling the rows of the input \(X\) with a reordering \(P\) just shuffles the output rows the same way — order carries no meaning of its own. To break this symmetry, we must physically write the position into each token's vector before attention ever sees it.

The naive stamp — "this is word number 5" as the integer 5 — is a bad idea: positions in a long document grow into the thousands, dwarfing the embedding's small numbers and refusing to generalize to lengths never seen in training. We want a stamp that is always a modest size, yet unique for every position, and that makes "5 apart" look the same whether you are at position 2 or position 200. The trick: describe position with a set of clocks. A wall clock pins down the time with hands moving at different speeds — a fast second hand for fine detail, a slow hour hand for the big picture. Use many sine and cosine waves of different speeds and, together, they give every position a unique fingerprint that stays neatly bounded between \(-1\) and \(1\).

Concretely, for position \(pos\) and dimension-pair index \(i\), the sinusoidal positional encoding fills even dimensions with a sine and odd dimensions with a cosine:

\[ PE_{(pos,\,2i)} = \sin\!\left(\frac{pos}{10000^{\,2i/d}}\right), \qquad PE_{(pos,\,2i+1)} = \cos\!\left(\frac{pos}{10000^{\,2i/d}}\right) \] (2)

Every symbol: \(pos\) is the token's position in the sequence (0, 1, 2, …); \(d\) is the embedding width; \(i\) runs over dimension pairs from 0 up to \(d/2-1\), so dimensions come in sine/cosine couples; and \(10000\) is a chosen constant that sets how wide the range of clock speeds is. The exponent \(2i/d\) grows from 0 to almost 1 as \(i\) increases, so the divisor \(10000^{\,2i/d}\) grows from 1 up to about 10000 — meaning low dimensions have a tiny divisor and wiggle fast, while high dimensions have a large divisor and wiggle slowly. The wavelength (how many positions before the wave repeats) is:

\[ \lambda_i = 2\pi \cdot 10000^{\,2i/d} \quad\text{(from } 2\pi \text{ up to } 10000\cdot 2\pi\text{)} \] (3)

Finally, we do not concatenate this stamp — we simply add it to the token embedding, so each input vector now carries both meaning and position in the same slots:

\[ x_{pos} = \operatorname{embed}(\text{token}) + PE_{pos} \] (4)

✍️ Worked example: encode the first three positions

Use a tiny width \(d = 4\), so there are two dimension pairs: \(i=0\) with divisor \(10000^{0/4}=1\), and \(i=1\) with divisor \(10000^{2/4}=\sqrt{10000}=100\). The four dimensions are \([\sin(pos/1),\ \cos(pos/1),\ \sin(pos/100),\ \cos(pos/100)]\).

1
Position 0. \(\sin 0 = 0,\ \cos 0 = 1\) for both bands, so \(PE_0 = [\,0,\ 1,\ 0,\ 1\,]\). Every sequence starts from the same anchor.
2
Position 1. Fast band: \(\sin 1 = 0.84,\ \cos 1 = 0.54\). Slow band: \(\sin(0.01)=0.01,\ \cos(0.01)=1.00\). So \(PE_1 = [\,0.84,\ 0.54,\ 0.01,\ 1.00\,]\).
3
Position 2. Fast band: \(\sin 2 = 0.91,\ \cos 2 = -0.42\). Slow band: \(\sin(0.02)=0.02,\ \cos(0.02)=1.00\). So \(PE_2 = [\,0.91,\ -0.42,\ 0.02,\ 1.00\,]\).
4
Read the pattern. The fast pair swings dramatically from position to position (great for telling neighbors apart); the slow pair barely moves (great for coarse, long-range location). Each position gets a distinct fingerprint, and we add it to that token's embedding. Two positions can never collide, because at least the fast dimensions will differ — the whole point of stacking many clock speeds.

🛠️ From scratch: sinusoidal positions

import numpy as np

def positional_encoding(seq_len, d, base=10000.0):
    pos  = np.arange(seq_len)[:, None]        # (L, 1): positions 0,1,2,...
    i    = np.arange(d // 2)[None, :]         # (1, d/2): dimension-pair index
    freq = 1.0 / (base ** (2*i / d))          # each pair gets its own frequency
    angle = pos * freq                        # (L, d/2): position times frequency
    PE = np.zeros((seq_len, d))
    PE[:, 0::2] = np.sin(angle)               # even dimensions: sine
    PE[:, 1::2] = np.cos(angle)               # odd dimensions:  cosine
    return PE

X = token_embeddings + positional_encoding(seq_len, d)   # add "where" onto "what"

⚠️ Mistakes everyone makes here

  • Thinking the position is concatenated. It is added to the embedding, sharing the same dimensions, so each vector holds meaning and position together — no extra width.
  • Using the raw integer position. Unbounded and scale-breaking: at position 3000 the stamp would drown out the embedding. Sinusoids stay in \([-1,1]\) and encode position at many scales at once.
  • Believing sinusoidal encodings can't exceed the training length. The formula is defined for any position, so it extrapolates in principle; quality just degrades, which is exactly why newer schemes (RoPE, ALiBi) were invented.
  • Confusing positional encoding with positional embedding. Encodings are the fixed sine/cosine values here; embeddings are learned position vectors (GPT-2's choice). Both aim to inject order; only one is trained.

🔑 Key results to remember

  • The gap: attention is permutation-equivariant (\(\operatorname{Attention}(PX)=P\,\operatorname{Attention}(X)\)) — it has no built-in order.
  • The fix: stamp each token with its position before attention sees it.
  • Sinusoidal PE: \(PE_{(pos,2i)}=\sin(pos/10000^{2i/d})\), \(PE_{(pos,2i+1)}=\cos(pos/10000^{2i/d})\).
  • Multi-scale: wavelengths run from \(2\pi\) to \(10000\cdot 2\pi\) — fast dims for fine position, slow dims for coarse.
  • Injection: add PE to the token embedding; and modern models often use learned or rotary (RoPE) positions instead.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. Why does plain attention need positional information added at all?

  • Because softmax destroys order.
    Softmax is not the culprit; the whole operation is order-blind by construction.
  • Because attention is permutation-equivariant — it treats the input as a set, so it can't tell word order.
    Correct. Reshuffling the tokens gives the same computation reordered, so "dog bites man" and "man bites dog" are indistinguishable without added position.
  • Because embeddings are too small.
    Embedding size is unrelated; even huge embeddings carry no position.
  • Because the model has too few heads.
    Head count doesn't create a sense of order; position must be injected explicitly.

Q2. In the sinusoidal scheme, how do low-index and high-index dimensions differ?

  • Low dimensions are learned; high dimensions are fixed.
    All sinusoidal dimensions are fixed by the formula; none are learned.
  • They are identical, just shifted.
    They have very different wavelengths, from about \(2\pi\) to \(10000\cdot2\pi\).
  • Low dimensions oscillate fast (fine position); high dimensions oscillate slowly (coarse position).
    Correct. The divisor \(10000^{2i/d}\) grows with \(i\), stretching the wavelength — fast clocks for local detail, slow clocks for global position.
  • High dimensions encode the token's meaning.
    Meaning lives in the embedding; PE dimensions only encode position.

Q3. How is the positional encoding combined with the token embedding?

  • It is added elementwise, keeping the same width.
    Correct. \(x_{pos}=\operatorname{embed}(\text{token})+PE_{pos}\), so each vector carries meaning and position together.
  • It is concatenated, doubling the width.
    No — addition keeps the width fixed; concatenation is not used here.
  • It replaces the embedding.
    Then you'd lose the word's meaning; PE augments, not replaces.
  • It is multiplied into the attention weights.
    PE is added at the input, before attention computes anything.

Q4. Why prefer sinusoids over just using the integer position number?

  • Sinusoids train faster.
    Fixed sinusoids aren't trained at all; speed isn't the reason.
  • Integers are impossible to compute.
    They're trivial to compute; the problem is their behavior, not feasibility.
  • Sinusoids use more memory.
    If anything they use the same; that would be a drawback, not a reason.
  • Sinusoids stay bounded in \([-1,1]\) and encode position at many scales, so they don't swamp the embedding or break on long sequences.
    Correct. A raw integer grows without bound and dominates the small embedding values; multi-scale bounded waves avoid both problems.

✍️ Practice

1. (warm-up) In the interactive, slide from \(i=0\) to \(i=31\). Describe how the curve and its printed wavelength change, and which end is best for telling adjacent words apart.

Show solution

At \(i=0\) the wave oscillates quickly, with a wavelength of about \(2\pi\approx6.3\) positions; as \(i\) rises the wave stretches out until, near \(i=31\), it barely completes part of a cycle over the whole window (wavelength in the thousands). The fast, low-\(i\) end is best for distinguishing neighbors, because it changes sharply from one position to the next; the slow, high-\(i\) end captures coarse, long-range location. Using both ends at once is what lets one vector pin down position at every scale.

2. (transfer) With \(d=4\), compute \(PE\) for position 0 and position 1 (divisors 1 and 100). Which dimensions change the most between the two positions?

Show solution

\(PE_0 = [\sin0,\cos0,\sin0,\cos0] = [0,1,0,1]\). \(PE_1 = [\sin1,\cos1,\sin(0.01),\cos(0.01)] = [0.84,0.54,0.01,1.00]\). The first two dimensions (the fast \(i=0\) band) change a lot — from \([0,1]\) to \([0.84,0.54]\) — while the slow \(i=1\) band moves only from \([0,1]\) to \([0.01,1.00]\). Neighboring positions are separated mostly by the fast dimensions, exactly as intended.

3. (stretch) A useful property of sinusoidal PE is that the encoding of position \(pos+k\) can be written as a fixed linear (matrix) transform of the encoding of \(pos\), for any offset \(k\). Why would that make it easier for attention to reason about relative position?

Show solution

For a single frequency, \(\sin\) and \(\cos\) of \((pos+k)\) are just rotations of \(\sin\) and \(\cos\) of \(pos\) by a fixed angle (the angle-addition formulas), and that rotation depends only on the offset \(k\), not on \(pos\). So "shift by \(k\)" is the same linear operation everywhere in the sequence. A learned attention head can therefore latch onto "the token 3 positions back" with one consistent transformation, rather than memorizing a separate rule per absolute position — which is precisely the idea that rotary embeddings (RoPE) later made central by rotating the query and key vectors directly.

🚀 In the real world & at the frontier

Positioning is one of the liveliest corners of transformer research, because it controls how far a model can reliably read. The original sinusoids gave way to learned position embeddings in GPT-2, and then to rotary position embeddings (RoPE), now standard in LLaMA-style models: instead of adding a vector, RoPE rotates the query and key by an angle proportional to position, which bakes relative distance directly into the dot product. ALiBi takes an even simpler route, biasing attention scores by how far apart tokens are. The prize everyone is chasing is length generalization — training on 4K tokens but working correctly at 128K or beyond — and clever tweaks to positional schemes (RoPE base-frequency scaling, position interpolation) are a big part of how today's long-context models stretch so far. The humble idea you learned here, "write the position into the vector," is still the hinge the whole field turns on.

Recap — say it to a friend

"Attention treats a sentence as an unordered bag of words, so we stamp each token with its position using sine and cosine waves of many speeds — fast clocks for fine position, slow clocks for coarse — and add that stamp to the embedding, giving every position a unique, bounded fingerprint the model can use."
