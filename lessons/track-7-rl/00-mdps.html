MDPs & the reinforcement-learning problem

Every model so far learned from a fixed dataset. Reinforcement learning is different: an agent acts, the world responds, and it must learn — from reward alone — how to behave. First we need the language to state that problem precisely.

Track 12 · Lesson 0 Concept + code + interactive ~22 min Builds on: Track 1 (probability)

Supervised learning is handed the right answer for every example. Reinforcement learning is only told how good the outcome was — often much later — and must discover good behaviour by trial and error. This is how we train agents to play games, control robots, and, as you will see in Lesson 4, align language models. It all rests on one formal object: the Markov decision process. This lesson gives you the vocabulary — state, action, reward, return, policy, value — that every algorithm in the track is built from.

💡 Intuition: teaching a dog a trick

Imagine training a dog to roll over. You never explain the exact sequence of muscle movements — you couldn't, and the dog couldn't read it anyway. Instead you wait, and when the dog does something in the right direction, you give it a treat. The dog has to figure out, from the treats alone, which of its own actions earn rewards. That is exactly reinforcement learning: no answer key, just a running score, and a learner that has to reverse-engineer good behaviour from it.

Two things make this genuinely harder than the supervised learning of earlier tracks. First, the treat often comes after the useful action — the dog rolls, pauses, then gets the treat — so the learner must trace a reward back to the move that earned it. Second, the dog has to try things to discover what works; it can't just repeat the one trick it already knows. Hold on to those two ideas — delayed reward and the need to explore. Everything in this track is, at heart, a way to cope with them.

📐 The pieces: agent, environment, reward

Picture an agent (the learner and decision-maker, e.g. the dog) interacting with an environment (everything outside it, e.g. the room and the trainer) in a loop of discrete timesteps. At step \(t\) the agent observes a state \(s_t\) — a snapshot of the situation — chooses an action \(a_t\), and the environment responds with a next state \(s_{t+1}\) and a single number, the reward \(r_{t+1}\). The agent's one and only goal is to collect as much reward as possible over time. It is never told which action was "correct" — only how much reward followed.

We package the environment as a Markov decision process (MDP), written as the tuple \((\mathcal{S}, \mathcal{A}, P, R, \gamma)\). Each symbol names one of the five pieces:

  • \(\mathcal{S}\) — the set of states (every situation the agent can be in); \(\mathcal{A}\) — the set of actions it can take.
  • \(P(s' \mid s, a)\) — the transition probability: the chance of landing in state \(s'\) after doing action \(a\) in state \(s\). (Read "\(s'\)" as "s-prime", the next state.)
  • \(R(s, a, s')\) — the reward handed out for that transition.
  • \(\gamma\) (gamma, a number between 0 and 1) — the discount factor: how much a reward in the future is worth to us now.

The word Markov means the future depends only on the present state, not on the whole history of how you got there. Once you know \(s_t\), the path you took to reach it is irrelevant to what happens next. That is a strong assumption, and it is exactly what makes the problem tractable: the state is a sufficient summary of the past, so the agent only ever has to reason about "where am I now?", never "how did I get here?".

The agent's behaviour is a policy \(\pi(a \mid s)\) — a rule (possibly random) that gives the probability of choosing action \(a\) when in state \(s\). What it tries to maximise is the return \(G_t\): the discounted sum of all future rewards, starting from time \(t\).

\[ G_t = r_{t+1} + \gamma\, r_{t+2} + \gamma^2 r_{t+3} + \cdots = \sum_{k=0}^{\infty} \gamma^k\, r_{t+k+1}. \] (0.1)

Read equation (0.1) left to right: the next reward counts in full, the one after is multiplied by \(\gamma\), the one after that by \(\gamma^2\), and so on — each step further away is shrunk by another factor of \(\gamma\). The discount does two jobs at once. It keeps the sum finite even for endless tasks (a geometric series), and it sets how far-sighted the agent is: with \(\gamma\) near 0 it grabs immediate reward and ignores the future; with \(\gamma\) near 1 it plans far ahead. In plain terms, a reward of 1 arriving \(k\) steps from now is worth only \(\gamma^k\) today — the RL version of "a dollar tomorrow is worth less than a dollar today."

Because the return is random — chance lives in both the environment's transitions and the policy's choices — we grade situations by its average. The state-value function \(V^\pi(s)\) is the expected return if you start in state \(s\) and follow policy \(\pi\) forever after; the action-value function \(Q^\pi(s,a)\) is the same but pins down the first action too. (The symbol \(\mathbb{E}_\pi[\cdot]\) just means "average over all the randomness, assuming we act by \(\pi\)".)

\[ V^\pi(s) = \mathbb{E}_\pi\!\left[G_t \mid s_t = s\right], \qquad Q^\pi(s,a) = \mathbb{E}_\pi\!\left[G_t \mid s_t = s,\, a_t = a\right]. \] (0.2)

\(V^\pi\) tells you how good it is to be in a state; \(Q^\pi\) tells you how good it is to take a particular action there. Solving an MDP means finding an optimal policy \(\pi^\star\) whose value is at least as high as any other policy's, in every state. Every method in this track is a different strategy for estimating these values — or the policy directly — from raw experience.

✍️ Worked example: compute a return by hand

Suppose one short episode produces the reward sequence \(r_1=+1,\; r_2=0,\; r_3=+1,\; r_4=+1\), then ends. Take \(\gamma=0.9\). What is the return \(G_0\) seen from the start?

1
Write the formula. From equation (0.1): \(G_0 = r_1 + \gamma r_2 + \gamma^2 r_3 + \gamma^3 r_4\). Each reward is weighted by \(\gamma\) raised to the number of steps you wait for it.
2
Compute the weights. \(\gamma^0=1,\; \gamma^1=0.9,\; \gamma^2=0.81,\; \gamma^3=0.729\).
3
Plug in. \(G_0 = 1(1) + 0.9(0) + 0.81(1) + 0.729(1) = 1 + 0 + 0.81 + 0.729 = 2.539\).
4
Read the meaning. The \(+1\) that arrives three steps later contributes only \(0.729\), not a full \(1\). That geometric shrink is the discount at work. If instead the reward were \(+1\) at every step forever, the return would be \(\sum_k \gamma^k = \tfrac{1}{1-\gamma} = \tfrac{1}{0.1} = 10\) — a finite number, even though the rewards never stop. That is why we need \(\gamma<1\).

🛠️ From scratch: an MDP is just a step function

An MDP needs no libraries — the whole thing is a function that takes a state and action and returns the next state, a reward, and whether the episode is over. Here is the grid world from the widget:

import numpy as np

# A 4x4 grid world. States 0..15, actions 0=up 1=down 2=left 3=right.
GOAL, PIT = 15, 13

def step(s, a):
    r, c = divmod(s, 4)                 # decode state into (row, col)
    if   a == 0 and r > 0: r -= 1       # up
    elif a == 1 and r < 3: r += 1       # down
    elif a == 2 and c > 0: c -= 1       # left
    elif a == 3 and c < 3: c += 1       # right   (walls: stay put)
    s2 = r * 4 + c
    reward = 1.0 if s2 == GOAL else (-1.0 if s2 == PIT else -0.04)
    done = s2 in (GOAL, PIT)
    return s2, reward, done

def episode_return(rewards, gamma=0.9):
    # G = r1 + g*r2 + g^2*r3 + ...   (the discounted sum)
    return sum((gamma ** k) * r for k, r in enumerate(rewards))
Why this is harder than supervised learning. Two difficulties appear here that Tracks 1–6 never faced. Delayed reward: the action that mattered may have happened long before the reward arrived — the credit-assignment problem. Exploration: the agent must try uncertain actions to discover good ones, trading that off against exploiting what it already knows. Every algorithm in this track is a way to handle these two.

⚠️ Mistakes everyone makes here

  • Confusing reward with return. The reward \(r_{t+1}\) is one number for one step; the return \(G_t\) is the whole discounted sum of future rewards. Agents maximise the return, not the next reward.
  • Thinking the agent is told the right action. It only ever sees an evaluative score ("how good"), never the instructive label ("do this"). That is the entire difference from supervised learning.
  • Treating \(\gamma\) as a learning rate. \(\gamma\) is part of the problem definition — it sets the objective. The learning rate is an algorithm setting you'll meet later; they are unrelated.
  • Forgetting the Markov assumption. Value functions only make sense if the state summarises everything relevant. If the next outcome depends on history not in the state, you must enrich the state until it does.

🔑 Key results to remember

  • RL = learning from reward by interaction, not from labelled examples. The signal is evaluative ("how good"), not instructive ("the answer").
  • MDP \((\mathcal{S},\mathcal{A},P,R,\gamma)\); the Markov property says the state summarises all the past you need.
  • Return \(G_t=\sum_k \gamma^k r_{t+k+1}\); the discount \(\gamma\) bounds the sum and sets the planning horizon (\(\tfrac{1}{1-\gamma}\) steps, roughly).
  • Policy \(\pi(a\mid s)\) is what we learn; value functions \(V^\pi,Q^\pi\) grade states and actions by expected return.
  • Two core challenges: delayed reward (credit assignment) and the exploration–exploitation trade-off.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What does the "Markov" property in an MDP assert?

  • Rewards are always positive.
    Rewards can be any sign. Markov is about state, not reward magnitude.
  • The next state and reward depend only on the current state and action, not the full history.
    Correct. The current state is a sufficient statistic of the past, which is what makes value functions well-defined and the problem solvable.
  • The policy must be deterministic.
    Policies may be stochastic; the Markov property concerns the environment's dynamics, not the policy's form.
  • The discount factor must equal 1.
    \(\gamma\) is typically \(<1\). It is unrelated to the Markov assumption.

Q2. Why is a discount factor \(\gamma < 1\) used in the return?

  • To make all rewards equal.
    It does the opposite — it weights near rewards more than far ones.
  • To force the agent to ignore the future entirely.
    Only \(\gamma=0\) does that. A typical \(\gamma\) like 0.9 still values the future, just less than the present.
  • To keep the infinite sum of rewards finite and set how far-sighted the agent is.
    Correct. Geometric weighting bounds the return for ongoing tasks and tunes the planning horizon: higher \(\gamma\) means more long-term planning.
  • To guarantee the policy is optimal.
    Optimality comes from the learning algorithm; \(\gamma\) only defines the objective being optimised.

Q3. The difference between \(V^\pi(s)\) and \(Q^\pi(s,a)\) is that…

  • \(Q^\pi\) also fixes the first action taken, while \(V^\pi\) averages over the policy's action choice.
    Correct. \(V^\pi(s)=\sum_a \pi(a\mid s)Q^\pi(s,a)\): the state value is the policy-weighted average of action values.
  • \(V^\pi\) is for deterministic policies only.
    Both are defined for stochastic and deterministic policies alike.
  • \(Q^\pi\) ignores future rewards.
    Both are expected returns, summing discounted future rewards; \(Q\) just conditions on the first action.
  • They are always equal.
    They coincide only when the action is forced; in general they differ because \(Q\) pins the first action.

Q4. The "credit-assignment problem" in RL refers to…

  • deciding how much compute to spend.
    That is a resource question, not credit assignment.
  • normalising rewards to zero mean.
    A useful trick (you'll meet baselines later), but not what credit assignment means.
  • choosing the learning rate.
    Unrelated; credit assignment is about which actions deserve credit, not optimiser settings.
  • figuring out which earlier actions deserve credit (or blame) for a reward that arrives much later.
    Correct. Because reward is delayed, the agent must trace a late reward back to the decisions that caused it — the heart of what makes RL hard.

✍️ Practice

1. (warm-up) An agent gets reward \(+1\) at every step forever. With \(\gamma=0.9\), what is the return \(G_t\)? With \(\gamma=0.99\)? What does the change say about the agent's horizon?

Show solution

It is a geometric series: \(G_t=\sum_{k=0}^\infty \gamma^k = \frac{1}{1-\gamma}\). For \(\gamma=0.9\), \(G_t=\frac{1}{0.1}=10\); for \(\gamma=0.99\), \(G_t=\frac{1}{0.01}=100\). The quantity \(\frac{1}{1-\gamma}\) is roughly "how many steps ahead the agent effectively cares about" — 10 steps versus 100 here. Nudging \(\gamma\) closer to 1 makes the agent much more far-sighted.

2. (transfer) Pick a real task and write it as an MDP — name \(\mathcal{S},\mathcal{A},R\). Then point out where the Markov assumption might be violated, and how you'd fix it.

Show solution

Example — a thermostat: \(\mathcal{S}\) = current temperature (and maybe time of day), \(\mathcal{A}\) = {heat, cool, off}, \(R\) = comfort minus energy cost. The Markov assumption breaks if the next temperature depends on history not in the state — e.g. thermal mass means the recent trend matters, not just the instantaneous reading. The standard fix is to enrich the state (include the last few temperatures, or their rate of change) until it again summarises everything relevant. Choosing a good state representation is a recurring practical theme in applied RL.

3. (stretch) Show that \(V^\pi(s)=\sum_a \pi(a\mid s)\,Q^\pi(s,a)\).

Show solution

By definition \(V^\pi(s)=\mathbb{E}_\pi[G_t\mid s_t=s]\). Condition on the first action using the law of total expectation: \(\mathbb{E}[G_t\mid s]=\sum_a \Pr(a_t=a\mid s_t=s)\,\mathbb{E}[G_t\mid s_t=s,a_t=a]\). The first factor is exactly \(\pi(a\mid s)\) and the second is exactly \(Q^\pi(s,a)\), giving \(V^\pi(s)=\sum_a \pi(a\mid s)Q^\pi(s,a)\). In words: a state's value is the average of its action-values, weighted by how often the policy picks each action.

🚀 In the real world & at the frontier

The MDP framing is astonishingly general. Board games (AlphaGo), video games (Atari, StarCraft), datacentre cooling, chip floor-planning, and robot locomotion are all MDPs — and so, as you'll see in Lesson 4, is aligning a language model to human preferences. The frontier pushes past the clean assumptions here: when the agent can't see the full state, it's a partially observable MDP (POMDP), and it must infer the hidden state from a history of observations. When rewards are almost never handed out (sparse reward), credit assignment becomes brutal, and modern methods lean on exploration bonuses, learned world models, or human feedback to fill the gap. But the vocabulary never changes: state, action, reward, return, policy, value.

Recap — say it to a friend

"Reinforcement learning is an agent choosing actions in states to earn reward, and an MDP is the clean way to write that down. The agent maximises the discounted sum of future reward — the return — and we grade situations with value functions. It's harder than supervised learning because reward is delayed and the agent has to explore to learn."
