Value iteration & Q-learning

If you knew the value of every state, acting well would be trivial — just step toward higher value. This lesson builds that value map two ways: value iteration when the rules are known, and Q-learning when they aren't.

Lesson 0 defined what we want — an optimal policy — but not how to get one. The key realisation is that we don't have to search over policies directly. If we can compute the value of every state or state–action pair, the best policy falls out for free: in each state, pick the action with the highest value. So the whole problem reduces to estimating values well. We'll do it first with a model of the world (value iteration), then without one, learning purely from experience (Q-learning) — the algorithm that, scaled up with neural networks, learned to play Atari from raw pixels.

💡 Intuition: ripples spreading from the goal

Picture the grid world as a pond and the goal square as a stone dropped in. On the first pass, only squares touching the goal "know" they're good. On the next pass, squares touching those squares learn they're good too, because from them you can reach a good square. Value spreads outward like a ripple, one step per pass, until every square carries a number that says "how much reward can I expect from here if I play well?" That number is the state value \(V(s)\), and once the map is filled in, the policy is just "always walk uphill."

The one rule that spreads the ripple is the Bellman equation: the value of a square equals the reward you get for stepping, plus the (discounted) value of wherever that step lands you — and you take the action that makes this as large as possible. Everything below is that single idea, applied over and over.

📐 The Bellman optimality equation

Write \(V^\star(s)\) for the value of state \(s\) under the best policy, and \(Q^\star(s,a)\) for the value of taking action \(a\) in \(s\) and then playing optimally. The Bellman optimality equations say each value equals an immediate reward plus a discounted future value, with a \(\max\) that picks the best action:

\[ V^\star(s) = \max_{a}\ \sum_{s'} P(s'\mid s,a)\,\big[\,R(s,a,s') + \gamma\, V^\star(s')\,\big]. \] (1.1)

Reading (1.1) piece by piece: for each action \(a\) you might take, look at every state \(s'\) you could land in, weighted by its transition probability \(P(s'\mid s,a)\); for each, add the reward \(R\) now to \(\gamma\) times the value \(V^\star(s')\) of where you end up; average those (that's the \(\sum_{s'}\)); and finally keep the action that scores highest (the \(\max_a\)). The action-value version pushes the \(\max\) one step later, onto the next action:

\[ Q^\star(s,a) = \sum_{s'} P(s'\mid s,a)\,\big[\,R(s,a,s') + \gamma\, \max_{a'} Q^\star(s',a')\,\big]. \] (1.2)

The two are linked simply: \(V^\star(s)=\max_a Q^\star(s,a)\), and the optimal policy is "act greedily", \(\pi^\star(s)=\arg\max_a Q^\star(s,a)\) — pick the highest-scoring action. Notice why \(Q\) is convenient: with \(Q^\star\) in hand you can act without a model, because the action is right there in the table. With only \(V^\star\) you'd still need to know \(P\) and \(R\) to look one step ahead. That difference drives everything that follows.

Value iteration: sweep the equation to a fixed point

Equation (1.1) is a description, not yet an algorithm. Value iteration turns it into one by treating the equals sign as an assignment: start with \(V(s)=0\) everywhere, then repeatedly overwrite every state's value with the right-hand side, using the current estimates for \(V^\star(s')\).

\[ V_{k+1}(s) \leftarrow \max_{a}\ \sum_{s'} P(s'\mid s,a)\,\big[\,R(s,a,s') + \gamma\, V_k(s')\,\big]. \] (1.3)

Each sweep is one ripple outward. Because \(\gamma<1\), this update is a contraction — every sweep shrinks the error toward zero — so \(V_k\) is guaranteed to converge to the true \(V^\star\). When the numbers stop changing, read off the greedy policy. Here is what it produces on our grid:

Q-learning: solve the MDP without the rules

Value iteration needs the model — the transition probabilities \(P\) and rewards \(R\). But a robot in the real world doesn't get handed \(P\); it only gets to try things and see what happens. Q-learning learns \(Q^\star\) from raw experience. After taking action \(a\) in state \(s\), seeing reward \(r\), and landing in \(s'\), it nudges its estimate toward what it just observed:

\[ Q(s,a) \leftarrow Q(s,a) + \alpha\,\underbrace{\big[\,r + \gamma\, \max_{a'} Q(s',a') - Q(s,a)\,\big]}_{\text{TD error }\;\delta}. \] (1.4)

The bracket is the temporal-difference (TD) error \(\delta\): the gap between our old guess \(Q(s,a)\) and a fresh, one-step-better estimate \(r + \gamma\max_{a'}Q(s',a')\). We step our estimate a fraction \(\alpha\) (alpha, the learning rate, e.g. 0.5) of the way toward the new target. Concretely: if \(Q(s,a)=0\), we observe \(r=-0.04\), the next state's best value is \(\max_{a'}Q(s',a')=0.5\), and \(\gamma=0.95\), then the target is \(-0.04+0.95(0.5)=0.435\), the error is \(0.435\), and with \(\alpha=0.5\) we set \(Q(s,a)=0.2175\). Two subtleties make it work: we use \(\max_{a'}\) (so we learn the value of playing optimally next, no matter which action we actually explored — this is what "off-policy" means), and we must explore, usually with \(\varepsilon\)-greedy: with small probability \(\varepsilon\) pick a random action, otherwise the greedy one, so every state–action pair gets visited. Run it long enough and the return climbs to the same optimum value iteration found — with no model at all:

✍️ Worked example: one Bellman backup by hand

Take a state \(s\) with two available actions and \(\gamma=0.9\). Suppose the current value estimates of the neighbours are known. Compute \(V(s)\) with one backup.

1
Action "right" moves you (deterministically) to a square with value \(V=10\), for reward \(0\). Its backed-up value is \(0 + 0.9(10) = 9.0\).
2
Action "up" moves you to a square with value \(V=5\), for reward \(+1\). Its backed-up value is \(1 + 0.9(5) = 5.5\).
3
Take the max. \(V(s) \leftarrow \max(9.0,\, 5.5) = 9.0\), and the greedy action is "right." Even though "up" pays a bigger immediate reward, "right" leads somewhere far more valuable — the whole point of looking ahead.
4
That's one cell, one sweep. Value iteration does this for every state, over and over, and the numbers ripple outward until they stop moving. Q-learning does the same arithmetic, but replaces the known \(V(s')\) with a sampled \(\max_{a'}Q(s',a')\) from a transition it actually experienced — and takes a small step \(\alpha\) toward it instead of overwriting.

🛠️ From scratch: both algorithms in 30 lines

Value iteration needs the model and sweeps to a fixed point; Q-learning throws away the model and learns from sampled episodes. Same grid world, two philosophies:

import numpy as np
GOAL, PIT, N = 15, 13, 16

def step(s, a):                              # deterministic 4x4 grid (Lesson 0)
    r, c = divmod(s, 4)
    if   a==0 and r>0: r-=1
    elif a==1 and r<3: r+=1
    elif a==2 and c>0: c-=1
    elif a==3 and c<3: c+=1
    s2 = r*4 + c
    rew = 1.0 if s2==GOAL else (-1.0 if s2==PIT else -0.04)
    return s2, rew, s2 in (GOAL, PIT)

def value_iteration(gamma=0.95, iters=100):  # needs the model
    V = np.zeros(N)
    for _ in range(iters):
        for s in range(N):
            if s in (GOAL, PIT): continue
            V[s] = max(step(s,a)[1] + gamma*V[step(s,a)[0]] for a in range(4))
    return V

def q_learning(gamma=0.95, alpha=0.5, eps=0.2, episodes=500):  # model-free
    Q = np.zeros((N, 4))
    for _ in range(episodes):
        s = 0
        for _ in range(50):
            a = np.random.randint(4) if np.random.rand()<eps else int(Q[s].argmax())
            s2, r, done = step(s, a)
            target = r + (0.0 if done else gamma*Q[s2].max())
            Q[s, a] += alpha * (target - Q[s, a])     # the TD update (1.4)
            s = s2
            if done: break
    return Q
The payoff, measured. Both methods recover the same greedy policy on the grid, and the same value at the start state — but value iteration reads the rulebook (\(P,R\)) while Q-learning only ever played the game. That is the leap that matters: swap the lookup table \(Q[s,a]\) for a neural network \(Q_\theta(s,a)\) and the very same TD update becomes DQN, which learned to play dozens of Atari games from pixels alone.

⚠️ Mistakes everyone makes here

  • Thinking Q-learning needs the model. It doesn't — that's the entire point. Value iteration needs \(P\) and \(R\); Q-learning learns \(Q^\star\) from sampled transitions \((s,a,r,s')\).
  • Dropping exploration. A purely greedy agent can lock onto a mediocre path and never discover the better one. You need \(\varepsilon>0\) (or another exploration scheme) so every state–action pair is visited.
  • Using the action you took instead of the max. The Q-learning target uses \(\max_{a'}Q(s',a')\), the value of playing optimally next — not the value of whatever exploratory action you happened to pick. That's what makes it learn the optimal \(Q^\star\).
  • Learning rate too high. Because the target \(r+\gamma\max Q'\) itself contains a (moving) estimate, a large \(\alpha\) makes the updates chase a shifting goal and wobble. Moderate \(\alpha\), decayed over time, is stable.

🔑 Key results to remember

  • Bellman optimality: \(V^\star(s)=\max_a\sum_{s'}P[\,R+\gamma V^\star(s')\,]\); the \(Q\) form pushes the \(\max\) onto the next action.
  • Value iteration turns that equation into an update and sweeps to a fixed point — guaranteed to converge because \(\gamma<1\) makes it a contraction. Needs the model.
  • Q-learning is model-free: \(Q\leftarrow Q+\alpha(r+\gamma\max_{a'}Q'-Q)\), the TD update. Learns \(Q^\star\) from experience.
  • Act greedily w.r.t. the learned values to recover the policy: \(\pi^\star(s)=\arg\max_a Q^\star(s,a)\).
  • Exploration is mandatory for model-free learning; \(\varepsilon\)-greedy is the simplest scheme.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. In the Bellman optimality equation for \(V^\star\), what is the \(\max_a\) doing?

  • Averaging the value over all actions.
    That would be a fixed policy's value. Optimality takes the best action, not the average.
  • Choosing the action with the largest immediate reward.
    It maximises reward plus discounted future value, not immediate reward alone — the whole point of looking ahead.
  • Selecting the action whose reward-plus-discounted-future-value is largest.
    Correct. \(V^\star\) assumes you then act optimally, so each state's value is the best available (reward + \(\gamma\)·next-value).
  • Normalising the values to sum to 1.
    There is no normalisation here; \(\max\) picks the best action's value.

Q2. What is the key practical difference between value iteration and Q-learning?

  • Value iteration is model-free; Q-learning needs the model.
    It's the reverse. Value iteration needs \(P,R\); Q-learning is model-free.
  • Value iteration needs the model \((P,R)\); Q-learning learns from sampled experience without one.
    Correct. That's exactly why Q-learning works for robots and games where the dynamics are unknown.
  • Only Q-learning uses a discount factor.
    Both use \(\gamma\); it's part of the shared objective.
  • Value iteration cannot find the optimal policy.
    It provably converges to \(V^\star\) and the optimal policy when the model is known.

Q3. The TD error \(\delta = r + \gamma\max_{a'}Q(s',a') - Q(s,a)\) measures…

  • the total reward of the whole episode.
    It's a one-step quantity, not the full-episode return.
  • the probability of reaching the goal.
    It's a value gap, not a probability.
  • the learning rate.
    The learning rate \(\alpha\) scales the error; it isn't the error itself.
  • the gap between the old estimate and a fresh one-step-better target.
    Correct. We move \(Q(s,a)\) a fraction \(\alpha\) of this gap toward the target \(r+\gamma\max Q'\).

Q4. Why does Q-learning need \(\varepsilon\)-greedy exploration?

  • So every state–action pair gets tried, otherwise good options may never be discovered.
    Correct. A greedy-only agent can get stuck exploiting a suboptimal path; random actions guarantee coverage.
  • To make the learning rate decay.
    Unrelated; \(\varepsilon\) controls exploration, not the step size.
  • To make the policy deterministic.
    The opposite — \(\varepsilon\)-greedy adds randomness for exploration; the final policy is read off greedily.
  • Because the model requires it.
    Q-learning has no model; exploration is needed precisely because it learns from limited samples.

✍️ Practice

1. (warm-up) Currently \(Q(s,a)=2.0\). You take \(a\), receive \(r=1\), and land in \(s'\) where the action-values are \(\{0.5, 3.0, 1.0, -2.0\}\). With \(\gamma=0.9\) and \(\alpha=0.1\), compute the updated \(Q(s,a)\).

Show solution

The target is \(r+\gamma\max_{a'}Q(s',a') = 1 + 0.9(3.0) = 3.7\). The TD error is \(\delta = 3.7 - 2.0 = 1.7\). The update is \(Q(s,a)\leftarrow 2.0 + 0.1(1.7) = 2.17\). We moved 10% of the way toward the better estimate — note we used \(\max = 3.0\), not the value of whatever action we'll actually take next.

2. (transfer) Q-learning uses \(\max_{a'}Q(s',a')\) in its target even while exploring with random actions. Explain in words why this "off-policy" choice makes it learn the optimal \(Q^\star\) rather than the value of the exploratory behaviour.

Show solution

The target asks: "if I were to act optimally from the next state, how good would this transition be?" By always plugging in \(\max_{a'}\), the update estimates the value of the greedy (optimal) continuation, independent of the random action \(\varepsilon\)-greedy actually took to gather the data. So the behaviour policy (exploratory) and the policy being evaluated (greedy/optimal) are different — hence "off-policy." Exploration is only there to collect diverse data; the \(\max\) ensures what we learn is \(Q^\star\), the value of the best policy.

3. (stretch) Consider a 2-state chain: from state A, one action gives reward 0 and moves to B; from B, one action gives reward \(+1\) and stays at B. With \(\gamma=0.9\), run value iteration to its fixed point and give \(V^\star(A)\) and \(V^\star(B)\).

Show solution

State B loops on itself earning \(+1\) forever: \(V^\star(B) = 1 + 0.9\,V^\star(B)\Rightarrow V^\star(B) = \frac{1}{1-0.9} = 10\). State A: \(V^\star(A) = 0 + 0.9\,V^\star(B) = 0.9(10) = 9\). Value iteration reaches these by sweeping: \(V(B)\) climbs \(1, 1.9, 2.71,\dots\to 10\), and \(V(A)\) tracks \(0.9\,V(B)\to 9\). The contraction (\(\gamma<1\)) guarantees convergence to this unique fixed point.

🚀 In the real world & at the frontier

Tabular Q-learning stores one number per state–action pair — hopeless when states are images. The 2015 DQN breakthrough replaced the table with a convolutional network \(Q_\theta(s,a)\) and kept the exact TD update you just wrote, adding two stabilisers: a replay buffer (learn from a shuffle of past transitions, breaking correlations) and a target network (a slowly-updated copy that keeps the bootstrapping target from moving too fast). That combination cleared human scores on dozens of Atari games from pixels. Later work fixed Q-learning's tendency to overestimate values (Double DQN) and bundled a stack of improvements into Rainbow. The catch: the \(\max_{a'}\) is easy over a handful of discrete actions but intractable over continuous ones (a robot's joint torques) — which is exactly why the next lessons optimise the policy directly.

Recap — say it to a friend

"If you know how good every state is, acting well is easy — walk uphill. The Bellman equation says a state's value is reward plus the discounted value of where you land. Value iteration ripples that rule to a fixed point when you know the rules; Q-learning learns the same values from pure trial and error, which is how machines learned to play Atari."
