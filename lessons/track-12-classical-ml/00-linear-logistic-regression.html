Linear & Logistic Regression: where machine learning begins

Before the fancy models, there are two you must know in your bones: fit a straight line to predict a number, and bend that line through an S-curve to predict a probability. They're the simplest models that work — and secretly, they're single neurons.

Track 5 · Lesson 0 Concept + code + interactive ~26 min Builds on: Tracks 1, 2

Every model in this course is, in some sense, an elaboration of the two ideas in this lesson. Linear regression draws the best straight line through data to predict a number (a price, a temperature). Logistic regression takes that same straight line and squashes it through an S-shaped curve to predict a probability (spam or not, sick or healthy). They are the workhorses of real-world data science — often the first thing a professional tries — and they are the perfect on-ramp, because they introduce the whole machinery of ML (a model, a loss, gradient descent) at its simplest. And here's the punchline that ties them to the rest of the course: each one is a single neuron. You've been building toward this since Track 2.

💡 Intuition: the line of best fit, and bending it into a probability

Picture a scatter of dots — say, house size (x) versus price (y). You want a rule that predicts price from size. The simplest rule is a straight line, \(y = wx + b\), where \(w\) (the weight, or slope) says how much price rises per unit of size, and \(b\) (the bias, or intercept) is the baseline. "Best" means the line that comes closest to the dots. We measure closeness by the mean squared error (MSE): for each dot, take the vertical gap between the dot and the line (the residual), square it (so positives and negatives don't cancel, and big misses are punished more), and average over all dots. Training is just finding the \(w, b\) that make this average as small as possible — which we do with gradient descent (Track 2), or in closed form.

Now suppose y isn't a number but a yes/no label — is this email spam? A straight line is a poor fit: it shoots off to \(+\infty\) and \(-\infty\), but a probability must stay between 0 and 1. The fix is elegant: run the linear score \(wx+b\) through the sigmoid function \(\sigma(z) = 1/(1+e^{-z})\), a smooth S-curve that squashes any number into \((0,1)\). Now the output reads as "the probability this is spam." That's logistic regression. We train it not with squared error but with cross-entropy loss (Track 3) — the natural loss for probabilities — and remarkably, its gradient comes out to the same clean form as linear regression's: (prediction − truth) times the input.

✍️ Worked example: one gradient-descent step for a line

Fit \(y = wx + b\) to three points: \((1, 3), (2, 5), (3, 7)\) — which lie exactly on \(y = 2x + 1\). Start at \(w = 0, b = 0\), learning rate \(\eta = 0.1\).

1
Predict & find residuals. With \(w=b=0\), every prediction is 0. Residuals (pred − truth): \(0-3=-3\), \(0-5=-5\), \(0-7=-7\).
2
Gradients of the MSE. The gradient for \(w\) is \(\frac{2}{n}\sum(\text{residual})\cdot x\): \(\frac{2}{3}[(-3)(1)+(-5)(2)+(-7)(3)] = \frac{2}{3}(-34) = -22.7\). For \(b\) it's \(\frac{2}{n}\sum \text{residual} = \frac{2}{3}(-15) = -10\).
3
Take the step (subtract \(\eta\times\)gradient): \(w \leftarrow 0 - 0.1(-22.7) = 2.27\); \(b \leftarrow 0 - 0.1(-10) = 1.0\). In one step we're already near the true \(w=2, b=1\).
4
Repeat. Each step nudges the line toward the data; after enough steps it settles at \(w=2, b=1\), the true line. Logistic regression works identically — the only change is the prediction runs through a sigmoid first, and the residual becomes (probability − label). Same loop, same gradient shape.

🛠️ From scratch: both models are a few lines

# linear regression: predict a number, minimise squared error
for _ in range(steps):
    pred = X @ w + b
    err  = pred - y                    # residual
    w -= lr * (2/n) * X.T @ err
    b -= lr * (2/n) * err.sum()

# logistic regression: predict a probability, minimise cross-entropy
for _ in range(steps):
    p   = sigmoid(X @ w + b)           # probability of class 1
    err = p - y                        # SAME clean gradient shape!
    w -= lr * (X.T @ err) / n
    b -= lr * err.mean()

The symmetry is not a coincidence. Both are generalized linear models: a linear score \(wx+b\), an optional squashing function, and a loss chosen so the gradient simplifies to "(prediction − truth) × input." Linear regression even has a closed-form answer — the normal equation \(w = (X^\top X)^{-1}X^\top y\) — that lands on the exact optimum in one shot (our code checks that gradient descent agrees with it).

⚠️ Mistakes everyone makes here

  • Using linear regression for yes/no problems. A straight line isn't bounded to [0,1], so its "probabilities" can be negative or above 1. That's exactly why the sigmoid (logistic regression) exists.
  • Squaring the error for logistic regression. Cross-entropy, not squared error, is the right loss for probabilities — it gives the clean gradient and doesn't get stuck on confident-wrong predictions. Squared error on a sigmoid creates a non-convex, sticky loss surface.
  • Forgetting to scale features. If one feature ranges in thousands and another in fractions, gradient descent zig-zags (recall ill-conditioning, Track 2). Standardize features to comparable scales first.
  • Thinking "linear" means "only straight lines." Linear-in-the-weights is what matters. Feed in \(x^2\) or \(x_1 x_2\) as extra features and the same linear model fits curves — the trick behind polynomial regression and, later, the kernel SVM.

🔑 Key results to remember

  • Linear regression: predict a number with \(y=wx+b\); train by minimising mean squared error.
  • Logistic regression: predict a probability with \(\sigma(wx+b)\); train by minimising cross-entropy.
  • Both gradients simplify to (prediction − truth) × input — the shared shape of generalized linear models.
  • Linear regression has a closed form (the normal equation); logistic regression is solved iteratively.
  • Each is a single neuron — linear regression with no activation, logistic with a sigmoid. This is the bridge to deep learning (Track 6).

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What does linear regression minimise?

  • The number of misclassified points.
    That's a classification idea; linear regression predicts a continuous number, not a class.
  • The mean squared error — the average squared vertical gap between points and the line.
    Correct. Squaring stops positive and negative errors cancelling and punishes big misses more.
  • The sigmoid of the output.
    Sigmoid belongs to logistic regression, not plain linear regression.
  • The number of features.
    Feature count is fixed by the data, not something training minimises.

Q2. Why can't we use a plain straight line to predict a probability?

  • Lines are too slow to compute.
    Speed isn't the issue; lines are extremely fast.
  • Lines can't have a slope.
    Lines are defined by their slope; that's not the problem.
  • A line is unbounded, but a probability must stay between 0 and 1.
    Correct. The sigmoid squashes the unbounded line into (0,1) so the output is a valid probability.
  • Probabilities can't be learned.
    They can — logistic regression does exactly that.

Q3. The gradient for both linear and logistic regression has what shape?

  • (prediction − truth) × input.
    Correct. This shared, clean form is why both are called generalized linear models and both train with the same loop.
  • input² × weight.
    Not the gradient form here; this doesn't appear.
  • a random value.
    Gradients are deterministic given the data and weights.
  • always zero.
    If the gradient were always zero, nothing would ever learn.

Q4. How do these two models connect to neural networks?

  • They don't — they're totally separate.
    They're deeply connected; that connection is the whole bridge to deep learning.
  • They are three-layer networks.
    They have no hidden layers at all.
  • They are convolutional networks.
    No convolution is involved; they operate on plain feature vectors.
  • Each is a single neuron — linear regression with no activation, logistic with a sigmoid.
    Correct. Stack many such neurons with nonlinearities between them and you get the MLP of Track 6.

✍️ Practice

1. (warm-up) Run linear_regression.py. It fits by gradient descent AND by the normal equation. Do they agree? Change the noise level and re-run — what happens to the R² (fit quality)?

Show solution

They agree to three decimals — both find the same optimal line, one iteratively and one in closed form. As you raise the noise, R² drops (the line explains less of the scatter) even though the slope stays roughly right; noise doesn't bias the fit, it just makes the data less predictable. This separates two things beginners conflate: getting the right relationship (low bias) versus how much variance the data has left over (irreducible error, Track 4).

2. (transfer) In logistic_regression.py, print the predicted probability for a point sitting exactly on the decision boundary. What value do you expect, and why?

Show solution

Exactly 0.5. On the boundary the linear score \(wx+b\) is 0, and \(\sigma(0) = 1/(1+e^0) = 1/2\). The 0.5 contour is precisely the set of points the model is maximally unsure about — the black line in the figure. Moving away from it in the "class 1" direction pushes the score positive and the probability toward 1; the other way, toward 0. Understanding that the boundary is the "50/50" surface is key to reading any probabilistic classifier.

3. (stretch) Logistic regression can only draw a straight decision boundary. How would you make it separate two classes arranged in concentric rings (one inside the other)?

Show solution

Add a feature. If you append \(x_1^2 + x_2^2\) (squared distance from the centre) as a third input, the inner ring has small values and the outer ring large ones — now a linear boundary in this expanded feature space (a threshold on the radius) separates them perfectly, which is a circle back in the original space. This "engineer a feature that makes it linearly separable" move is the seed of the kernel trick (the SVM lesson) and, more powerfully, of what a neural network's hidden layers learn to do automatically. Linear models are far more capable than "straight line" suggests, once you choose the right features.

🚀 In the real world & at the frontier

Don't mistake "simple" for "obsolete." Logistic regression is still a default in medicine (predicting disease risk), finance (credit scoring), and any setting where you must explain the model — its weights directly say how each factor pushes the odds up or down, which a deep net can't. It's the baseline every serious project runs first, because a fancy model that can't beat logistic regression isn't worth the complexity. And the lineage runs straight to the frontier: a modern language model's final layer, which turns a hidden vector into next-token probabilities, is a giant multi-class logistic regression (a "softmax head"). Master these two models and you understand the first and last layer of almost everything.

Recap — say it to a friend

"Linear regression fits the straight line that minimises squared error to predict a number; logistic regression runs that line through a sigmoid to predict a probability — and each is just a single neuron, the atom of every neural network."
