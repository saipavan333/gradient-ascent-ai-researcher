DP-SGD: training a model that can't memorize you

Differential privacy protected a single statistic. DP-SGD makes an entire trained neural network differentially private, with two small changes to ordinary training: clip each example's gradient, then add noise. The model learns the pattern without memorizing any individual.

Lesson 2 made a single released number private. But a trained model is the product of millions of computations on the data, and it can memorize individual training examples — large language models have been shown to regurgitate verbatim training text, including private information. DP-SGD (Differentially Private Stochastic Gradient Descent) makes the whole training process differentially private, so the final model provably reveals almost nothing about any single training example. The genius is how little it changes: ordinary SGD computes gradients from a batch and steps; DP-SGD adds exactly two operations. First, clip each individual example's gradient to a maximum length — so no single example can push the model very far. Second, add Gaussian noise to the summed gradient before the step — blurring the exact contribution. Clipping bounds how much one person can influence each update (the sensitivity from Lesson 2); noise hides that bounded influence. Together they give a formal privacy guarantee for the trained model, at a modest cost in accuracy. This is the workhorse of private deep learning, and combined with federated learning it's how models get trained on sensitive data responsibly.

💡 Intuition: cap every vote, then add static

Think of each training example as casting a "vote" (its gradient) for how the model should change. The danger to privacy is a loud, distinctive vote — an outlier example that shoves the model in a unique direction, leaving its fingerprint in the weights. DP-SGD does two things. It caps the volume of every vote (gradient clipping), so even the most extreme example can only nudge the model by a bounded amount — no one can shout. Then it adds static to the tally (Gaussian noise), so the exact combination of votes is fuzzy. The model still hears the consensus — the pattern shared across many examples survives the noise — but any single distinctive voice is capped and blurred beyond recognition. It learns the crowd's signal without recording any individual's.

The DP-SGD update, compared to plain SGD:

\[ g_i \leftarrow g_i \cdot \min\!\Big(1, \tfrac{C}{\lVert g_i\rVert}\Big) \;\;(\text{clip to norm } C), \qquad \theta \leftarrow \theta - \eta\,\frac{1}{B}\Big(\sum_i g_i + \mathcal{N}(0, \sigma^2 C^2)\Big) \] (3.1)

Read it: for each example \(i\), if its gradient \(g_i\) is longer than \(C\), scale it down to length \(C\) (clipping — capping the vote); otherwise leave it. Then sum the clipped gradients, add Gaussian noise \(\mathcal{N}(0,\sigma^2C^2)\) (scaled to the clip \(C\) and a noise multiplier \(\sigma\)), and take the step. The clip \(C\) bounds each example's sensitivity; \(\sigma\) sets how much noise (and thus how much privacy). Everything else is ordinary SGD.

✍️ Worked example: DP-SGD vs plain SGD

From dp_sgd.py: a classifier trained normally, then with DP-SGD (clip + noise).

1
Plain SGD. Ordinary training, no privacy. Test accuracy: 0.966. But the model may have memorized specifics of its training data.
2
Clip (step 1). Compute each example's gradient, and cap any whose norm exceeds \(C=1\) — no single example dominates a step.
3
Noise (step 2). Add Gaussian noise (multiplier \(\sigma=1\)) to the summed clipped gradients, then step.
4
Result. DP-SGD accuracy: 0.965 — essentially unchanged, now with a privacy guarantee. On this easy task the cost is tiny; on harder tasks with strong privacy (small \(\varepsilon\)), the accuracy hit is larger. The clip + noise bought provable protection for ~0.1% accuracy.

🛠️ From scratch: DP-SGD's two extra lines

gw = per_example_gradients(X, y, w)                 # one gradient per example
norms = np.linalg.norm(gw, axis=1)
gw = gw * np.minimum(1.0, C / norms)[:, None]      # (1) CLIP each to norm C
noise = rng.normal(0, sigma * C, gw.shape[1])      # (2) ADD Gaussian noise
grad = (gw.sum(0) + noise) / len(y)                # noised, clipped average gradient
w -= lr * grad                                     # ordinary step

# plain SGD 0.966  ->  DP-SGD 0.965   (privacy for ~0.1% accuracy here)

The two privacy operations are the clip line and the noise line — everything else is standard SGD. Real libraries (Opacus for PyTorch, TensorFlow Privacy) add efficient per-example gradient computation and a privacy accountant that tracks the total \(\varepsilon\) spent over all the training steps, so you know exactly how private your final model is.

Why clipping must come first. The order matters: you clip per-example gradients before summing, not the summed gradient. Only per-example clipping bounds how much a single person can affect the update — which is the sensitivity the noise is calibrated to. Clipping the sum would let one huge example dominate before the cap. This per-example clipping is also the main engineering cost of DP-SGD (you can't just use the batched gradient), and it's why specialized libraries exist. The reward is a rigorous statement: "this model is \((\varepsilon,\delta)\)-differentially private," meaning it provably didn't memorize any individual.

⚠️ Mistakes everyone makes here

  • Clipping the batch gradient instead of per-example. Only per-example clipping bounds each person's influence. Clipping the sum gives no privacy guarantee.
  • Setting the clip norm \(C\) badly. Too small and you throw away useful gradient signal (slow, poor learning); too large and you need more noise for the same privacy. \(C\) needs tuning.
  • Ignoring the privacy accountant. Without tracking cumulative \(\varepsilon\) over all steps, you don't actually know how private your model is — "we added noise" isn't a guarantee.
  • Expecting free privacy. Strong privacy (small \(\varepsilon\)) genuinely costs accuracy, more so on hard tasks and small datasets. There's no way around the trade-off.

🔑 Key results to remember

  • DP-SGD makes a whole trained model differentially private with two changes to SGD (eq 3.1).
  • (1) Clip each per-example gradient to norm \(C\) — bounds one person's influence per step.
  • (2) Add Gaussian noise (multiplier \(\sigma\)) to the summed gradients — hides the exact contribution.
  • A privacy accountant tracks total \(\varepsilon\) over all steps; libraries (Opacus, TF-Privacy) handle it.
  • Modest accuracy cost (0.966 → 0.965 here); larger for strong privacy on hard tasks.

Q1. What are DP-SGD's two changes to ordinary SGD?

  • Bigger batches and a smaller learning rate.
    Those are ordinary tuning, not the privacy mechanism.
  • Dropout and weight decay.
    Those are regularizers, not DP operations.
  • Clip each per-example gradient, then add Gaussian noise to the sum.
    Correct. Clip bounds each person's influence; noise hides it.
  • Encrypt the weights and the data.
    DP-SGD adds noise, not encryption.

Q2. Why clip per-example gradients rather than the batch gradient?

  • Only per-example clipping bounds how much one person affects the update.
    Correct. That bounded sensitivity is what the noise is calibrated to.
  • It's faster.
    It's actually slower/costlier — the opposite.
  • To increase accuracy.
    It's about privacy, not accuracy.
  • It uses less memory.
    Per-example gradients use more memory.

✍️ Practice

1. (warm-up) In the interactive, train with zero noise, then with high noise. What happens to the boundary and the accuracy, and what have you gained for that cost?

Show solution

At zero noise the boundary is crisp and accuracy is highest — but this is ordinary SGD with no privacy guarantee. As you raise the noise, the boundary jitters (each step is perturbed) and accuracy dips modestly. What you've gained for that cost is privacy: the noise (with per-example clipping) provably limits how much the trained model reflects any single example, so it can't memorize individuals. That's the whole DP-SGD trade-off in one slider — a little accuracy for a formal guarantee. The practical goal is to pick the least noise that still meets your required privacy level (ε), keeping accuracy as high as possible.

2. (transfer) DP-SGD's accuracy cost is much larger on small datasets than large ones. Why, connecting to Lesson 2?

Show solution

Because privacy is cheaper in a crowd. On a large dataset, each example is one of many, so the fixed amount of noise DP-SGD adds is small relative to the strong, consistent signal from thousands of examples — the consensus easily survives. On a small dataset, each example carries more of the signal (and more of the sensitivity), so the same privacy level requires noise that is large relative to the signal, drowning it and hurting accuracy a lot. This mirrors Lesson 2's point that a private mean needs less noise as \(n\) grows: individual influence shrinks with more people. The implication is practical — DP works best with lots of data, and combining many users' data (e.g., via federated learning) is one way to get the scale that makes strong privacy affordable.

3. (stretch) How do federated learning, DP-SGD, and secure aggregation (next lesson) fit together into a privacy stack?

Show solution

They defend different points and compose into layered protection. Federated learning (Lesson 0) keeps raw data on-device — the server never sees examples, only model updates. DP-SGD (this lesson) makes each client's contributed update differentially private — even if someone sees the update, it provably reveals little about any individual example (this is "local" or "user-level" DP depending on where the noise is added). Secure aggregation (next lesson) ensures the server sees only the sum of client updates, never any individual client's update, using cryptographic masks. Stacked: data never leaves the device (FL), each update is noised so it can't memorize individuals (DP), and updates are cryptographically hidden so the server only learns the aggregate (secure agg). Together they address the three leaks — the data, the per-example memorization, and the per-client exposure — giving a defense far stronger than any one alone. Real privacy-preserving systems (like Google's federated analytics) combine all three.

🚀 In the real world & at the frontier

DP-SGD is how models get trained on sensitive data with a guarantee: medical models, models on user text and behavior, and increasingly large language models where memorization of private training data is a documented risk. Libraries like Opacus and TensorFlow Privacy make it usable, and DP training is becoming a compliance expectation for sensitive applications. The frontier works hard to shrink its cost — better clipping strategies, tighter privacy accounting, architectures friendlier to DP, and pre-training on public data then privately fine-tuning on sensitive data. The tension DP-SGD embodies — strong privacy really does cost accuracy, and can affect groups unevenly — is one of the defining practical challenges of trustworthy AI, and progress here directly expands what can be learned from data people are unwilling, or legally unable, to share.
