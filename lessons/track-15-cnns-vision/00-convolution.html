Convolution: the operation that sees

An MLP treats an image as a flat list of pixels and throws away the one thing that matters most — that nearby pixels belong together. Convolution keeps that structure, and with it a network can learn to see edges, textures, and eventually cats. It starts with one small grid of shared weights.

Track 15 · Lesson 0 Concept + code ~22 min Builds on: Track 4

You built MLPs in Track 4 that classify vectors. Feed one a 100×100 image and two problems appear: you'd flatten it to 10,000 inputs and need millions of weights, and you'd destroy all spatial structure — a shape shifted by one pixel looks like a completely different input. Convolutional neural networks fix both by replacing "every input wired to every neuron" with a tiny grid of shared weights that slides across the image. This lesson builds that sliding operation — the convolution — from scratch.

💡 Concept: one small kernel, slid everywhere

A kernel (or filter) is a small grid of weights — say 3×3. To convolve it with an image, you place it over the top-left corner, multiply each kernel weight by the pixel beneath it, sum those products into a single number, then slide one step right and repeat. Sweeping across the whole image produces a feature map: a new grid where each value says "how strongly the pattern this kernel looks for appears at this spot." The little patch of pixels under the kernel at any moment is that output's receptive field.

Two ideas do all the work. Parameter sharing: the same 9 weights are used at every position, so a detector learned in one corner works everywhere — and you have 9 parameters instead of millions. Locality: each output depends only on a small neighbourhood, matching how visual features (edges, corners) are local. (Strictly, sliding-without-flipping is cross-correlation; deep learning calls it convolution, and since the weights are learned the distinction doesn't matter.) 

def conv2d(image, kernel, stride=1, pad=0):
    if pad: image = np.pad(image, pad)          # keep the borders
    H, W = image.shape; kh, kw = kernel.shape
    H_out = (H - kh)//stride + 1
    W_out = (W - kw)//stride + 1
    out = np.zeros((H_out, W_out))
    for i in range(H_out):
        for j in range(W_out):
            r, c = i*stride, j*stride
            patch = image[r:r+kh, c:c+kw]        # the receptive field
            out[i, j] = np.sum(patch * kernel)   # weighted sum
    return out
Why this is the right inductive bias. A fully-connected layer could learn that neighbouring pixels matter — but it would have to learn it separately for every location, from data. Convolution bakes "features are local and position-independent" into the architecture, so the network spends its data learning what the features are, not where to look. Building the right assumptions into a model (an inductive bias) is one of the most powerful moves in ML.

🔑 Key results to remember

  • Convolution = slide a shared kernel, take a weighted sum at each position → a feature map.
  • Parameter sharing makes it cheap (a 3×3 kernel = 9 weights, reused everywhere) and translation-equivariant (shift the input, the feature map shifts the same way).
  • Output size = \(\lfloor (H + 2p - k)/s \rfloor + 1\), where \(k\) = kernel size, \(p\) = padding, \(s\) = stride. Padding preserves size; larger stride shrinks it.
  • One kernel = one feature detector. Real CNNs learn many kernels per layer, each hunting a different pattern.
  • The weights are learned, not hand-designed — we used Sobel only to see the mechanism; training discovers the useful kernels (Lesson 2).

🧩 Check your understanding
Answer from memory, then read why.

Q1. Why does a convolutional layer need far fewer parameters than a fully-connected layer on the same image?

  • Because it uses lower-precision numbers.
    Precision is unrelated; the saving comes from how weights are organized, not their bit-width.
  • Because the same small kernel is reused at every position instead of a separate weight per input-output pair.
    Correct. Parameter sharing means one 3×3 kernel (9 weights) covers the whole image, versus a dense layer's weight for every pixel-to-neuron connection.
  • Because it discards most of the pixels.
    Convolution visits every pixel; it doesn't throw them away.
  • Because images are small.
    The advantage grows with image size — dense layers scale terribly, conv layers don't.

Q2. An 8×8 image is convolved with a 3×3 kernel, stride 1, no padding. What is the output size?

  • 8×8.
    That would need padding of 1 to preserve size; here there's none.
  • 5×5.
    Check the formula: \((8-3)/1+1 = 6\), not 5.
  • 6×6.
    Correct. \((H-k)/s+1 = (8-3)/1+1 = 6\) per dimension.
  • 3×3.
    That's the kernel size, not the output. The kernel fits in 6 positions per axis.

Q3. "Translation equivariance" of convolution means…

  • if you shift the input, the feature map shifts by the same amount.
    Correct. Because the kernel is applied identically everywhere, a moved feature simply produces a moved response — the detector still fires.
  • the output is identical no matter how you shift the input.
    That's invariance, a stronger property pooling helps approximate — convolution alone is equivariant, not invariant.
  • the kernel rotates with the image.
    Standard convolution is not rotation-equivariant; this describes something else.
  • the image must be square.
    Shape has nothing to do with equivariance.

Q4. We used a fixed Sobel kernel to find edges. In a real CNN, where do the kernel weights come from?

  • They're always Sobel filters.
    Sobel was just a teaching example; real kernels are rarely hand-set.
  • They're chosen randomly and frozen.
    They start random but do not stay frozen — they're updated.
  • They're computed from the image's Fourier transform.
    No FFT is involved in learning the weights; that's a different technique.
  • They're learned by gradient descent, like any other weights.
    Correct. A kernel is just a set of weights; backprop finds the filters that minimize the loss (Lesson 2).

✍️ Practice

1. Run conv2d.py, then transpose the Sobel kernel (sobel_x.T) and convolve again. What does the new kernel detect, and why?

Show solution

Transposing turns the vertical-edge detector into a horizontal-edge detector. Sobel-x has its sign change across columns (left column −, right column +), so it responds to left-right brightness jumps. Transposing puts the sign change across rows, so it now responds to top-bottom jumps. On the test image (a single vertical edge) the transposed kernel gives almost no response — there is no horizontal edge to find. This is the whole idea: each kernel is tuned to one kind of local pattern, and a layer holds many of them.

2. With an 8×8 input and a 3×3 kernel, what padding p keeps the output 8×8? Verify from the size formula.

Show solution

Set output = input: \((8 + 2p - 3)/1 + 1 = 8 \Rightarrow 2p - 3 + 1 = 0 \Rightarrow p = 1\). "Same" padding for an odd kernel of size \(k\) is \(p=(k-1)/2\) — so 1 for 3×3, 2 for 5×5. Add pad=1 in the call and the feature map matches the input size, which is why deep CNNs can stack many conv layers without the image shrinking to nothing.

3. Conceptual: a dense layer is strictly more expressive than a conv layer (it can represent any conv layer plus much more). So why do CNNs beat MLPs on images?

Show solution

Expressiveness is not the bottleneck — generalization from limited data is. The dense layer can represent a convolution, but to learn it it must discover, from data, that weights should be shared and local. That's a needle in an enormous haystack, and with finite data and finite compute it won't find it; it will instead overfit position-specific noise. The CNN hard-codes the right structure, shrinking the hypothesis space to good solutions, so it learns more from less. This is the bias–variance trade-off (Track 3) expressed as architecture: the right constraints reduce variance far more than they cost in bias.
