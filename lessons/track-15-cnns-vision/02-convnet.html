A ConvNet from scratch — and the filters it teaches itself

Convolution plus pooling plus a linear head, trained by the same backprop from Track 4, is a complete convolutional network. We build one in pure NumPy, train it on raw pixels, and then look at the edge detectors it discovered on its own.

Track 15 · Lesson 2 Concept + code ~26 min Builds on: Lessons 0–1, Track 4

You now have the two spatial operations — convolution (Lesson 0) and pooling (Lesson 1). A convolutional network stacks them into a feature extractor, flattens the result, and finishes with a small linear classifier. Crucially, the filters are not designed — they're learned by gradient descent, exactly like the weights of an MLP. In this lesson we implement the whole forward and backward pass by hand and train it to tell vertical bars from horizontal bars in noisy 8×8 images.

💡 Concept: extractor + head, trained end to end

The architecture is a pipeline: image → conv (several filters) → ReLU → max-pool → flatten → linear → softmax. The convolution and pooling turn raw pixels into a compact vector of "which features fired, roughly where"; the linear layer maps that vector to class scores; softmax turns scores into probabilities. Training minimizes cross-entropy (Track 13) with gradient descent — the gradient flows backward through the linear layer, back through pooling (to the winning cells only), back through ReLU, and into the convolution, updating every filter.

The one genuinely new piece of backprop is the convolution's gradient. Because each filter weight touched many output positions (parameter sharing), its gradient is the sum over all those positions of (upstream gradient at that position) × (the input patch that sat under it). Pooling's backward pass we met in Lesson 1: send the gradient only to the argmax cell. Everything else is the linear/softmax/ReLU machinery you already built. 

def conv_backward(dout, x, W):          # gradient w.r.t. the filters
    F, kh, kw = W.shape
    _, Ho, Wo = dout.shape
    dW = np.zeros_like(W)
    for f in range(F):
        for i in range(Ho):
            for j in range(Wo):
                dW[f] += dout[f, i, j] * x[i:i+kh, j:j+kw]   # sum over positions
    return dW

# training step: softmax+CE grad -> linear -> unpool -> ReLU -> conv
dlogits = probs.copy(); dlogits[y] -= 1.0

dW = conv_backward(dc, x, W)             # filters learn
It really works — and fast. Trained on 400 tiny images, this from-scratch CNN reaches 100% test accuracy within one epoch. Starting from random filters (≈50% = chance), gradient descent quickly sculpts them into oriented-edge detectors — because an edge's orientation is exactly the evidence that separates a vertical bar from a horizontal one.

This is the whole promise of deep learning in one picture: give it the right architecture and a goal, and it discovers the features.

🔑 Key results to remember

  • A CNN = feature extractor (conv→relu→pool, stacked) + a small classifier head, trained end to end.
  • Filters are learned by backprop, not designed. The network discovers edge/texture detectors because they reduce the loss.
  • Convolution's weight gradient sums over all positions the shared kernel visited: \(dW_f = \sum_{i,j} dout_{f,i,j}\cdot \text{patch}_{i,j}\).
  • The rest of backprop is familiar: softmax+cross-entropy → linear → unpool (to argmax) → ReLU mask → conv.
  • Depth builds hierarchy: early layers learn edges, later layers combine them into parts and objects (seen in real deep CNNs).

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. Why is a convolution filter's gradient a sum over all output positions?

  • Because summing is numerically more stable.
    It's not a stability trick; it follows from the math of the forward pass.
  • Because the same shared weights were used at every position, so each contributes to the gradient.
    Correct. By the chain rule, a parameter reused in many places accumulates gradient from every place it was used.
  • Because there are multiple filters.
    Each filter's gradient is computed separately; the sum is over spatial positions, not filters.
  • Because of the ReLU.
    ReLU masks gradients but doesn't cause the summation over positions.

Q2. The network started at ~50% accuracy on the two-class task. What does that number represent?

  • A bug — it should start higher.
    No; before training, random filters carry no useful signal.
  • The best achievable accuracy.
    It's the worst-useful case, not the best; training pushes it to ~100%.
  • The training-set accuracy only.
    It's the expected accuracy on either split for a random classifier.
  • Chance level for two balanced classes — random guessing.
    Correct. With two equally likely classes, a random model is right half the time; learning is the climb from there.

Q3. Nobody told the network what an edge is, yet it learned edge detectors. Why?

  • Because oriented edges are the features that best separate the classes, so they minimize the loss.
    Correct. Learning is loss minimization; the gradient drives filters toward whatever features reduce error, and here that's orientation-sensitive edges.
  • Because edges are hard-coded into convolution.
    Convolution is generic; nothing about it presupposes edges.
  • Because the images literally contain the Sobel kernel.
    The Sobel kernel from Lesson 0 was a demo; it's not present during training.
  • Because ReLU produces edges.
    ReLU is a pointwise nonlinearity; it doesn't create edge detectors.

Q4. In a deeper CNN, how do the features typically change from early to late layers?

  • They stay edge detectors throughout.
    Only the first layer or two are edge-like; depth builds beyond that.
  • They get simpler with depth.
    The trend is the opposite — complexity increases with depth.
  • Early layers detect edges; deeper layers combine them into textures, parts, then objects.
    Correct. This hierarchy of composition is a hallmark of deep vision models, confirmed by feature-visualization studies.
  • Deeper layers detect individual pixels.
    Deeper layers have larger receptive fields and more abstract features, not pixel-level ones.

✍️ Practice

1. Run convnet.py, then set n_filters=1. Can a single filter still solve vertical-vs-horizontal? What about the noise level — push noise up until it breaks.

Show solution

One filter is often enough here: a single oriented-edge detector plus pooling already separates the two bar types, so accuracy stays high (a vertical bar excites a vertical-edge filter along a column; a horizontal bar barely does). As you raise the noise, the bars blur into the background and accuracy degrades gracefully, then collapses toward chance once the signal-to-noise ratio drops too far. This maps the model's operating range — every model has one — and shows capacity (number of filters) and problem difficulty (noise) trading off, the same capacity story as Track 3.

2. The dense head has 54 → 2 weights. If we doubled the input image to 16×16, how does the flattened feature count change, and why does that matter for parameter count?

Show solution

With 16×16 input, conv (valid 3×3) gives 14×14, pool 2×2 gives 7×7, so per filter that's 49 features; with 6 filters the flattened vector is 294, and the head becomes 294→2. Notice what did not change: the number of convolution parameters (still 6×3×3 = 54) — because filters are shared, they're independent of image size. Only the dense head grows. That's exactly why modern nets replace a big flatten+dense with global average pooling (average each feature map to one number), keeping the classifier tiny and image-size-agnostic.

3. Conceptual: we verified the CNN works by looking at its learned filters. Why is that kind of inspection more than a curiosity?

Show solution

Because it's evidence the model learned the right thing rather than a shortcut. A model can hit high accuracy for wrong reasons (a background artefact correlated with the label — a "Clever Hans" effect). Seeing sensible edge detectors builds justified confidence; seeing garbage filters despite high accuracy is a red flag that the test set shares a spurious cue with training. This is the entry point to interpretability (Track 14) and to honest evaluation (Track 9): a number alone never tells you why a model is right.
