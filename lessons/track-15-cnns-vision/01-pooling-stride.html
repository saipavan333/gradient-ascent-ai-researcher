Pooling & stride: shrink the picture, keep the point

Convolution finds features but leaves the map as big as the image. Pooling summarizes each little patch with a single number — making the network smaller and faster, and giving it a helpful blindness to exactly where a feature sits.

Track 7 · Lesson 1 Concept + code + interactive ~22 min Builds on: Lesson 0

After a convolution you have a feature map — a grid of numbers where each number says "how strongly my pattern showed up here." For deciding what is in a picture, you almost never need to know a feature's location down to the exact pixel. Knowing an edge appears somewhere in this little region is plenty. Pooling takes advantage of that: it downsamples the map — that just means "makes the grid smaller by summarizing each small patch with one number." The map gets smaller (less to compute), and the network stops caring about tiny shifts in position. This lesson builds pooling from scratch and lets you watch it work.

💡 Intuition: summarize each little patch with one number

Think of shrinking a photo to a thumbnail. You chop the image into little squares and replace each square with a single representative value. There are two natural ways to pick that value. You can take the maximum — the single largest number in the square, which answers "did my feature fire strongly anywhere in here?" Or you can take the average — the mean of the square, which answers "how active was this region on the whole?" The first is called max-pooling, the second average-pooling. Max-pooling is the popular choice, because for feature detection the loudest signal is what matters and the quiet background is just clutter.

The usual setup is a 2×2 square that moves in steps of 2, so the squares don't overlap. That turns a grid into one that is half as tall and half as wide — a quarter of the numbers. The step size a window moves by has a name: the stride. A stride of 2 means "jump two cells each time," which is exactly what shrinks the map. And here is the real prize: because you keep only the biggest value in each square, a feature that wiggles by one pixel but stays inside the same square gives the same pooled answer. In plain terms, the network becomes a little bit blind to exactly where a feature is — a property called translation invariance ("the answer doesn't change when the thing moves a little"). That blindness is a feature, not a bug: a cat is a cat whether it's a few pixels left or right.

✍️ Worked example: max-pool a 4×4 map by hand

Take this 4×4 feature map and pool it with a 2×2 window, stride 2. There are four non-overlapping squares, so the answer is 2×2. I'll do one square carefully and let you see the pattern.

1
Write the map and mark the four squares. \[ \begin{bmatrix}\,\color{#2563eb}1&\color{#2563eb}3&\color{#059669}2&\color{#059669}0\,\\ \,\color{#2563eb}4&\color{#2563eb}2&\color{#059669}1&\color{#059669}5\,\\ \,\color{#d97706}0&\color{#d97706}6&\color{#dc2626}7&\color{#dc2626}2\,\\ \,\color{#d97706}1&\color{#d97706}1&\color{#dc2626}3&\color{#dc2626}4\,\end{bmatrix} \] Each colour is one 2×2 square that will become one output number.
2
Take the maximum of the top-left (blue) square. The four numbers are 1, 3, 4, 2. The biggest is 4. That single number is the top-left of the output.
3
Do the same for the other three. Green square {2,0,1,5} → 5. Orange {0,6,1,1} → 6. Red {7,2,3,4} → 7.
4
Assemble the pooled map. \[ \text{max-pool} = \begin{bmatrix}4&5\\6&7\end{bmatrix}. \] Sixteen numbers became four, and each surviving number is the loudest signal from its corner. If you'd used average-pool instead, the blue square would give \((1+3+4+2)/4 = 2.5\) — smaller, because averaging waters down a single strong response with its quieter neighbours.

🛠️ From scratch: pooling in a few lines

def pool2d(x, size=2, stride=2, mode="max"):
    H, W = x.shape
    H_out = (H - size)//stride + 1
    W_out = (W - size)//stride + 1
    out = np.zeros((H_out, W_out))
    for i in range(H_out):
        for j in range(W_out):
            r, c = i*stride, j*stride
            window = x[r:r+size, c:c+size]       # one little square
            out[i, j] = window.max() if mode == "max" else window.mean()
    return out

That's the whole operation: walk over the map in steps of stride, grab each little window, and keep either its largest value (max) or its average (mean). Notice there are no weights to learn here — pooling is a fixed rule, so it adds nothing to the model's parameter count. It's pure, cheap summarizing.

⚠️ Mistakes everyone makes here

  • Thinking pooling has weights to train. It doesn't. Max and average are fixed operations — there is nothing to learn, which is exactly why pooling is so cheap.
  • Expecting invariance to big shifts. One 2×2 pool only ignores shifts within a 2-pixel square. Move a feature far and the pooled map does change. Large-shift tolerance is built up gradually by stacking several pooling layers, not bought all at once.
  • Confusing stride with kernel size. Kernel size is how big the window is; stride is how far it jumps between windows. A 2×2 window with stride 1 overlaps and barely shrinks the map; stride 2 makes the windows tile neatly and halves each side.
  • Using pooling when you need exact position. Pooling throws away location on purpose. That's great for "what is this?" but harmful for tasks that need a pixel-accurate answer, like outlining an object (more on this below).

🔑 Key results to remember

  • Pooling shrinks a feature map by summarizing each small window with one number: max (loudest response) or average (overall activity).
  • It has no weights — a fixed operation, so it costs the model nothing to learn.
  • Max-pooling gives a little translation invariance: a feature that moves within a window leaves the pooled number unchanged.
  • Stride is the step size the window jumps by; a stride-2 convolution can shrink the map instead of pooling, using learnable weights.
  • Backprop through max-pool sends the gradient only to the cell that was the maximum (the "winner"); the others get nothing.

Q1. How many weights does a max-pooling layer add to the model?

  • One per window.
    Taking a maximum needs no weights — there's nothing to learn per window.
  • One per input channel.
    No weights are attached to channels; pooling is a fixed reduction.
  • Zero — it's a fixed operation.
    Correct. Max and average have no learnable parameters, which is part of why pooling is cheap.
  • The same number as the conv layer before it.
    Pooling has no parameters of its own, regardless of the previous layer.

Q2. A 6×6 feature map goes through max-pool with a 2×2 window and stride 2. What's the output size?

  • 3×3.
    Correct. \((6-2)/2+1 = 3\) per side — a quarter of the numbers.
  • 4×4.
    Re-check: \((6-2)/2+1 = 3\), not 4.
  • 5×5.
    That would be stride 1; here the stride is 2.
  • 6×6.
    Pooling shrinks the map; the size must drop.

Q3. Why is max-pooling usually preferred over average-pooling for detecting features?

  • It's differentiable and averaging isn't.
    Both can be used with gradient descent; that's not the reason.
  • It adds helpful parameters.
    Neither adds any parameters.
  • It's always more accurate.
    Not universally true; it depends on the task.
  • It keeps the strongest evidence a feature is present and ignores the quiet background.
    Correct. For "did this pattern appear here at all?" the peak response is the signal; averaging dilutes a sharp detection with its surroundings.

Q4. During training, how does the gradient pass back through a max-pool window?

  • Split equally among all cells in the window.
    That's how average-pool sends gradients back; max is different.
  • All of it goes to the cell that was the maximum; the others get zero.
    Correct. Only the winning cell affected the output, so only it receives gradient — you remember which cell won on the forward pass.
  • None passes through — pooling blocks gradients.
    Gradients do flow, or the layers before pooling couldn't learn.
  • It's multiplied by the window size.
    No such scaling happens for max-pool.

✍️ Practice

1. (warm-up) Max-pool this 2×2 map with a single 2×2 window: \(\begin{bmatrix}2&9\\5&1\end{bmatrix}\). Then average-pool it. Which is bigger, and why?

Show solution

Max-pool = 9 (the largest). Average-pool = \((2+9+5+1)/4 = 4.25\). Max is bigger because it reports the single loudest value, while the average is dragged down by the three smaller numbers. This is the whole difference in one tiny example: max keeps the peak, average keeps the overall level.

2. (transfer) A feature fires with value 9 at one cell. You shift the input so that the 9 lands in a different 2×2 window than before. Does the max-pooled map change? What if it stays inside the same window?

Show solution

If the 9 moves to a different window, two output cells change — the one it left (which now reports a smaller max) and the one it entered (which now reports 9). If it stays inside the same window, the output is identical, because the maximum of that window is still 9. That's exactly the "little bit of position-blindness" pooling gives: invariance up to the window size, and no further. Try it in the interactive above — nudge a bright cell within its square versus across the boundary.

3. (stretch) Modern networks often replace a 2×2 pool with a convolution that uses stride 2. Both shrink the map by half. What can the strided convolution do that pooling cannot — and what does it cost?

Show solution

A strided convolution shrinks the map while applying learnable weights, so it can learn how to downsample — deciding what to keep rather than blindly taking the max. Pooling is a fixed rule; a strided conv is a trainable one. The cost is exactly those extra weights (more parameters, a bit more computation and overfitting risk). It's a classic trade: pooling is free but rigid; strided convolution is flexible but must be paid for in parameters. Many recent architectures choose the strided conv because the flexibility is usually worth it.

🚀 In the real world & at the frontier

Pooling is everywhere classic CNNs are — the max-pool layers in LeNet and AlexNet, the "global average pool" that modern networks use to squash a whole feature map into one number per channel before the final classifier (which keeps the model small and lets it accept any image size). But there's a real tension worth knowing: pooling deliberately forgets where things are, and some tasks need that location back. Outlining every object in an image (segmentation), finding body joints (pose estimation), and sharpening blurry photos (super-resolution) all rely on precise position, so their networks either pool gently or add clever "skip connections" that carry the lost detail forward (the U-Net design). The lesson researchers keep relearning: a shortcut that helps one task can quietly hurt another — always match the tool to the job.
