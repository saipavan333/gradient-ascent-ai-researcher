Catastrophic forgetting: the network that erases itself

Teach a neural network task A, then task B, and something alarming happens: it forgets task A almost completely. This "catastrophic forgetting" is the central obstacle to building machines that learn continuously, the way humans do.

Track 16 · Lesson 3 Concept + code + interactive ~17 min Builds on: Track 6

Here's a property of neural networks that feels almost broken once you see it. Train a network to do task A — say, classify one set of things — and it does great. Now train that same network on a new task B, without showing it any task-A data. It learns B fine, but when you check task A again, its accuracy has collapsed, often to near-random. It didn't just get a little rusty; it overwrote the very weights that solved A while learning B. This is catastrophic forgetting, and it's the single biggest obstacle to continual learning — the goal of a model that keeps learning new things over its lifetime without erasing the old, the way you learn a new language without forgetting your native one. Humans and animals do this naturally; standard neural networks catastrophically fail at it. This lesson makes the failure vivid — you'll watch task-A accuracy nosedive in real time as the network learns task B — and explains exactly why it happens, setting up the fixes in the final lesson.

💡 Intuition: one whiteboard, two lessons

Imagine a network's weights as a single whiteboard. To learn task A, it covers the board with the notes that solve A. Now you ask it to learn task B on the same board — but it has no instinct to preserve the old notes, so gradient descent freely erases and overwrites whatever helps it do B, scribbling over A's notes in the process. By the time B is learned, A's notes are mostly gone. The network never chose to forget A; it just had no reason to protect A's weights, and the pressure to fit B pushed those weights wherever B needed them. Nothing holds the old knowledge in place.

The mechanism is plain gradient descent. When training on task B, the loss and its gradients depend only on B's data:

\[ \theta \leftarrow \theta - \eta\,\nabla_\theta \mathcal{L}_B(\theta) \qquad \text{— no term for task A, so nothing preserves A's weights} \] (3.1)

Read it: the update moves the weights \(\theta\) purely to reduce task B's loss \(\mathcal{L}_B\); task A appears nowhere in the objective. If the weights that were important for A happen to be useful (or in the way) for B, gradient descent will happily change them. There's no penalty for destroying A-relevant weights, because A's loss isn't being watched. Sharing one set of weights across sequential tasks, with each task's training blind to the others, is the whole disease.

✍️ Worked example: forgetting on two blob tasks

From forgetting.py: task A and task B live in nearby regions with opposite labelling rules, so learning B pulls the shared weights away from A.

1
Learn A. Train the network on task A alone. Task-A accuracy: 0.995. It's mastered.
2
Learn B (no A data). Now train only on task B. Task-B accuracy climbs to 0.99 — B is mastered too.
3
Re-check A. Task-A accuracy has crashed to 0.07 — worse than random guessing (the weights flipped toward B's opposite rule). Catastrophic.
4
The diagnosis. Because the tasks share weights and B's training ignored A, the gradient steps for B overwrote A's solution. The network can hold one rule at a time on these overlapping regions, and B won.

🛠️ From scratch: demonstrating the collapse

net = MLP()
net.train(XA, yA);   a_before = net.acc(XA, yA)   # 0.995  — task A mastered
net.train(XB, yB)                                 # learn B, with NO access to A
a_after = net.acc(XA, yA)                         # 0.07   — task A forgotten!
b_after = net.acc(XB, yB)                         # 0.99   — task B fine

assert a_before > 0.95 and a_after < 0.5 and b_after > 0.95   # the collapse is real

There's no trick here — it's an ordinary MLP trained ordinarily. The forgetting isn't a bug in the code; it's an inherent consequence of shared weights plus task-blind gradient descent. Any standard network trained sequentially will do this.

Why brains don't do this (as much). Biological learning has mechanisms neural nets lack: the brain seems to protect and consolidate important memories (partly during sleep), replay past experiences (the hippocampus replays memory traces), and allocate different neurons to different tasks. Standard artificial networks have none of this by default — every weight is fair game for every task. The fixes in the next lesson are, tellingly, artificial versions of exactly these biological tricks: protect important weights, and replay old data.

⚠️ Mistakes everyone makes here

  • Assuming a bigger network won't forget. More capacity helps a little, but large networks still forget catastrophically when trained sequentially. Capacity isn't the cure.
  • Thinking forgetting means the tasks conflict. Even compatible tasks that could coexist get forgotten, because nothing forces the network to preserve the old solution while learning the new one.
  • Confusing it with overfitting. Forgetting is about losing old knowledge when learning new data, not about generalizing poorly on the current task. It's a sequential-learning problem.
  • Expecting a low learning rate to fix it. A tiny learning rate slows forgetting but also slows learning B; it trades one problem for another rather than solving it.

🔑 Key results to remember

  • Catastrophic forgetting: learning task B on a network erases its ability to do task A.
  • Cause: shared weights + task-blind gradient descent — B's loss has no term protecting A's weights (eq 3.1).
  • It's dramatic: task-A accuracy can crash from ~1.0 to below chance after learning B.
  • Not fixed by more capacity or (fully) by smaller learning rates.
  • It's the core obstacle to continual (lifelong) learning — the subject of the next lesson.

Q1. What is catastrophic forgetting?

  • A network failing to learn any task.
    It learns each task fine; the problem is losing old ones.
  • Overfitting the current task.
    That's a different issue; forgetting is about old knowledge.
  • Learning a new task erases the network's ability to do an earlier one.
    Correct. Task B's training overwrites task A's weights.
  • Running out of memory.
    It's about weights being overwritten, not RAM.

Q2. Why does it happen?

  • Task B's gradient steps change shared weights with no term protecting task A.
    Correct. A's loss isn't in the objective during B, so A's weights are fair game.
  • Because networks can't represent two tasks.
    They often can represent both; the issue is sequential training overwriting.
  • Because of the random seed.
    It's systematic, not a seed artifact.
  • Because task B has more data.
    It happens even with equal data; the cause is task-blind updates.

Q3. Does using a much bigger network fix catastrophic forgetting?

  • Yes, completely.
    Big networks still forget when trained sequentially.
  • Yes, if it has dropout.
    Dropout doesn't address sequential overwriting.
  • Only for images.
    Forgetting is domain-general.
  • No — more capacity helps a little but forgetting persists.
    Correct. Capacity isn't the cure; you need mechanisms that protect or rehearse old knowledge.

Q4. How does catastrophic forgetting differ from overfitting?

  • They're the same thing.
    They're distinct failure modes.
  • Forgetting is losing old-task knowledge when learning new data; overfitting is poor generalization on the current task.
    Correct. One is about sequential tasks, the other about a single task's generalization.
  • Overfitting only happens in RNNs.
    Overfitting happens in any model.
  • Forgetting improves accuracy.
    It destroys old-task accuracy.

✍️ Practice

1. (warm-up) In the interactive, train A fully, then train B and stop it early (a few steps in). Is task A already damaged? What does that tell you about how fast forgetting sets in?

Show solution

Yes — even a few steps of task-B training already dent task-A accuracy, and it degrades steadily from there (as the forgetting-curve figure shows). Forgetting isn't a slow drift that only matters after long training; it begins immediately, because the very first B-gradients already push the shared weights toward B and away from A. This is why continual learning is hard: you can't just "train a bit on the new task and be fine" — you need an explicit mechanism working from the first update to protect or rehearse the old knowledge, which is exactly what the next lesson provides.

2. (transfer) One "obvious" fix is to keep all past data and retrain on everything (A + B together) each time a new task arrives. Why isn't that a real solution to continual learning?

Show solution

Retraining on all past data (joint training) does avoid forgetting — but it defeats the purpose of continual learning. It requires storing every example ever seen (infeasible for a lifelong learner with unbounded task streams, and often impossible for privacy or storage reasons), and retraining from scratch on the entire history for each new task, which gets slower and more expensive without bound. True continual learning wants to absorb new tasks incrementally — with bounded memory and compute, ideally without revisiting all old data. Joint training is the "cheating" upper bound you compare against; the real challenge is getting close to it while storing little and training only on the new task plus, at most, a small memory. That's what replay and regularization methods (next lesson) aim for.

3. (stretch) Based on the whiteboard intuition, propose two different strategies to reduce forgetting — one that touches the data, one that touches the weights.

Show solution

Data strategy — replay/rehearsal: keep a small buffer of old-task examples and mix them into training on the new task, so the gradients still "see" task A and keep its notes on the whiteboard. (This is the next lesson's main method.) Weight strategy — protect important weights: figure out which weights matter most for task A and penalize changing them while learning B (add a term to the loss that anchors those weights near their A-values) — this is Elastic Weight Consolidation (EWC), an artificial version of memory protection. A third family, architectural, gives each task some dedicated capacity so tasks don't share (and overwrite) the same weights. All three map onto the biological tricks from the callout — replay, consolidation, and dedicated neurons — and the next lesson builds the replay version and sketches EWC.

🚀 In the real world & at the frontier

Catastrophic forgetting is why deploying a model that keeps learning from new data is genuinely hard: a recommendation or fraud model updated on this week's data can silently lose last month's patterns; a robot learning a new skill can forget an old one. It's a live constraint on large language models too — naively fine-tuning on new data degrades previously learned abilities, so practitioners use careful mixing, adapters, and replay. Overcoming forgetting is essential for any AI that must adapt over time rather than being frozen after training, and it connects to deep questions about memory, stability, and plasticity that the field is still actively working out. The next lesson shows the practical fixes that make continual learning workable.

Recap — say it to a friend

"Train a network on task A then task B, and it forgets A — often falling below chance — because B's gradient steps overwrite the shared weights with no term protecting A. It's not overfitting and it's not fixed by a bigger network; it's the core obstacle to lifelong learning. Brains avoid it with replay and memory protection, which are exactly the fixes we'll build next."
