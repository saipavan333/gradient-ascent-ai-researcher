Prototypical networks: few-shot by nearest prototype

MAML adapts with gradient steps. Prototypical networks take a simpler, elegant route: learn an embedding where each class is just the average of its examples, and you classify by nearest prototype. Simple, fast, and a remarkably strong few-shot method.

Track 16 · Lesson 2 Concept + code + interactive ~18 min Builds on: Lesson 0

Lesson 0 classified by nearest centroid but relied on whatever embedding you happened to have. Lesson 1's MAML learned to adapt with gradient steps, which is powerful but fiddly. Prototypical networks (protonets) find a sweet spot between them: keep the dead-simple nearest-centroid rule, but meta-learn the embedding itself so that the rule works beautifully. The whole model is one idea — represent each class by a single prototype, the mean of its few examples in the embedding space, and classify a new example by which prototype it's closest to, turning the distances into class probabilities with a softmax. There's no per-task inner loop, no second derivatives — just embed, average, compare. And by training the embedding across thousands of few-shot episodes to make nearest-prototype classification succeed, protonets often match or beat the far more complex MAML. This lesson shows why such a simple recipe is so effective, and what "meta-learning the embedding" really buys you.

💡 Intuition: one representative per class

Suppose each class elects a single representative — the "average member" — and to classify a newcomer, you just see which representative they most resemble. That's a prototype. The insight protonets add over Lesson 0 is that you can shape the space so this works: train the embedding so members of a class cluster tightly around their mean and different classes' means sit far apart. In such a space, the mean is an excellent summary and "nearest prototype" is nearly always right. The distances to the prototypes become a natural measure of confidence — very close to one prototype and far from the rest means high certainty; roughly equidistant means the model is unsure.

Formally, embed the support, average each class into a prototype \(c_k\), and convert the query's distances to prototypes into probabilities with a softmax over the negative distances:

\[ c_k = \frac{1}{K}\sum_{i \in k} f(x_i), \qquad p(y=k \mid x_q) = \frac{\exp\!\big(-\lVert f(x_q)-c_k\rVert^2\big)}{\sum_{k'}\exp\!\big(-\lVert f(x_q)-c_{k'}\rVert^2\big)} \] (2.1)

The prototype \(c_k\) is the mean embedding of class \(k\)'s support. For a query \(x_q\), we measure its squared distance to each prototype; the negative distance is a similarity score (closer = higher), and the softmax turns those scores into class probabilities that sum to 1. Nearest prototype gets the most probability. Training minimizes the cross-entropy of this on query examples across many episodes — which pushes the embedding \(f\) to make prototypes clean and well-separated.

✍️ Worked example: softmax over distances

A query sits at these squared distances from three prototypes: \(d = [1,\ 4,\ 9]\). Turn them into class probabilities via equation (2.1).

1
Negate the distances (closer should score higher): scores \(=-d=[-1,-4,-9]\).
2
Exponentiate: \(e^{-1}=0.368,\ e^{-4}=0.018,\ e^{-9}=0.0001\). Sum \(=0.386\).
3
Normalize: \(p=[0.953,\ 0.047,\ 0.0003]\). The nearest prototype (distance 1) gets 95% of the probability; the far one is negligible.
4
Read it as confidence. A clear winner means a confident, well-separated query. If the two nearest distances were close (say \(d=[1,1.2,9]\)), the probability would split — the model honestly reporting uncertainty. In the validated run, 5-way 5-shot protonets reach 100% accuracy on well-separated classes, assigning near-1 probability to the true class.

🛠️ From scratch: prototypical classification

def proto_classify(S, Sy, Q, n_way):
    protos = np.array([S[Sy == c].mean(0) for c in range(n_way)])   # mean embedding per class
    d = ((Q[:, None] - protos[None])**2).sum(2)                     # squared dist to each proto
    logits = -d                                                    # nearer = higher score
    p = softmax(logits)                                            # distances -> probabilities
    return p.argmax(1), p                                          # predict + confidence

# 5-way 5-shot accuracy ~1.00;  avg probability on the true class ~1.00

The classifier is four lines and has no trainable parameters of its own — the only thing that's learned is the embedding \(f\) that produced S and Q. That's the elegance: all the intelligence lives in the representation, and the decision rule is a transparent softmax over distances. It's also why protonets are so fast at test time.

Why averaging is the right call. Using the mean as the prototype isn't arbitrary — under the squared-Euclidean distance in equation (2.1), the class mean is provably the point that minimizes the total distance to that class's examples (the same fact behind k-means, Track 13). And the softmax-over-negative-squared-distance is exactly the posterior you'd get from a Gaussian model with equal, spherical covariance per class. So protonets have a clean probabilistic interpretation: they're doing simple Gaussian classification in a learned space. Simple method, principled roots.

⚠️ Mistakes everyone makes here

  • Thinking the classifier is what's learned. The nearest-prototype rule has no parameters; the embedding \(f\) is the entire learned model. Improve the embedding, not the rule.
  • Using the wrong distance. Protonets rely on squared-Euclidean distance (which makes the mean the optimal prototype). Swapping in cosine or other metrics changes what the prototype should be.
  • Assuming one prototype fits every class. A single mean assumes each class is a single blob. Multi-modal classes (e.g., "dog" spanning very different breeds) may need multiple prototypes per class.
  • Ignoring that prototypes shift with the support. Different sampled support examples give slightly different prototypes — more shots stabilize them, exactly as in Lesson 0.

🔑 Key results to remember

  • Prototype = the mean embedding of a class's support examples.
  • Classify by nearest prototype; softmax over negative squared distances gives class probabilities (eq 2.1).
  • The classifier has no parameters — only the embedding \(f\) is meta-learned (across many episodes).
  • Principled: the mean is optimal for squared distance; the softmax is Gaussian classification in the learned space.
  • Simpler than MAML, often as good — no inner loop, no second derivatives.

Q1. In a prototypical network, what is a class prototype?

  • A trainable weight vector.
    It's computed from the support, not a free parameter.
  • The mean embedding of that class's support examples.
    Correct. Average the few examples in the embedding space.
  • The query point.
    The query is what you classify against prototypes.
  • The output layer.
    There's no trained output layer; the rule is parameter-free.

Q2. How does a protonet turn distances into class probabilities?

  • By counting neighbours.
    That's k-NN; protonets use prototypes and a softmax.
  • By thresholding the nearest distance.
    It uses a smooth softmax, not a hard threshold.
  • Softmax over the negative squared distances to the prototypes.
    Correct. Closer = higher score; softmax normalizes to probabilities.
  • By training a logistic regression.
    No extra classifier is trained; the rule is parameter-free.

Q3. What is actually learned in a prototypical network?

  • The embedding \(f\), trained so nearest-prototype classification works.
    Correct. The decision rule has no parameters; the embedding is the model.
  • The prototypes directly.
    Prototypes are computed from support at test time, not learned weights.
  • The softmax temperature only.
    The core learned object is the embedding.
  • Nothing is learned.
    The embedding is meta-learned across episodes.

Q4. Why is the mean a good choice for the prototype?

  • It's the largest example.
    It's an average, not an extreme.
  • It's random.
    It's deterministic and principled.
  • It maximizes distance to the class.
    The opposite — it minimizes distance to the class's examples.
  • Under squared distance, the mean minimizes total distance to the class's examples.
    Correct. That's why averaging is optimal, and it links to Gaussian classification.

✍️ Practice

1. (warm-up) In the interactive, drag the query to sit exactly between two prototypes. What do the probability bars show, and what does that represent?

Show solution

The two nearest prototypes get roughly equal, large probabilities and the far ones get almost none — the model splits its confidence 50/50 between the two plausible classes. This is the softmax honestly reporting uncertainty: equidistant from two prototypes means the evidence genuinely doesn't favour either. It's a nice property of protonets — the distances give not just a prediction but a calibrated-feeling confidence (Track 15), and a near-tie is a signal you might want more shots or a better embedding to separate those classes.

2. (transfer) Protonets and MAML both do few-shot learning. Give one advantage of each.

Show solution

Protonet advantages: dramatically simpler — no inner-loop adaptation, no second derivatives, one forward pass to embed and classify; fast at test time; and a clean probabilistic interpretation. MAML advantages: more flexible — it actually adapts the network's weights to the new task, so it can handle tasks where a fixed embedding plus nearest-prototype isn't enough (e.g., tasks requiring the features themselves to change, or non-classification tasks like regression and RL where "prototype" doesn't apply). In practice, for few-shot classification protonets are a strong, simple default that often matches MAML; MAML's edge shows on harder or non-classification adaptation. The general lesson: prefer the simplest method that works (protonet), reach for the more powerful, complex one (MAML) only when the simple one demonstrably falls short.

3. (stretch) A single mean prototype assumes each class is one blob. Describe a realistic class that breaks this, and how you'd extend protonets to handle it.

Show solution

A class like "chair" is multi-modal: office chairs, armchairs, bar stools, and beanbags occupy very different regions of feature space, so their single mean lands in a no-man's-land representative of none of them, and a genuine chair query might be far from that mean. Extensions: use multiple prototypes per class (cluster each class's support with k-means and keep several sub-prototypes, classifying by the nearest of any of a class's prototypes), or learn a richer per-class density instead of a single point. This trades protonets' simplicity for expressiveness when classes really are multi-modal. It's the same lesson as k-means vs a mixture model (Track 13/15): one centroid is a strong, cheap assumption, but multi-modal data needs more than one representative to be captured faithfully.

🚀 In the real world & at the frontier

Prototypical networks are a standard, strong baseline for few-shot classification and are widely used in practice for their simplicity and speed — in vision, text classification, and drug discovery, wherever new categories appear with few examples. Their "compare to a class prototype in a learned space" idea also underlies metric-learning systems everywhere: face recognition (each identity is a prototype embedding), speaker verification, and retrieval. The broader lesson protonets teach is that a great representation plus a trivial decision rule often beats a mediocre representation plus a clever classifier — a theme that recurs across modern AI, from contrastive learning (Track 13) to the frozen-embedding few-shot systems built on today's foundation models.

Recap — say it to a friend

"A prototypical network represents each class by one prototype — the mean of its few examples in a learned embedding — and classifies a query by nearest prototype, using a softmax over negative distances for probabilities. The decision rule has no parameters; only the embedding is meta-learned, trained across episodes so the simple rule works. It's much simpler than MAML and often just as accurate."
