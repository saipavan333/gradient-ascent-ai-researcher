Self-supervised learning: labels for free

The trick that powers modern AI: instead of paying humans for answers, hide part of each input and train the model to predict the missing part from the rest. The data becomes its own teacher — and the representation it learns transfers to real tasks.

Here is the idea that quietly rewired the field. Supervised learning needs a human to write down the answer \(y\) for every input \(x\). Self-supervised learning refuses to pay that bill. It takes an ordinary unlabelled input and manufactures a prediction task out of it — cover up a word and predict it, cut an image in half and predict the missing half, delete a number from a sequence and fill it in. The "answer" is just the part you hid, so it costs nothing. You then train a perfectly normal supervised model on this made-up task. The point is not the task itself — nobody cares whether the model can un-hide a word. The point is that to succeed, the model must build a genuine internal understanding of the data, and that understanding, called a representation, is what you keep and reuse. This lesson builds the cleanest example — an autoencoder — and shows the representation falling out for free.

💡 Intuition: to fill in the blank, you must understand the sentence

Think of the fill-in-the-blank exercises from school: "The capital of France is ____." To answer, you didn't need anyone to label the sentence — the missing word was the answer, hidden in plain sight. And to fill it in reliably across thousands of such sentences, you had to actually learn geography, grammar, and meaning. That is the whole trick of self-supervision: the prediction task is a pretext — an excuse — and the real prize is the understanding you're forced to build along the way.

The autoencoder is the same idea in its barest form. Instead of hiding part of the input, it hides capacity: it squeezes the whole input through a narrow bottleneck — a code far too small to just memorize the input — and then asks the model to rebuild the original from that tiny code. To rebuild a face from 20 numbers, those 20 numbers can't be random; they must capture the things that actually matter about faces. The bottleneck forces the model to compress structure, and the compressed code is the representation you walk away with.

An autoencoder has two halves. The encoder takes the input \(x\) and squeezes it down to a small code \(z\). The decoder takes \(z\) and tries to rebuild the input, producing \(\hat{x}\) (x-hat, the reconstruction). Training minimizes how different the rebuild is from the original — nothing more:

\[ z = \text{encoder}(x), \qquad \hat{x} = \text{decoder}(z), \qquad \mathcal{L} = \lVert x - \hat{x} \rVert^2 \] (1.1)

Read it plainly: encode \(x\) into the small code \(z\); decode \(z\) back into a guess \(\hat{x}\); the loss \(\mathcal{L}\) is the squared difference between the original and the guess (\(\lVert\cdot\rVert^2\) means "add up the squared errors across every number"). There is no label \(y\) anywhere — the input plays the part of its own target. That is why it is called self-supervised. Because it is an ordinary squared-error loss, you train it with the exact same gradient descent and backpropagation from Tracks 2 and 4.

✍️ Worked example: why the bottleneck forces understanding

Follow what the size of the code does, using our validated demo: 8-D data (three hidden groups) squeezed to a 2-number code.

1
Before training. Random encoder and decoder weights. The reconstruction is garbage: squared error per point ≈ 17.9. The code is meaningless noise.
2
Train to rebuild. Minimize \(\lVert x-\hat x\rVert^2\) by gradient descent — no labels used. Error falls from 17.9 to about 0.96. The 2-number code now carries enough to rebuild each 8-D point closely.
3
Inspect the code — the payoff. Colour the 2-D codes by the hidden group (which the model never saw). They fall into three clean clusters: k-means on the codes matches the true groups with 0.997 purity. The pretext task was "rebuild yourself," but the representation it produced separates the classes for free.
4
Use it downstream. Now a classifier needs almost no labels: the hard work of organizing the data is already done in the code. That is the entire value proposition — learn the representation from unlimited unlabelled data, then fine-tune on a tiny labelled set.

🛠️ From scratch: an autoencoder's forward pass

def forward(self, X):
    h1 = np.tanh(X @ self.W1.T + self.b1)   # encoder layer
    z  = h1 @ self.W2.T + self.b2           # THE CODE (bottleneck: only 2 numbers)
    h2 = np.tanh(z @ self.W3.T + self.b3)   # decoder layer
    xr = h2 @ self.W4.T + self.b4           # reconstruction  x-hat
    return xr, z, h1, h2

# loss = mean squared error between X and xr  ->  NO labels, x is its own target
# after training: `z` is the learned representation you keep and reuse

It is an ordinary neural network — the only special thing is the narrow middle layer z and the fact that the target is the input itself. Train it on unlabelled data, throw away the decoder, and the encoder is now a feature extractor: feed it new data and read off z as a compact, structure-preserving representation.

This is how the big models are born. A modern language model is pre-trained by self-supervision on a staggering scale: hide the next word, predict it, across trillions of words of unlabelled text (Track 9). It never sees a human label during pre-training. The "understand the data to fill the blank" pressure builds a representation so rich that a tiny amount of labelled fine-tuning afterward turns it into a translator, a coder, or a chatbot. Self-supervision is why pre-training scaled.

⚠️ Mistakes everyone makes here

  • Caring about the reconstruction. Nobody wants a machine that copies its input. The reconstruction (or the filled-in blank) is a throwaway pretext — the representation \(z\) is the product.
  • Making the bottleneck too wide. If the code is as big as the input, the network can just copy \(x\) through unchanged, learn nothing, and score a perfect loss. The squeeze is what forces understanding — no squeeze, no learning.
  • Confusing it with unsupervised learning. Self-supervised learning trains a real supervised model on an invented task; it just gets its labels from the data. k-means (Lesson 0) has no prediction task at all.
  • Expecting the pretext task to be the useful one. "Predict the missing patch" is not a product. Its value is entirely in the transferable features it forces the network to build.

🔑 Key results to remember

  • Self-supervised = invent a prediction task from unlabelled data (hide part, predict it). Labels come free from the data.
  • The pretext task is a means; the learned representation is the end.
  • An autoencoder compresses \(x\) to a small code \(z\) and rebuilds it: \(\mathcal{L}=\lVert x-\hat x\rVert^2\), no labels.
  • The bottleneck must be narrow — otherwise the network just copies the input and learns nothing.
  • The code preserves structure: in our demo, k-means on the learned code recovered the hidden classes at 0.997 purity — separation for free.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. In self-supervised learning, where do the labels come from?

  • From human annotators, as usual.
    The whole point is to avoid human labelling.
  • From a separate labelled dataset.
    No external labels are used; the signal is internal.
  • From the data itself — you hide part of the input and predict it.
    Correct. The hidden part is the answer, so labels are free.
  • They aren't used at all; there is no prediction target.
    There is a target — it's just manufactured from the input rather than provided by a human.

Q2. Why must an autoencoder's code be smaller than its input?

  • To make training faster.
    Speed isn't the reason; a wide code can even be slower to help.
  • Otherwise it can copy the input straight through and learn nothing.
    Correct. The squeeze forces the network to compress structure instead of memorizing.
  • Because bigger codes cause overflow.
    There's no numerical overflow issue here.
  • To match the number of classes.
    The code size is unrelated to any class count — there are no classes in the pretext task.

Q3. After training an autoencoder, what do you actually keep and use?

  • The reconstructions \(\hat x\).
    Reconstructions are throwaway — a copy of the input has no value.
  • The loss value.
    The loss tracked training; it isn't the product.
  • The decoder.
    Usually discarded — its job was only to make the pretext task well-defined.
  • The encoder, to produce the representation \(z\) for new inputs.
    Correct. The encoder becomes a feature extractor; \(z\) is the transferable representation.

Q4. Why is self-supervision central to modern large models?

  • It lets them pre-train on enormous unlabelled corpora, then fine-tune on a little labelled data.
    Correct. Hiding-and-predicting on trillions of unlabelled tokens builds rich features no labelling budget could buy.
  • It removes the need for gradient descent.
    It still trains by ordinary gradient descent.
  • It guarantees zero error.
    It guarantees nothing of the sort; it's about scale of data.
  • It only works on small datasets.
    The opposite — its superpower is exploiting massive datasets.

✍️ Practice

1. (warm-up) In the interactive, rotate the code axis to its worst orientation (largest error), then Auto-fit. What is the axis doing at the best orientation, in terms of the data's spread?

Show solution

The worst axis points across the data's narrow direction, so most of each point's position is lost (long red stubs). Auto-fit rotates the axis to lie along the direction the data spreads out the most — the "long axis" of the cloud. Compressing along that direction throws away the least, because it keeps the coordinate that varies most between points. A linear autoencoder's best 1-D code is exactly the top principal component (Track 15's PCA); this widget is showing you PCA as compression.

2. (transfer) Run self_supervised.py. The reconstruction error drops from ~17.9 to ~0.96 and the codes cluster at 0.997 purity. Which of those two numbers is the one you actually care about, and why?

Show solution

The purity. The falling reconstruction error only tells you the pretext task is being solved — the network is learning to rebuild inputs, which is worthless on its own. The purity tells you the by-product — the learned code — has organized the data so that the hidden classes are separated, which is what makes the representation useful downstream. Always evaluate self-supervision by the quality of the representation (usually via a downstream task), never by how well it solved the make-believe pretext task.

3. (stretch) Language models hide the next word; some vision models hide a random patch of an image (masked autoencoders). Propose a self-supervised pretext task for audio, and say what representation you'd hope it forces the model to learn.

Show solution

Many good answers. One: mask a short slice of the waveform (or spectrogram) and predict it from the surrounding audio — to fill it in, the model must learn phonemes, pitch, timbre, and rhythm, exactly the features a speech or music task needs. Another: predict whether two short clips came from the same recording (a contrastive task, Lesson 2). Another: predict the correct time-order of shuffled clips, forcing it to learn temporal structure. In every case the pretext is throwaway; the value is that solving it requires genuinely understanding sound. This is real: wav2vec and HuBERT pre-train speech models exactly this way.

🚀 In the real world & at the frontier

Self-supervision is arguably the most important idea in modern AI. BERT masks words in a sentence and predicts them; GPT predicts the next word; masked autoencoders blank out image patches; wav2vec does it for speech. In every case, a model trained to fill in blanks on unlabelled data learns representations so strong that fine-tuning on a small labelled set beats years of hand-engineered features. The research frontier is about designing pretext tasks whose "understanding requirement" matches what you ultimately want — and Lesson 2's contrastive learning is one of the most powerful of these, so influential it deserves its own lesson.

Recap — say it to a friend

"Self-supervised learning invents its own labels: hide part of the input and train the model to predict it. An autoencoder is the simplest case — squeeze the input through a tiny code and rebuild it, no labels. Nobody wants the rebuild; the prize is the code, a compact representation that already organizes the data. That's how today's big models pre-train on the whole unlabelled internet."
