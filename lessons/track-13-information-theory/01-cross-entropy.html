Cross-entropy: the loss you’ve always used

Every classifier and language model you’ve trained minimized “cross-entropy loss.” Now you’ll see exactly what it measures — the cost of using the wrong distribution — and why minimizing it is the same as maximum likelihood.

Cross-entropy is the single most important loss function in deep learning — it’s what you minimized to train the MLP (Track 4), the GPT (Track 5), and every classifier. Entropy measured the surprise of a distribution against itself; cross-entropy measures the surprise when you use a wrong distribution to describe the data. That gap is exactly what training closes.

💡 Concept: the cost of a wrong belief

Suppose the true distribution of labels is \(p\), but your model predicts \(q\). The cross-entropy is the average surprise you experience when reality follows \(p\) but you expected \(q\):

\[ H(p, q) = -\sum_x p(x)\,\log_2 q(x) \quad\text{bits}. \] (1.1)

In classification the true distribution \(p\) is a one-hot vector — all the mass on the correct class — so the sum collapses to a single term: \(H(p,q) = -\log_2 q(\text{true class})\). The loss is just the negative log-probability your model assigned to the right answer. Predict the correct class with high probability → small loss; assign it low probability → large loss.

📐 Why minimizing it = maximum likelihood

Cross-entropy has a floor. It is always at least the entropy \(H(p)\), with equality only when \(q = p\):

\[ H(p, q) \;\ge\; H(p), \qquad \text{equality} \iff q = p. \] (1.2)

The verification in cross_entropy.py makes this concrete: for \(p=[0.6,0.3,0.1]\), \(H(p,p)=H(p)=1.295\) bits exactly, and any other \(q\) gives a strictly higher cross-entropy. So minimizing cross-entropy pushes your model’s \(q\) toward the true \(p\). And summed over a dataset, \(-\sum \log q(\text{label})\) is precisely the negative log-likelihood — so minimizing cross-entropy is maximum likelihood estimation (Track 1), now revealed as an information-theoretic principle. The two names describe the same objective.

The softmax + cross-entropy pairing. This is why classifiers end in a softmax (turning scores into a distribution \(q\)) followed by cross-entropy loss: softmax produces the predicted probabilities, cross-entropy scores them against the true class by negative log-probability, and the gradient — beautifully — is just \(q - p\) (predicted minus true), which you derived by hand in Track 5’s GPT. Information theory explains why that clean gradient exists.

✍️ Worked example: the loss for one prediction

Cross-entropy is exactly the loss your classifiers minimise. Take a 3-class example whose true label is class 1 (so \(p=[1,0,0]\), a one-hot).

1
Confident and right. Model says \(q=[0.9,0.05,0.05]\). Loss \(=-\log_2 0.9 = 0.15\) bits. Small — good prediction, small penalty.
2
Unsure. \(q=[0.34,0.33,0.33]\). Loss \(=-\log_2 0.34 = 1.56\) bits. Bigger — hedging is penalised.
3
Confident and wrong. \(q=[0.02,0.49,0.49]\). Loss \(=-\log_2 0.02 = 5.6\) bits. Huge — the loss explodes as the true class's probability approaches zero.
4
Why one-hot simplifies it. With a one-hot label, \(H(p,q)=-\log q_{\text{true}}\) — only the probability the model gave to the correct class matters. That single term is the cross-entropy loss (in nats when using \(\ln\)), summed over your batch.

🔑 Key results to remember

  • Cross-entropy \(H(p,q) = -\sum_x p(x)\log_2 q(x)\): average surprise of using \(q\) when the truth is \(p\).
  • For one-hot labels it’s \(-\log q(\text{true class})\) — the negative log-probability of the right answer.
  • \(H(p,q) \ge H(p)\), with equality iff \(q=p\): using the wrong distribution always costs extra.
  • Minimizing cross-entropy = maximum likelihood (negative log-likelihood) = pushing \(q\) toward \(p\).
  • Softmax + cross-entropy gives the clean gradient \(q-p\) — the workhorse of classification.

⚠️ Mistakes everyone makes here

  • Thinking cross-entropy is symmetric. \(H(p,q)\ne H(q,p)\). The true distribution \(p\) weights the terms; the prediction \(q\) sits inside the log. Order matters.
  • Forgetting the floor. Cross-entropy can't go below the true entropy \(H(p)\). Minimising it drives \(q\to p\); the leftover gap above \(H(p)\) is the KL divergence.
  • Feeding un-normalised \(q\). \(q\) must be a probability distribution (softmax output). Raw logits aren't probabilities — always softmax first.
  • Confusing bits and nats. Frameworks compute cross-entropy with \(\ln\) (nats). Same objective, scaled by \(\ln 2\); the gradients point the same way.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. For a one-hot label, cross-entropy loss equals…

  • the entropy of the model’s prediction.
    That’s the model’s own output entropy, a different quantity. Cross-entropy compares prediction to the true label.
  • the negative log-probability the model assigned to the correct class.
    Correct. With \(p\) one-hot, \(-\sum p\log q\) keeps only the true class’s term: \(-\log q(\text{true})\). High confidence in the right class → low loss.
  • the number of classes.
    Loss depends on the predicted probability, not the class count.
  • always 1 bit.
    It varies continuously with \(q\); it’s only ~1 bit for a specific \(q\).

Q2. Cross-entropy \(H(p,q)\) is minimized (equal to \(H(p)\)) when…

  • \(q\) is uniform.
    A uniform \(q\) generally gives high cross-entropy unless \(p\) is also uniform.
  • \(q\) is one-hot.
    A confident \(q\) is only best if it’s confident about the right thing, i.e. matches \(p\).
  • the entropy \(H(p)\) is zero.
    That’s a property of \(p\), not the condition for the minimum over \(q\).
  • \(q = p\) — the model’s distribution matches the true one.
    Correct. \(H(p,q)\ge H(p)\) with equality iff \(q=p\); training drives \(q\) toward \(p\) precisely to reach this floor.

Q3. Why is minimizing cross-entropy the same as maximum likelihood?

  • Because summed over the data, \(-\sum \log q(\text{label})\) is the negative log-likelihood.
    Correct. Cross-entropy loss over a dataset is exactly the negative log-likelihood of the labels under the model, so minimizing one maximizes the other — two names, one objective.
  • Because both require a GPU.
    Hardware is irrelevant to the equivalence.
  • They are actually different objectives.
    They coincide exactly for the standard setup; that’s the key insight.
  • Because cross-entropy ignores the labels.
    It centrally uses the labels (they define \(p\)); that’s how it connects to likelihood.

Q4. During training, a model predicts the correct class with probability 0.01. What does cross-entropy do?

  • Gives near-zero loss.
    Near-zero loss is for confident-correct predictions; this is a confident mistake.
  • Gives a moderate, capped loss.
    The loss isn’t capped — \(-\log q\) grows without bound as \(q\to0\).
  • Gives a very large loss (\(-\log_2 0.01 \approx 6.6\) bits), strongly penalizing the confident error.
    Correct. The steep tail of \(-\log q\) means assigning tiny probability to the truth is punished hard, producing a large gradient that rapidly corrects the model — exactly what you want.
  • Gives negative loss.
    Cross-entropy is non-negative; \(-\log q\) is positive for \(q<1\).

✍️ Practice

1. Run cross_entropy.py. Confirm that \(H(p,p)=H(p)\) and that every other \(q\) gives more. Why does this guarantee training can’t “overshoot” the true distribution?

Show solution

Because cross-entropy is a bowl with its unique minimum exactly at \(q=p\) (value \(H(p)\)), and it rises in every direction away from \(p\). Gradient descent on it therefore heads toward \(p\) and settles there — it can’t do better than matching the true distribution, and any deviation strictly increases the loss. This is why cross-entropy is such a well-behaved training objective: its global minimum is precisely “predict the truth,” with no spurious better options. (In practice \(p\) is the empirical label distribution, so the model targets the data’s statistics — which is why honest evaluation on held-out data, Track 9, still matters.)

2. “Label smoothing” replaces the one-hot target with, say, \([0.9, 0.05, 0.05]\). In cross-entropy terms, what does that change?

Show solution

It changes the target distribution \(p\) from a hard one-hot to a slightly softened one. Minimizing cross-entropy now drives \(q\) toward that softer target instead of demanding \(q(\text{true})\to1\). The effect is regularization: the model is discouraged from becoming over-confident (pushing a single probability to 1 requires enormous logits), which improves calibration and often generalization. It’s a small, information-theoretically clean tweak — you’re just telling cross-entropy to aim for a less extreme \(p\) — and it connects to the over-confidence concerns behind calibration and the KL penalties of the next lesson.

3. Conceptual: a language model reports validation “perplexity” 20. Relate this to cross-entropy and to what the model is doing.

Show solution

Perplexity is \(2^{H(p,q)}\) where \(H(p,q)\) is the model’s per-token cross-entropy (in bits). Perplexity 20 means the model’s uncertainty per token equals choosing uniformly among 20 options — equivalently a cross-entropy of \(\log_2 20 \approx 4.3\) bits per token. Lower perplexity = lower cross-entropy = the model assigns higher probability to the actual next tokens = better prediction. So perplexity is just cross-entropy in a more interpretable unit, and improving a language model is reducing its cross-entropy on held-out text — the same objective you trained with, now used to evaluate.

🚀 In the real world & at the frontier

Cross-entropy is the default loss for classification and language modelling — every time a network predicts a distribution over classes or over the next token, it's trained by minimising cross-entropy against the true labels. Its information-theoretic reading — "how many extra bits does your imperfect model cost versus the truth?" — is exactly why it's the right objective: minimising it is minimising the coding cost of your predictions. It also connects straight to maximum likelihood (minimising cross-entropy = maximising the likelihood of the data), tying the loss you use every day to a deep statistical principle.

Recap — say it to a friend

"Cross-entropy \(H(p,q)=-\sum p\log q\) is the average bits to encode data from the true distribution \(p\) using a model \(q\). It's the loss behind every classifier and language model: minimising it pushes the prediction \(q\) toward the truth \(p\), and it bottoms out at the true entropy \(H(p)\). Confident-and-wrong predictions get punished hardest, because the loss blows up as the true class's probability goes to zero."
