GRU: the same idea, with fewer parts

The GRU keeps the LSTM's key insight — gates that protect a memory — but trims it down: two gates instead of three, one state instead of two. Fewer parameters, faster training, and often just as accurate. A lesson in cutting to the essentials.

Track 8 · Lesson 3 Concept + code + interactive ~20 min Builds on: Lesson 2

The LSTM works, but it carries a lot of machinery: three gates, a separate candidate, and two separate states. The Gated Recurrent Unit (GRU), introduced by Cho and colleagues in 2014, asks a good engineering question: is all of that necessary? It merges the two states into one and collapses the forget and input gates into a single update gate. The result is a smaller, faster cell that, on many tasks, matches the LSTM — a clean example of simplifying a design without losing what makes it work.

💡 Intuition: one dial that fades old into new

The LSTM used two separate valves — one to keep old memory, one to write new. The GRU notices these often do opposite jobs, so it uses one dial to handle both at once: the update gate \(z\). Think of a photo cross-fade slider. At one end you see the old picture; at the other, the new one; in between, a blend. The GRU's update gate blends the old memory with a freshly proposed one:

\[ h_t = (1-z)\odot n + z\odot h_{t-1}. \] (3.1)

When \(z\approx 1\), the slider sits on "old" — the previous memory \(h_{t-1}\) is copied forward almost unchanged (and, since the new content is weighted by \(1-z\approx 0\), nothing new is written). That's the exact "carry it forward, keep the gradient's highway" trick from the LSTM, now done by a single gate. When \(z\approx 0\), the slider sits on "new" — the fresh candidate \(n\) takes over. A second gate, the reset gate \(r\), decides how much of the old memory to mix into that candidate in the first place:

\[ r=\sigma(W_r[x,h]),\quad z=\sigma(W_z[x,h]),\quad n=\tanh(W_n[x,\, r\odot h]). \] (3.2)

Two gates, one state — and the same protection against vanishing gradients, because when \(z\approx1\) the memory (and the gradient) rides forward untouched.

✍️ Worked example: the update gate as a cross-fade

Start with memory \(h_0 = 1\), and let a distracting candidate \(n = 0\) arrive each step. Compare two settings of the update gate.

1
Keep it (\(z=1\)): \(h_t = (1-1)\cdot 0 + 1\cdot h_{t-1} = h_{t-1}\). The memory stays at 1 every step — carried forward untouched, exactly like an LSTM with the forget gate open.
2
Overwrite it (\(z=0\)): \(h_t = (1-0)\cdot 0 + 0\cdot h_{t-1} = 0\). The old memory is instantly replaced by the incoming content. Great for "pay attention to what just arrived, forget the past."
3
Blend (\(z=0.5\)): \(h_t = 0.5\cdot 0 + 0.5\cdot h_{t-1} = 0.5\,h_{t-1}\). The memory halves each step — a gradual fade, like a leaky bucket.
4
The point. One number \(z\) spans the whole range from "remember perfectly" to "replace completely." The LSTM needed a forget gate and an input gate to cover the same ground; the GRU ties them together into one, saving a gate's worth of parameters.

🛠️ From scratch: two gates, one state

r = sigmoid(Wr @ [x, h])
z = sigmoid(Wz @ [x, h])
n = tanh(Wn @ [x, r*h])            # reset gate mixes the past into the candidate
h = (1 - z)*n + z*h_prev           # update gate cross-fades old vs new
Fewer parts, same job. A GRU uses three weight matrices where an LSTM uses four — about 25% fewer recurrent parameters for the same width. On a long-range memory task it still latches and holds the signal (we bias the update gate toward "carry," just like the LSTM's forget-bias trick). Whether LSTM or GRU wins is task-dependent and usually close — so the GRU's smaller size often makes it the practical default.

⚠️ Mistakes everyone makes here

  • Thinking one gate is strictly worse than three. The GRU's single update gate covers keep-vs-write together; on many tasks it loses nothing. Simpler isn't weaker here — it's often just as good and cheaper.
  • Getting the update gate backwards. \(z\approx1\) means keep the old memory (because the old term is weighted by \(z\)). It's easy to assume "gate open = write new"; here open means carry.
  • Ignoring the reset gate's separate role. The reset gate \(r\) doesn't decide keep-vs-write; it decides how much of the past feeds into the candidate. Small \(r\) lets a fresh candidate depend mostly on the new input.
  • Assuming there's always a "best" cell. LSTM vs GRU has no universal winner — it depends on the data and budget. The professional move is to try both, not to argue about it.

🔑 Key results to remember

  • The GRU has two gates (update \(z\), reset \(r\)) and one state — a streamlined LSTM.
  • Update gate cross-fades: \(h_t=(1-z)\,n + z\,h_{t-1}\). \(z\approx1\) carries memory forward (the gradient highway).
  • Reset gate \(r\) controls how much past enters the candidate \(n\).
  • ~25% fewer parameters than an LSTM; often comparable accuracy, faster to train.
  • LSTM vs GRU is task-dependent and usually close — try both; the GRU is a fine default.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. How does a GRU differ structurally from an LSTM?

  • It adds a third state.
    The GRU removes the separate cell state and uses fewer gates.
  • It merges the two states into one and uses two gates instead of three.
    Correct. That consolidation is what makes the GRU smaller than an LSTM.
  • It removes all gating.
    Gating is the whole point; the GRU keeps two gates.
  • It replaces tanh with ReLU everywhere.
    The GRU still uses sigmoid gates and a tanh candidate.

Q2. In \(h_t=(1-z)\,n + z\,h_{t-1}\), what does \(z\approx1\) do?

  • Replaces the state with the candidate.
    That's \(z\approx0\); with \(z\approx1\) the candidate is weighted by \((1-z)\approx0\).
  • Erases the memory.
    It preserves the memory, not erases it.
  • Carries \(h_{t-1}\) forward almost unchanged.
    Correct. \(z\approx1\) weights the old state fully and the candidate near zero — memory persists and gradients flow.
  • Doubles the learning rate.
    Gates don't touch the optimizer's learning rate.

Q3. What does the reset gate \(r\) do?

  • It reveals the state as output.
    The GRU has no separate output gate; \(h_t\) is the state directly.
  • It sets the learning rate.
    Gates don't touch hyperparameters.
  • It decides keep-versus-write.
    That's the update gate's job; the reset gate does something narrower.
  • It controls how much of the old memory enters the candidate \(n\).
    Correct. \(n=\tanh(W_n[x, r\odot h])\): a small \(r\) lets the candidate lean on the new input and ignore the past.

Q4. When might you prefer a GRU over an LSTM in practice?

  • When you want fewer parameters and faster training with usually comparable accuracy.
    Correct. The GRU's smaller size is its main practical draw; on many tasks accuracy is close, so it's a sensible default — but benchmark both.
  • When you need guaranteed higher accuracy.
    Neither is universally more accurate; it's task-dependent.
  • When the sequence has no order.
    If order doesn't matter you wouldn't use a recurrent model at all.
  • When you want to avoid gates.
    The GRU is a gated cell; avoiding gates means a plain RNN.

✍️ Practice

1. (warm-up) In the interactive, find the update-gate value where the memory roughly halves each step. Confirm it against the formula.

Show solution

It's \(z=0.5\): with an incoming candidate of 0, \(h_t = 0.5\,h_{t-1}\), so the memory halves every step (\(0.5^{16}\) after 16 steps — essentially gone). At \(z=1\) it never fades; at \(z=0\) it's replaced immediately. The update gate is a single continuous "memory half-life" dial, and the GRU learns where to set it for each unit.

2. (transfer) Run gru.py and note its parameter count; compare to an LSTM of the same width. What's the ratio, and where does it come from?

Show solution

The GRU has three weight matrices (\(W_r, W_z, W_n\)) versus the LSTM's four (\(W_f, W_i, W_g, W_o\)), so about 3/4 the recurrent parameters — a 25% reduction, purely from having one fewer gate. Fewer parameters means less memory, faster steps, and sometimes better generalization on small data — the reasons the GRU is often chosen when resources are tight.

3. (stretch) LSTMs and GRUs ruled sequence modeling for years, then Transformers replaced them for large language tasks. What limitation of all recurrent models did attention overcome?

Show solution

Recurrence is inherently sequential: step \(t\) needs step \(t-1\), so you can't process a sequence in parallel — training is slow, and connecting two far-apart items still means passing through all the steps between them. Attention (Track 5) lets every position look at every other directly and all at once, so the path between any two items is constant and the whole sequence runs in parallel on modern hardware. Gated cells solved vanishing gradients; Transformers solved the sequential bottleneck — which is why they took over at scale, even as LSTMs/GRUs remain great for smaller or streaming tasks.

🚀 In the real world & at the frontier

The GRU is a favourite whenever efficiency matters: mobile and embedded speech, real-time time-series, and as a lightweight building block inside bigger systems. Its design philosophy — question every component, keep only what earns its place — is exactly how research progresses, and it echoes forward: today's state-space models (Track 24) are, in a sense, the next round of "what's the simplest recurrent rule that still remembers well and runs fast?" The GRU is a reminder that a smaller, well-chosen model often beats a bigger, fancier one — a lesson worth carrying into every architecture decision you'll make.

Recap — say it to a friend

"A GRU is a slimmed-down LSTM: one 'cross-fade' update gate blends old memory with new (keeping the gradient highway when it's near 1), plus a reset gate — two gates and one state instead of three and two, often just as good."
