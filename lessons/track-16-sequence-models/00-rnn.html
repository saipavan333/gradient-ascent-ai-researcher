Recurrent networks: giving a model a memory

An MLP takes a fixed-size vector; a CNN takes a fixed-size grid. But language, audio, and sensor readings arrive as sequences of varying length, where order is everything. The recurrent network's answer: read one item at a time and carry a memory forward.

Here's a problem the networks so far can't handle. How do you feed both a 5-word sentence and a 50-word sentence to the same model? You can't just flatten them into one fixed list of numbers — you'd lose the order, and the two are different lengths anyway. A recurrent neural network (RNN) solves this by reading the sequence one item at a time and keeping a running summary of everything it has seen so far. That running summary is called the hidden state, and it is the network's memory. The same small set of weights is reused at every step — just as a CNN reused one kernel across space, an RNN reuses one "cell" across time.

💡 Intuition: reading a book one word at a time

Think about how you read a sentence. You don't see all the words at once; you read them in order, and as you go you keep a mental summary of the story so far. When you reach the last word, that summary lets you understand the whole thing. An RNN works exactly like this. At each step it takes the next input, combines it with its current summary (the hidden state), and produces an updated summary. Feed it "the cat sat" word by word, and after the last word its hidden state holds a compressed sense of the whole phrase. For a yes/no decision, you just read that final summary and pass it through a simple classifier.

Concretely, at each step \(t\) the cell blends the current input \(x_t\) with the previous summary \(h_{t-1}\) and squashes the result with \(\tanh\) (a smooth S-shaped function that keeps numbers between −1 and 1):

\[ h_t = \tanh\!\left(W_{xh}\, x_t + W_{hh}\, h_{t-1} + b\right) \] (0.1)

Read it in words: "new summary = squash( (weights times new input) + (weights times old summary) + a bias )." The weights \(W_{xh}, W_{hh}, b\) are the same at every step — that's what lets one model handle any length and reuse a pattern it learned at position 3 when the same thing shows up at position 30. Training is the usual gradient descent, applied to the whole unrolled loop; because the gradient flows backward across the time steps, it has a special name: backpropagation-through-time (BPTT). It's ordinary backprop, just run along the sequence.

✍️ Worked example: run a tiny RNN by hand

Let's use a 1-number memory and hand-pick weights so the RNN does something you can follow: hold onto the first input. Say \(W_{xh}=2\), \(W_{hh}=1\), \(b=0\), starting memory \(h_{-1}=0\), and inputs \(x = [1, 0, 0]\).

1
Step 0, read \(x_0=1\): \(h_0 = \tanh(2\cdot1 + 1\cdot0 + 0) = \tanh(2) \approx 0.96\). The memory jumps up — it noticed the first input was a 1.
2
Step 1, read \(x_1=0\): \(h_1 = \tanh(2\cdot0 + 1\cdot0.96) = \tanh(0.96) \approx 0.74\). No new input, but the old memory carries forward (a bit weaker).
3
Step 2, read \(x_2=0\): \(h_2 = \tanh(1\cdot0.74) \approx 0.63\). Still clearly positive.
4
Read the final memory. \(h_2 \approx 0.63 > 0\), so a classifier reading "is it positive?" would correctly say the first bit was a 1. Notice the catch: the memory of that first 1 keeps shrinking each step (0.96 → 0.74 → 0.63). Over 3 steps it's fine. Over 30 steps it would fade to nearly nothing — which is exactly the problem the next lesson is about.

🛠️ From scratch: the whole loop

class VanillaRNN:
    def forward(self, x):
        h = np.zeros(self.H)                       # start with an empty memory
        for t in range(len(x)):                    # read one item at a time
            h = np.tanh(self.Wxh[:,0]*x[t] + self.Whh @ h + self.bh)
        return softmax(self.Why @ h + self.by), h  # read the final memory

# BPTT: unroll the loop, then backprop from the last step to the first,
# adding up each shared weight's gradient over every step it was used.

⚠️ Mistakes everyone makes here

  • Thinking each step has its own weights. It's one small cell reused at every step. That reuse is what lets an RNN handle any length and share what it learns across positions.
  • Confusing the input with the memory. \(x_t\) is the new item you just read; \(h_{t-1}\) is the summary of everything before it. They play different roles in the same equation.
  • Assuming the memory is perfect. As the worked example showed, the memory of an old input fades a little every step. Plain RNNs only reliably remember things from a handful of steps ago.
  • Forgetting "through-time" just means "along the sequence." BPTT isn't a new algorithm — it's ordinary backprop applied to the unrolled loop, so a weight used at every step collects gradient from every step.

🔑 Key results to remember

  • An RNN reads a sequence one item at a time, updating a memory: \(h_t = \tanh(W_{xh}x_t + W_{hh}h_{t-1} + b)\).
  • The hidden state is the memory; reading the final one summarizes the whole sequence for a decision.
  • Weights are shared across time — one cell handles any length and reuses patterns across positions.
  • Training = backpropagation-through-time: unroll and backprop; each shared weight's gradient sums over all steps.
  • Plain RNNs only handle short memories — the signal from far-back inputs fades (next lesson).

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What lets an RNN handle sequences of different lengths?

  • It pads everything to a fixed length first.
    Padding is sometimes used for batching, but it isn't what gives RNNs length-flexibility — the loop is.
  • It has a separate weight set per position.
    That would fix the length and block sharing across positions; RNNs do the opposite.
  • It reuses one cell at every step, looping as long as the input.
    Correct. One shared cell applied repeatedly can consume any number of items, carrying its memory forward.
  • It turns the sequence into an image.
    No image is involved; the model reads the sequence directly.

Q2. In \(h_t = \tanh(W_{xh}x_t + W_{hh}h_{t-1} + b)\), what is \(h_{t-1}\)?

  • The next input.
    \(x_t\) is the current input; \(h_{t-1}\) isn't an input at all.
  • The memory summarizing everything seen up to the previous step.
    Correct. The previous hidden state is the running summary the cell updates with each new item.
  • The final output.
    The output comes from the final state through a separate layer; \(h_{t-1}\) is an in-progress memory.
  • A fixed constant.
    It changes every step as new inputs arrive.

Q3. Why is training an RNN called backpropagation-through-time?

  • Because it trains in real time.
    Nothing to do with wall-clock time; "time" means sequence steps.
  • Because gradients are computed forward.
    Backprop runs backward; "time" is the step axis, not the direction.
  • Because it uses a clock signal.
    There's no clock; the term refers to unrolling the sequence.
  • Because you unroll the sequence and backprop from the last step to the first.
    Correct. The loop becomes a deep chain over time steps, and gradients flow back along it.

Q4. A shared weight is used at all \(T\) steps. How is its gradient computed?

  • Add up the gradient contributions from every step it was used.
    Correct. A weight reused in many places collects gradient from each — just like a convolution kernel across space.
  • Use only the last step's gradient.
    That ignores its effect at earlier steps and gives a wrong gradient.
  • Average and then discard.
    You sum contributions; averaging would rescale the gradient incorrectly.
  • Each step gets its own weight, so no sharing.
    The premise is sharing — there's one weight, not many.

✍️ Practice

1. (warm-up) Run rnn.py with sequence length T=8, then bump it to 15, 25, 35 (add epochs if needed). What happens to accuracy, and what does it foreshadow?

Show solution

Accuracy stays near perfect for short sequences but degrades as T grows — the network increasingly fails to carry the first bit to the end. This previews the vanishing-gradient problem (next lesson): the further apart two events are, the weaker the learning signal connecting them, so a plain RNN can't form long-range associations. It's not a bug in the code — it's a built-in limit of the architecture that LSTMs and GRUs were invented to fix.

2. (transfer) The code clips gradients in step(). Remove the clipping and train with a slightly larger learning rate. What can go wrong?

Show solution

You risk exploding gradients: BPTT multiplies many terms together, and if that product grows, a single update can be huge, sending the loss to "NaN" (not-a-number) or making it swing wildly. Gradient clipping simply caps the size of the update when it gets too big, without changing its direction — a cheap, standard safety net for recurrent models. (The opposite failure — vanishing gradients — clipping can't fix; that needs the gated cells of later lessons.)

3. (stretch) An RNN and a 1-D CNN can both process sequences. What's the essential difference in how each one "sees" the past?

Show solution

A 1-D CNN looks at a fixed-size local window around each position — it can only relate items within that window (which only grows with depth). An RNN, in principle, has an unbounded reach: its memory can carry information from arbitrarily far back, since the state passes forward indefinitely. In practice the RNN's reach is limited by fading memory, and the CNN's by its window — both bounded, in different ways. The Transformer (Track 5) sidesteps both by letting every position look at every other directly, which is a big reason it took over.

🚀 In the real world & at the frontier

For most of the 2010s, RNNs (and their gated versions, coming next) powered speech recognition, machine translation, and text generation — the technology behind early Siri and Google Translate. Transformers have since taken the crown for large-scale language, but the recurrent idea is far from dead: it's ideal for streaming settings where data arrives one piece at a time and you can't wait for the whole sequence (live captioning, sensor monitoring, tiny on-device models). And the frontier has circled back — modern state-space models like Mamba (Track 24) are, at heart, very cleverly designed recurrent networks that rival Transformers while processing sequences in a single efficient sweep. The humble "carry a memory forward" idea keeps proving its worth.

Recap — say it to a friend

"An RNN reads a sequence one item at a time and keeps a running summary — its memory — updating it at each step with the same reused cell, so it can handle text or time series of any length."
