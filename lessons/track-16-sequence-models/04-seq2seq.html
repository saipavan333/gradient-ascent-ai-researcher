Sequence-to-sequence: from one answer to a whole output

Translation, summarization, and speech-to-text turn one sequence into another. The encoder–decoder design does this by squeezing the whole input into a single "context" vector and unrolling it back out — and the weakness of that squeeze is exactly what led to attention and the Transformer.

So far our RNNs read a sequence and produce one answer — a label, a yes/no. But the most valuable sequence tasks produce a whole new sequence: give it an English sentence, get back the French; give it an article, get back a summary. These are sequence-to-sequence (seq2seq) problems. The classic solution has two RNNs. An encoder reads the entire input and boils it down into a single fixed-length summary — the context vector. A decoder then starts from that summary and generates the output one item at a time, feeding each thing it produces back in as the next input.

💡 Intuition: read it all, then retell it from memory

Imagine a translator who must listen to an entire sentence, hold it all in their head, and only then start speaking the translation — no glancing back at the original. The "hold it all in their head" part is the context vector: one fixed-size memory that has to capture everything about the input. The "start speaking" part is the decoder, producing the translation word by word, each word informed by what it already said. This works, and it's a beautiful idea — but you can already feel the strain: cramming a 50-word sentence into one fixed memory is hard, and the longer the input, the more gets lost. That strain is the story of this lesson.

During training we use a shortcut called teacher forcing: instead of feeding the decoder its own (possibly wrong) previous guess, we feed it the correct previous word. This makes training faster and more stable. At test time the decoder has no answer key, so it must feed itself — a small mismatch between training and use that we'll flag as a known gotcha.

✍️ Worked example: reverse [3, 1, 4] step by step

Our from-scratch model learns to reverse a short sequence — a clean stand-in for translation (input sequence in, different sequence out). Let's trace it on \([3, 1, 4]\).

1
Encode. The encoder reads 3, then 1, then 4, updating its memory each time. After the last item, its memory (the context vector) holds a squeezed summary of the whole input.
2
Start decoding. The decoder begins from that context and a "start" signal, and outputs the first item: 4 (the last input, since we're reversing).
3
Feed it back. That 4 becomes the decoder's next input; combined with its memory, it outputs 1. Then 1 feeds back and it outputs 3.
4
Result: \([4, 1, 3]\). It worked — 100% on short sequences in our code. But make the input longer and accuracy drops, because that single context vector has to hold more and more in the same fixed space. Watching your own model degrade with length is the most convincing argument for why attention was needed.

🛠️ From scratch: encode once, decode step by step

context = encoder(src)             # final memory = fixed-length summary
h = context
for k in range(out_len):           # generate one item at a time
    h = decoder_step(prev_token, h)
    p = softmax(Wout @ h)          # a probability for each possible output
    prev_token = argmax(p)         # feed the prediction back in (greedy)

⚠️ Mistakes everyone makes here

  • Thinking the context vector grows with the input. It's a fixed size no matter how long the input is — which is precisely why long inputs overflow it. That's the bottleneck.
  • Confusing the encoder's and decoder's jobs. The encoder only reads and summarizes; the decoder only writes, one item at a time, from that summary. Two RNNs, two roles.
  • Forgetting the train/test mismatch. Teacher forcing feeds the correct previous word during training, but at test time the model feeds itself — so early mistakes can snowball (called "exposure bias").
  • Assuming greedy decoding is optimal. Always taking the single most likely next item can miss a better overall sequence. Beam search (keeping several partial candidates) usually does better.

🔑 Key results to remember

  • Seq2seq maps an input sequence to an output sequence via encoder → context vector → decoder.
  • The decoder generates one item at a time, feeding each output back in as the next input.
  • Teacher forcing: during training, feed the true previous item (faster, more stable).
  • The context bottleneck: squeezing an arbitrarily long input into one fixed vector loses information, especially for long inputs.
  • Attention removed the bottleneck (let the decoder look back at all encoder states); the Transformer then dropped recurrence entirely (Track 5).

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What is the "context vector" in an encoder–decoder model?

  • The output sequence.
    The output is produced by the decoder; the context is the input summary that seeds it.
  • The attention weights.
    Basic seq2seq has no attention; the context is just the encoder's final memory.
  • The encoder's fixed-size summary of the whole input, used to start the decoder.
    Correct. It's a fixed-length vector (usually the encoder's last memory) that carries the input's information into decoding.
  • The vocabulary.
    The vocabulary is the set of possible items, not a per-input summary.

Q2. What does "generate autoregressively" mean for the decoder?

  • Each output item is produced using the items generated before it.
    Correct. The decoder feeds its own prior outputs back in, building the sequence one step at a time.
  • All output items appear at once, independently.
    That's non-autoregressive generation; standard decoders are sequential.
  • The model regresses to the average.
    Unrelated; "auto-regressive" here means conditioning on prior outputs.
  • The encoder runs twice.
    The encoder runs once; autoregression is about the decoder.

Q3. "Teacher forcing" during training means…

  • Freezing the encoder.
    It's about decoder inputs, not freezing weights.
  • Using a larger learning rate.
    Unrelated to learning rate.
  • Training only on the hardest examples.
    That's a different idea; not teacher forcing.
  • Feeding the true previous item (not the model's own guess) as the next decoder input.
    Correct. Using ground-truth history stabilizes and speeds training; at test time the model must use its own outputs, a gap called exposure bias.

Q4. Why does the basic encoder–decoder struggle with long inputs?

  • The decoder runs out of vocabulary.
    Vocabulary size is unrelated to input length.
  • The whole input is squeezed into one fixed-length vector, losing information.
    Correct. A single context vector can't preserve all the detail of a long input — the bottleneck attention was designed to relieve.
  • RNNs can't process long inputs at all.
    They can; the issue is compressing them into one vector (plus fading memory).
  • Softmax fails for long sequences.
    Softmax works regardless of length; the bottleneck is the context vector.

✍️ Practice

1. (warm-up) Run seq2seq.py, then increase the sequence length (e.g. to 6, then 8). What happens to accuracy, and how does that dramatize the bottleneck?

Show solution

Longer sequences are harder: the single context vector must encode more items in the same number of dimensions, so accuracy falls (and training needs more capacity/epochs). This is the bottleneck made tangible — the very experiment that motivated attention, where the decoder, instead of relying on one summary, builds a fresh weighted mix of all the encoder's states at each output step. Watching your own model degrade with length is the most convincing case for why attention was needed.

2. (transfer) Our decoder uses teacher forcing in training but feeds itself at test time. Name the mismatch this creates and one way to reduce it.

Show solution

The mismatch is exposure bias: in training the decoder always sees correct previous items, but at test time it sees its own (sometimes wrong) guesses, and errors can compound. Remedies include scheduled sampling (sometimes feed the model's own prediction during training), training against sequence-level rewards, and better search at inference (beam search instead of greedy). It's a clean example of a gap between how a model is trained and how it's used — exactly the kind of thing honest evaluation (Track 9) exists to catch.

3. (stretch) Connect this lesson to Track 5. What exactly did attention add to the encoder–decoder, and what did the Transformer then remove?

Show solution

Attention added a learned "look-back": instead of one frozen context vector, the decoder computes at each output step a weighted blend of all the encoder's states, focusing on the relevant input positions — removing the bottleneck and giving direct access to any part of the input. The Transformer then took the bold next step: if attention can connect any positions directly, you don't need recurrence at all — replace the RNNs with stacked self-attention, gaining full parallelism and constant-length paths between items. This whole track's arc (RNN → gates → seq2seq → bottleneck) is exactly the historical path that made the Transformer the obvious next move.

🚀 In the real world & at the frontier

Encoder–decoder is still the shape of modern translation and summarization systems — but with attention baked in, and usually with Transformers instead of RNNs (Track 5). The context-bottleneck story is one of the most important in AI history: Bahdanau and colleagues' 2014 fix (attention) directly enabled the 2017 Transformer, which enabled GPT and the entire large-language-model era. So this humble "read it all, then retell it" model is the direct ancestor of the systems writing code and essays today. Understanding its one weakness — and the elegant fix — is understanding the hinge on which modern AI turned.

Recap — say it to a friend

"A seq2seq model uses one RNN to squeeze an input sequence into a single summary vector and a second RNN to unroll a new sequence out of it — and the fact that everything must fit through that one vector is the bottleneck attention was invented to fix."
