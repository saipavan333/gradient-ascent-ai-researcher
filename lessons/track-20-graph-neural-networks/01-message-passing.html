Message passing: how information moves on a graph

One idea sits underneath every graph neural network: each node updates itself by gathering messages from its neighbours. Do it once and a node knows its immediate surroundings; repeat and news travels across the whole graph. This is the beating heart of the track.

Track 14 · Lesson 1 Concept + code + interactive ~18 min Builds on: Lesson 0

Now that a graph is numbers, how does a node learn from where it sits? The answer — the single operation that defines this whole field — is message passing. Each node looks at its neighbours, collects a "message" from each (for now, just their current feature values), and combines those messages into an updated version of itself. That's one round. The magic is in repetition: after one round a node reflects its immediate neighbours; after two rounds it reflects neighbours-of-neighbours; after \(k\) rounds it has pooled information from everything within \(k\) hops. Stacking rounds is how a signal — a label, a feature, a rumour — flows outward across the graph. Remarkably, you don't even need training to see it work: in this lesson, planting one labelled node in each of two communities and just letting messages pass will colour in the entire graph correctly. Message passing is to graphs what convolution is to images: the fundamental, reusable local operation you stack into a deep model.

💡 Intuition: gossip through a social network

Picture a rumour starting with one person. In round one, they tell their friends. In round two, those friends tell their friends. Within a few rounds, the whole connected crowd has heard it — and crucially, it spreads fast within a tight friend group and slowly across the sparse links between groups. Message passing is exactly this gossip, made precise: at each step every node replaces its value with a blend of its neighbours' values (and a bit of its own). Values that start high spread to nearby nodes; the empty gaps between communities slow the spread, so each community ends up agreeing with itself before the message leaks across.

The simplest "combine" is an average. If \(h_i\) is node \(i\)'s value, one round is: replace \(h_i\) with the average of itself and its neighbours. In matrix form that's a single multiply by the normalised adjacency \(\hat{A}\) from Lesson 0:

\[ h_i^{\text{new}} = \frac{1}{\deg(i)+1}\Big(h_i + \sum_{j \in \mathcal{N}(i)} h_j\Big), \qquad \text{all at once: } \; H^{\text{new}} = \hat{A}\,H \] (1.1)

Reading it: \(\mathcal{N}(i)\) (script-N of i) is the set of node \(i\)'s neighbours; the sum gathers their values; dividing by \(\deg(i)+1\) averages them together with the node's own value (the \(+1\) is the self-loop). Doing this for every node at once is just one matrix multiply, \(H^{\text{new}} = \hat{A}H\), where \(H\) stacks all the node values. One multiply by \(\hat{A}\) = one hop of message passing. That's the entire mechanism.

✍️ Worked example: two labels colour a whole graph

This is the demo in message_passing.py: two communities, one labelled seed in each, pure diffusion — no training.

1
Seed. Put \(+1\) on one node in community A and \(-1\) on one node in community B. Every other node starts at 0 — unlabelled.
2
Pass messages. Each round, replace every node with the average of itself and its neighbours: \(H \leftarrow \hat{A}H\). The \(+1\) bleeds into community A's nodes; the \(-1\) bleeds into community B's.
3
Why it separates. Because edges are dense inside a community and sparse between, the \(+1\) floods community A long before it can trickle across the few bridge edges to B. After a handful of rounds, community A's nodes are all positive and B's all negative.
4
Read the answer. Take the sign of each node: positive → community A, negative → community B. In the validated run this matches the true communities 100% of the time — two labels, spread by message passing, classified all 40 nodes. (This is graph-based semi-supervised learning, echoing Track 13.)

🛠️ From scratch: message passing is one multiply

Aself = A + np.eye(N)
Dinv  = np.diag(1.0 / Aself.sum(1))
P = Dinv @ Aself                      # one message-passing step = average of neighbours

h = np.zeros(N)
h[seedA] =  1.0                       # one labelled node per community
h[seedB] = -1.0
for step in range(8):
    h = P @ h                         # spread the signal one more hop each round

pred = (h < 0).astype(int)            # sign of the diffused signal = predicted community

The loop is the whole algorithm, and its core is a single line: h = P @ h. Everything a GNN does is dressed-up versions of this — the next lesson simply inserts a learnable weight and a nonlinearity, turning "average your neighbours" into "learn what to take from your neighbours."

Depth = reach. One layer sees 1 hop, two layers see 2 hops, and so on. This is why GNNs are usually shallow (2–3 layers): a few hops already reach most of a well-connected graph, and going too deep causes over-smoothing — every node averages toward the same value and they all blur together. Reach is a feature, but too much reach erases the distinctions you wanted to learn.

⚠️ Mistakes everyone makes here

  • Thinking one layer is enough to see the whole graph. One round only reaches direct neighbours. To pool information from \(k\) hops away you need \(k\) rounds (layers).
  • Stacking too many layers. The opposite trap: after many rounds every node has averaged with everyone, so all node values converge — "over-smoothing." Distinct nodes become indistinguishable and accuracy drops.
  • Forgetting the self-loop. Without \(+I\), a node's update throws away its own current value and is built purely from neighbours — usually you want it to remember some of itself.
  • Assuming aggregation must be a mean. Sum, max, and attention-weighted averages are all valid aggregators, and they capture different things (a sum knows how many neighbours you have; a mean doesn't).

🔑 Key results to remember

  • Message passing: each node updates itself by aggregating its neighbours' features. Repeat to spread information.
  • One hop = one multiply by \(\hat{A}\): \(H^{\text{new}}=\hat{A}H\). \(k\) layers reach \(k\) hops.
  • Dense-within, sparse-between structure makes signals settle inside a community before leaking out — the basis of graph semi-supervised learning.
  • Depth is reach, but too much depth causes over-smoothing (all nodes blur together) — so GNNs are usually 2–3 layers.
  • Aggregators vary: mean, sum, max, or attention — each captures different neighbourhood information.

🧩 Check your understanding
Answer from memory, then read why.

Q1. What happens in one round of message passing?

  • Every node is connected to every other node.
    The graph's edges don't change; only node features update.
  • Each node updates itself by aggregating its neighbours' features.
    Correct. That local gather-and-combine is the entire operation.
  • The adjacency matrix is retrained.
    The structure \(A\) is fixed; message passing updates features, not edges.
  • Nodes are removed from the graph.
    Nothing is removed; values are updated in place.

Q2. How far can information travel after \(k\) rounds (layers)?

  • Only to direct neighbours, always.
    That's one round; more rounds reach further.
  • Across the entire graph in one round.
    One round only reaches 1 hop, not the whole graph.
  • Up to \(k\) hops away.
    Correct. Each round extends the reach by one hop, so \(k\) layers pool \(k\)-hop neighbourhoods.
  • It never travels.
    Spreading information is the whole point.

Q3. Why do very deep GNNs often perform worse?

  • They run out of memory.
    Memory isn't the conceptual issue here.
  • Graphs can't be deep.
    You can stack layers; the problem is what happens when you do.
  • The adjacency matrix becomes singular.
    Not the issue; \(\hat A\) stays well-defined.
  • Over-smoothing: after many rounds every node averages toward the same value and they blur together.
    Correct. Too much mixing erases the differences between nodes, hurting tasks that need those differences.

Q4. In the two-community demo, why does the signal separate the communities so cleanly?

  • Dense links inside a community spread the signal fast, while sparse links between them slow the leak.
    Correct. The structure itself confines each seed's signal to its own community for several rounds.
  • Because the model was trained on labels.
    No training happens — it's pure diffusion.
  • Because there are exactly two nodes.
    There are many nodes; two are merely seeded.
  • Because the graph is directed.
    The demo graph is undirected; direction isn't the reason.

✍️ Practice

1. (warm-up) In the interactive, inject a signal into one node and press Step repeatedly. Count how many steps it takes to reach a node three hops away, and keep going — what eventually happens to all the values?

Show solution

It takes three steps for any signal to first reach a node three hops away (one hop per round) — a direct demonstration that depth equals reach. Keep stepping and every node's value drifts toward the same middling number: the signal spreads everywhere and averages out. That's over-smoothing in miniature — beyond a few rounds, message passing stops sharpening distinctions and starts erasing them, which is exactly why practical GNNs are shallow.

2. (transfer) Message passing with a mean aggregator can't tell a node with 2 neighbours from one with 20 (both average to a similar value). Give a task where that matters, and a fix.

Show solution

Any task where degree itself is the signal — e.g., spotting a fraud hub that suddenly connects to hundreds of accounts, or distinguishing a popular molecule atom from a rare one. A mean normalises degree away, so it can't see "how many." Fixes: use a sum aggregator (which grows with degree), append the degree as an explicit node feature, or use an aggregator that's provably able to count (the GIN architecture was designed exactly to be as discriminative as possible). The general lesson: choose the aggregator to match what your task needs to distinguish.

3. (stretch) The demo classifies nodes with no training, just diffusion. What does the trainable GCN in the next lesson add, and why is it worth the extra machinery?

Show solution

Pure diffusion can only spread the raw label/feature values as-is; it has no way to transform features or learn which combinations matter. The GCN inserts a learnable weight matrix \(W\) and a nonlinearity at each hop: \(H'=\sigma(\hat A H W)\). That lets it reshape features (e.g., combine "age" and "purchase history" into a useful signal), learn task-specific representations, and handle rich node features — not just propagate a single number. Diffusion is the skeleton; \(W\) and \(\sigma\) add the muscle that turns message passing into a trainable model that can fit complicated node- and graph-level targets.

🚀 In the real world & at the frontier

Message passing is the abstraction that unified the field: nearly every GNN — GCN, GraphSAGE, GAT, GIN — is a choice of "what message to send" and "how to aggregate." It powers Google Maps' arrival-time predictions (roads as a graph), AlphaFold's reasoning over protein residues, and recommendation at planetary scale. The frontier pushes on its known limits: over-smoothing (why deep GNNs struggle), over-squashing (too much information crammed through a bottleneck edge), and expressive power (what structures message passing provably cannot tell apart). Some of the newest work replaces fixed neighbour-hops with graph transformers — attention over the whole graph — which is a natural next step once you've met attention on graphs in Lesson 3.

Recap — say it to a friend

"Message passing is the one move behind every GNN: each node updates itself by averaging in its neighbours, which is just multiplying by \(\hat A\). Repeat it and information flows outward — \(k\) layers reach \(k\) hops. Plant one label per community and pure diffusion colours the whole graph. Add a learnable weight to 'average your neighbours' and you've got a GCN."
