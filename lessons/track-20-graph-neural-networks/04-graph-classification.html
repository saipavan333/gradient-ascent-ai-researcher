Graph-level tasks: labelling a whole graph

So far we labelled individual nodes. But the biggest wins — is this molecule a drug? is this transaction ring a fraud? — need a label for the entire graph. The trick is to pool many node embeddings into one graph vector, and it's how GNNs are quietly reshaping chemistry, medicine, and search.

Track 14 · Lesson 4 Concept + code + interactive ~18 min Builds on: Lesson 3

Node classification (Lessons 2–3) answers "what is this node?" But many of the most valuable graph problems ask about the whole graph: Is this molecule toxic or therapeutic? Does this circuit of bank transfers form a money-laundering ring? Is this protein likely to bind that target? Each input is an entire graph, and the output is a single label. The challenge: a GNN produces one embedding per node, but graphs have different numbers of nodes, so you can't just concatenate them into a fixed vector. The solution is a readout (also called graph pooling): after message passing gives every node an embedding, combine all of them — usually by averaging or summing — into one fixed-length vector that represents the whole graph, then classify that. Because a mean or a sum ignores node order and works for any node count, the readout gives you the permutation-invariance and size-flexibility that Lesson 0 said a graph model must have. This lesson builds a graph classifier and then steps back to see where GNNs are changing the world.

💡 Intuition: from many opinions to one verdict

Think of each node embedding as one juror's opinion after they've heard the evidence (message passing let each node gather context from its neighbourhood). To reach a single verdict for the whole graph, you have to combine the jurors somehow. Averaging their opinions is the mean readout; tallying a total is the sum readout; taking the strongest single opinion is the max readout. Any of these turns a variable-size jury into one fixed verdict vector — which a normal classifier can then label. Crucially, the combination must not depend on the order you happened to list the jurors (the graph has no node order), which is exactly why order-blind operations like mean and sum are used.

The full pipeline is short: message-pass to get node embeddings, pool them into a graph vector, classify.

\[ H = \text{GNN}(A, X) \;\;\rightarrow\;\; h_G = \text{pool}\big(\{h_i\}\big) = \frac{1}{N}\sum_i h_i \;\;\rightarrow\;\; \hat{y} = \text{classifier}(h_G) \] (4.1)

Left to right: run a GNN over the graph to get a per-node embedding matrix \(H\); pool those node vectors \(\{h_i\}\) into one graph vector \(h_G\) (here a mean over all \(N\) nodes); feed \(h_G\) to an ordinary classifier for the graph's label \(\hat y\). The pooling step is the only new idea, and it's deliberately simple — its job is just to erase node identity and count while keeping the graph's overall character.

The trap to avoid. We match average degree (~7.3) between the two graph types, so simply counting edges is useless. The model must use real structure.
2
Readout features. For each graph, compute a few order-invariant structural numbers: average degree, the clustering coefficient (do your neighbours know each other?), triangle density, and the spectral gap (how easily the graph splits in two).
3
They separate. Community graphs have high clustering (0.46 vs 0.25 for random) and a small spectral gap (0.06 vs 0.39 — they split easily into their two communities). Degree is identical, so those structural features carry all the signal.
4
Classify. Feed the readout vector to a logistic-regression classifier → 100% accuracy. The pipeline "structural readout → classifier" told the two graph families apart perfectly, using shape, not size.

🛠️ From scratch: readout + classify

def readout(A):
    """summarise a whole graph as one fixed-length vector (order- and size-invariant)."""
    deg = A.sum(1); triangles = np.trace(A @ A @ A) / 6
    return np.array([deg.mean(), deg.std(),
                     clustering_coef(A), triangles / len(A), spectral_gap(A)])

X = np.array([readout(g) for g in graphs])     # one vector per graph, any size -> same length
# ...then any classifier (here logistic regression) labels the graph vectors
acc = train_logreg(X, y)                        # 100% telling community from random graphs

The readout is the whole story: it converts graphs of any size into vectors of the same length, using only quantities that don't depend on how the nodes are numbered. In a full GNN pipeline these hand-picked features are replaced by learned node embeddings that are then pooled — but the shape is identical: turn the graph into one vector, then classify.

Sum vs mean — a subtle choice. Mean pooling captures the "average character" of a graph but is blind to size (a 10-node and a 100-node version of the same motif pool to the same vector). Sum pooling grows with size, so it can tell them apart — and it turns out sum is provably more expressive for distinguishing graph structures (the insight behind the GIN architecture). The pooling operation isn't a throwaway detail: it sets a ceiling on what graph-level distinctions your model can ever make.

⚠️ Mistakes everyone makes here

  • Using an order-dependent readout. Concatenating node embeddings in "node order" breaks permutation-invariance — relabel the nodes and the graph vector changes. Pool with order-blind operations (mean, sum, max) instead.
  • Assuming mean pooling is always fine. Mean discards size information; for tasks where the number of a motif matters (how many reactive groups?), use sum, or you'll lose the signal.
  • Letting the model cheat on a spurious feature. If your two graph classes differ in size, the model may just count nodes and ignore structure. Match the nuisance variables (as we matched degree) to force it to learn what you actually care about.
  • Forgetting graphs vary in size. Any pipeline that assumes a fixed node count will break on the next graph. Readout exists precisely to absorb variable size.

🔑 Key results to remember

  • Graph-level tasks label a whole graph (molecule, transaction ring) — one label per graph, not per node.
  • Readout / pooling combines all node embeddings into one fixed graph vector: \(h_G=\text{pool}(\{h_i\})\).
  • Use order-blind pooling (mean, sum, max) for permutation-invariance and any-size support.
  • Sum is more expressive than mean (it senses size/count); the pooling choice caps what the model can distinguish.
  • Pipeline: GNN → pool → classifier. Structural readouts told community vs random graphs apart at 100%.

Answer from memory, then read why.

Q1. What is a "readout" (graph pooling) for?

  • To add more edges to the graph.
    It doesn't change the graph; it summarises node embeddings.
  • To combine all node embeddings into one fixed-length graph vector.
    Correct. That vector represents the whole graph so a classifier can label it.
  • To label each node.
    That's node classification; readout is for graph-level labels.
  • To normalise the adjacency matrix.
    That's \(\hat A\); readout pools node features.

Q2. Why must the readout use order-blind operations like mean or sum?

  • Because they're faster.
    Speed isn't the reason; correctness is.
  • Because graphs have no edges.
    Graphs do have edges; that's unrelated.
  • To increase the number of nodes.
    Pooling reduces to one vector; it doesn't add nodes.
  • So relabelling the nodes doesn't change the graph vector (permutation-invariance).
    Correct. A graph has no canonical node order, so the summary must ignore order.

Q3. What can sum pooling capture that mean pooling cannot?

  • The size of the graph / how many of something it contains.
    Correct. A sum grows with node count, so it senses size and multiplicity; a mean normalises that away.
  • The colour of the nodes.
    Nodes don't have colours; that's not the distinction.
  • The exact node order.
    Neither should encode order — that would break invariance.
  • Nothing — they're identical.
    They differ precisely on size sensitivity.

Q4. In the worked example, why is the average degree matched between the two graph classes?

  • To make the graphs bigger.
    Matching degree is about fairness, not size.
  • To speed up training.
    It's about what the model learns, not speed.
  • So the model can't cheat by counting edges and must use real structure.
    Correct. With degree matched, only structural features (clustering, spectral gap) separate the classes.
  • Because degree can't be computed.
    Degree is trivial to compute; it's deliberately neutralised.

✍️ Practice

1. (warm-up) In the interactive, generate ~15 graphs and watch the running accuracy. The layout looks random for both types — so what is the classifier actually keying on?

Show solution

The clustering coefficient: in a community-structured graph your neighbours tend to be each other's neighbours too (tight triangles), so clustering is high; in a random graph connections are scattered, so clustering is low. The classifier ignores the visual layout entirely and reads this one structural number off the adjacency matrix. It's a concrete demonstration that graph classification is about structure, which a readout can capture even when the picture looks like noise to a human.

2. (transfer) A molecule is a graph (atoms = nodes, bonds = edges). Sketch how you'd predict whether a molecule is water-soluble using everything in this track.

Show solution

Represent each atom as a node with features (element, charge, number of bonds) and each bond as an edge (possibly with bond-type features). Run a few GNN layers (GCN or GAT) so each atom's embedding reflects its local chemical environment — message passing spreads information about neighbouring atoms and groups. Then readout (sum or mean pool) all atom embeddings into one molecule vector, and feed that to a classifier/regressor for solubility. Train on molecules with known solubility. This is exactly how real molecular-property models work (e.g., for drug discovery), and it's why "learn on graphs" matters: chemistry is natively a graph problem, and a GNN respects that structure where a flat feature vector would throw it away.

3. (stretch) Mean pooling can't distinguish two graphs that differ only in size (e.g., a 6-ring vs a 12-ring of the same repeating unit). Why might that matter, and how does the choice of pooling relate to a GNN's fundamental expressive power?

Show solution

It matters whenever size or count carries meaning — molecule size affects properties, a bigger fraud ring is more suspicious, a longer cycle behaves differently. Mean pooling collapses those to the same vector, so the model is provably unable to tell them apart no matter how it's trained. This connects to a deep result: a GNN's ability to distinguish graphs is bounded by the Weisfeiler–Lehman graph-isomorphism test, and using an injective (information-preserving) aggregator and a sum readout — as the GIN architecture does — reaches that bound, whereas mean/max fall short. The takeaway: pooling and aggregation choices aren't cosmetic; they set a hard ceiling on which graphs your model can ever distinguish. Matching that ceiling to your task is a real design decision.

🚀 In the real world & at the frontier

Graph-level GNNs are where the headline applications live. In chemistry and drug discovery, models predict molecular properties and screen billions of candidate compounds — a GNN even discovered a novel antibiotic (halicin) by flagging molecules with the right structural signature. DeepMind's GNoME used graph networks to predict millions of new stable materials. Weather forecasting (GraphCast), traffic prediction (Google Maps), recommendation, and fraud detection all run graph-level or node-level GNNs at scale. You now have the whole arc: represent data as a graph, pass messages, learn with GCNs and attention, and pool for graph-level answers. That is the complete toolkit that lets neural networks reason over the relational structure of the world — arguably the most general data shape there is.

Recap — say it to a friend

"To label a whole graph, run a GNN to embed every node, then pool those embeddings into one graph vector — with an order-blind operation like mean or sum so node numbering doesn't matter — and classify that vector. Sum pooling senses size; mean doesn't. It's how GNNs predict molecule properties, catch fraud rings, and forecast weather: turn the graph into a vector, then decide."
