Graphs: data that comes as a web of connections

An image is a grid, a sentence is a line, but a social network, a molecule, a road map, and the web are none of those — they are graphs: things joined by relationships. To learn on them, we first need to write a graph down as numbers a model can chew on.

Track 14 · Lesson 0 Concept + code + interactive ~17 min Builds on: Track 6

Every model so far assumed a tidy, fixed shape for its input: a CNN wants a grid of pixels, an RNN wants a line of tokens. But a huge amount of the world's most valuable data has no such shape. A graph is a set of nodes (also called vertices — the "things") joined by edges (the "relationships between things"). Your friends and who-knows-whom is a graph; a molecule's atoms and their bonds is a graph; web pages and their links, the power grid, a citation network, a recommendation system of users and products — all graphs. What makes them special is that there is no natural order to the nodes and each node can have a different number of neighbours, so you can't just flatten them into a fixed list. This track builds neural networks that operate directly on graphs. Step one, this lesson: how do you turn a web of connections into numbers? The answer is the adjacency matrix, and everything else follows from it.

💡 Intuition: a table of who-connects-to-whom

Suppose five people are at a party and you want to record who is talking to whom. You could draw dots for people and lines for conversations — that's the graph. But to store it in a computer, make a grid with one row and one column per person, and put a 1 in cell (row i, column j) whenever person i and person j are talking, 0 otherwise. That grid is the adjacency matrix. It holds the entire structure of the graph as a block of numbers — and numbers are exactly what a neural network eats.

Two quantities fall right out of it. A node's degree is just how many neighbours it has — add up its row. And the whole matrix is symmetric for an undirected graph (if you talk to me, I talk to you), so cell (i, j) equals cell (j, i). Read those two facts off the grid and you already know a lot about the graph's shape.

Formally, for a graph with \(N\) nodes the adjacency matrix \(A\) is \(N\times N\) with

\[ A_{ij} = \begin{cases} 1 & \text{if there is an edge between node } i \text{ and node } j \\ 0 & \text{otherwise} \end{cases}, \qquad \deg(i) = \sum_{j} A_{ij} \] (0.1)

The degree of node \(i\), written \(\deg(i)\), is the sum of its row — the count of its 1s, i.e. its number of neighbours. One more object matters for what's coming: GNNs don't use \(A\) raw; they use a normalised adjacency \(\hat{A} = D^{-1/2}(A+I)D^{-1/2}\). Unpack it gently: \(A+I\) adds a 1 on the diagonal (a "self-loop," so a node also listens to itself); \(D\) is the diagonal matrix of degrees; and dividing by \(\sqrt{\deg}\) on both sides stops high-degree nodes from shouting over everyone. You'll use \(\hat{A}\) in every later lesson — for now just know it's the "politeness-adjusted" version of the connection table.

✍️ Worked example: reading a graph off its matrix

You're handed this 4×4 adjacency matrix and asked to describe the graph without drawing it. Rows/columns are nodes 0–3.

1
The matrix. Row 0: 0 1 1 0. Row 1: 1 0 1 0. Row 2: 1 1 0 1. Row 3: 0 0 1 0. First check: it's symmetric (cell i,j = cell j,i), so the graph is undirected.
2
Edges. Read the 1s above the diagonal: (0,1), (0,2), (1,2), (2,3). Four edges.
3
Degrees. Sum each row: node 0 → 2, node 1 → 2, node 2 → 3, node 3 → 1. Node 2 is the hub (connected to everyone); node 3 is a leaf (one connection).
4
Shape. Nodes 0, 1, 2 form a triangle (all pairwise connected), with node 3 hanging off node 2. You reconstructed the entire graph from 16 numbers — that's why the adjacency matrix is the representation.

🛠️ From scratch: a graph and its matrices

def normalised_adjacency(A):
    A = A + np.eye(len(A))          # add self-loops: a node also sees itself
    d = A.sum(1)                    # degree of each node (row sum)
    Dinv = np.diag(1.0 / np.sqrt(d))
    return Dinv @ A @ Dinv          # Â = D^-1/2 (A+I) D^-1/2  — degree-balanced

The stochastic_block_model builds a graph with two communities — many edges inside each, few between — which is the running example for this whole track (think two friend groups with one mutual acquaintance). Notice how little code it takes: a graph is its adjacency matrix, and the degree and normalised versions are one line each.

Why not just flatten it? You might think: turn the matrix into one long vector and feed it to an MLP. Two problems. First, if you relabel the nodes (swap "node 1" and "node 2"), the matrix scrambles but the graph is identical — an MLP would see a totally different input for the same graph. Second, graphs come in different sizes, but an MLP needs a fixed input length. A good graph model must be permutation-invariant (immune to relabelling) and size-agnostic. That's exactly what message passing (next lesson) delivers.

⚠️ Mistakes everyone makes here

  • Forgetting the graph has no node order. The labels 0,1,2… are arbitrary. Any method that gives a different answer when you renumber the nodes is broken — real graph models must be permutation-invariant.
  • Treating the adjacency matrix like an image. It looks like a grid, but a CNN's spatial assumptions (nearby pixels relate) don't hold — row 5 and row 6 are just two arbitrarily-numbered nodes, not neighbours.
  • Skipping the self-loop. Without adding \(I\), a node's update ignores its own current features and only listens to neighbours — usually you want it to keep some of itself, which is what \(A+I\) provides.
  • Ignoring degree normalisation. Raw \(A\) lets a node with 100 neighbours dominate; \(\hat{A}\)'s \(D^{-1/2}\) scaling keeps high- and low-degree nodes on comparable footing.

🔑 Key results to remember

  • A graph = nodes + edges, stored as an \(N\times N\) adjacency matrix \(A\) (\(A_{ij}=1\) if \(i\)–\(j\) linked).
  • Degree of a node = its row-sum = its number of neighbours.
  • Undirected graph ⇒ symmetric \(A\) (\(A_{ij}=A_{ji}\)).
  • GNNs use the normalised \(\hat{A}=D^{-1/2}(A+I)D^{-1/2}\): self-loops plus degree balancing.
  • Graph models must be permutation-invariant and handle any size — you can't just flatten and use an MLP.

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What does entry \(A_{ij}=1\) mean in an adjacency matrix?

  • Node \(i\) has degree \(j\).
    Degree is a row-sum, not a single entry.
  • There is an edge between node \(i\) and node \(j\).
    Correct. The matrix records the graph's connections, one cell per possible pair.
  • Node \(i\) equals node \(j\).
    Nodes being connected doesn't make them equal.
  • The graph is directed.
    Direction is about symmetry of the whole matrix, not a single 1.

Q2. How do you get a node's degree from the matrix?

  • Read the diagonal entry.
    The diagonal is 0 for a simple graph (no self-loops) — degree isn't there.
  • Take the largest entry in its row.
    Entries are 0/1; the max is just 1 if it has any neighbour.
  • Sum its row.
    Correct. Each 1 is one neighbour, so the row-sum is the neighbour count.
  • Multiply the row by the column.
    That's not how degree is defined.

Q3. Why can't you just flatten a graph's adjacency matrix and feed it to an MLP?

  • Matrices are too large.
    Size is a factor but not the core issue.
  • MLPs can't do multiplication.
    MLPs multiply constantly; that's not the problem.
  • Graphs are always directed.
    Many graphs are undirected; direction isn't the issue.
  • Relabelling nodes scrambles the matrix though the graph is unchanged, and graphs vary in size — an MLP isn't permutation-invariant or size-agnostic.
    Correct. A good graph model must give the same answer regardless of node numbering and work at any size.

Q4. What does adding \(I\) (the identity) to \(A\) accomplish in \(\hat{A}\)?

  • It adds self-loops so each node also includes its own features when updating.
    Correct. \(A+I\) puts a 1 on the diagonal, so a node listens to itself as well as its neighbours.
  • It makes the matrix invertible for training.
    That's not the purpose; self-loops are about including the node itself.
  • It deletes the edges.
    It adds to the diagonal; existing edges stay.
  • It doubles every degree.
    It adds exactly one (the self-loop) to each node's connections, not a doubling.

✍️ Practice

1. (warm-up) In the interactive, build two triangles joined by a single edge. Look at the matrix: where do the "inside a cluster" 1s sit versus the one "between clusters" 1? What structure does that block pattern reveal?

Show solution

The 1s clump into two dense blocks along the diagonal (each triangle's nodes connect to each other) with a single lonely 1 in the off-diagonal region (the bridge edge). That block-diagonal pattern is the fingerprint of community structure: dense within groups, sparse between. Spotting it in the matrix is exactly what community-detection and the GCN in Lesson 2 exploit — and it's why we generate graphs with a "stochastic block model."

2. (transfer) The entry \((A^2)_{ij}\) counts something meaningful. Compute \(A^2\) for a small graph and figure out what each entry counts.

Show solution

\((A^2)_{ij}=\sum_k A_{ik}A_{kj}\) counts the number of length-2 paths from \(i\) to \(j\) — i.e., how many common neighbours they share (for \(i\neq j\)), and the diagonal \((A^2)_{ii}\) equals node \(i\)'s degree (paths that go out and back). This is the seed of message passing: multiplying by \(A\) once spreads information one hop, twice spreads it two hops. A \(k\)-layer GNN effectively lets each node see \(k\) hops out, which is why depth controls "reach" on a graph.

3. (stretch) A directed graph (e.g., "who follows whom" on social media) has an asymmetric \(A\). Name one thing that changes about degree, and one modelling consequence.

Show solution

Degree splits into two: in-degree (column sum — how many point at you, your followers) and out-degree (row sum — how many you point at, who you follow). Modelling consequence: message passing must respect direction — information should flow along edges the right way (e.g., influence flows from followee to follower), so you use \(A\) and \(A^\top\) for the two directions, or aggregate incoming and outgoing neighbours separately. Directedness also breaks the symmetric normalisation \(\hat A\); directed GNNs use variants. The core idea — aggregate from neighbours — survives; you just track which neighbours are "in" and which are "out."

🚀 In the real world & at the frontier

Graph data runs some of the largest systems on earth: Google's PageRank ranks web pages by the link graph; recommendation engines at Pinterest and Amazon are graph models over billions of user–item edges; drug discovery represents molecules as graphs of atoms and bonds; fraud detection hunts for suspicious patterns in transaction graphs. The reason a whole track exists is that "things and their relationships" is one of the most general shapes data can take — more general than grids or sequences, which are just special, tidy graphs. Master the adjacency matrix here and every later lesson is a short step: message passing, GCNs, and attention all boil down to clever multiplications by \(A\) and \(\hat{A}\).

Recap — say it to a friend

"A graph is things joined by relationships — nodes and edges — and you write it down as an adjacency matrix: a grid with a 1 wherever two nodes connect. A node's degree is its row-sum, undirected graphs give symmetric matrices, and GNNs use a degree-balanced version with self-loops, \(\hat A\). You can't just flatten it into an MLP, because renumbering the nodes shouldn't change the answer — which is why we need graph-specific models."
