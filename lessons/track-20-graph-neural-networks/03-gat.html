Graph Attention Networks: learning which neighbours matter

A GCN treats every neighbour as equally important. But some neighbours are signal and some are noise. A GAT learns a weight for each neighbour — the same attention idea that powers Transformers, now on a graph — so a node can lean on the neighbours that actually help.

Track 14 · Lesson 3 Concept + code + interactive ~20 min Builds on: Lesson 2, Track 9

The GCN has one blunt assumption baked in: when a node aggregates its neighbours, they all get essentially the same weight (a fixed factor set by their degrees). But real neighbourhoods aren't uniform — a paper has one key influence among many incidental citations; a person has a few close friends among many acquaintances; a fraud account has one telling connection amid ordinary ones. Forcing every neighbour to count the same throws away exactly the distinction you often care about. The Graph Attention Network (GAT) fixes this by learning a weight — an attention score — for each neighbour, so the model can pour most of its "listening" into the neighbours that matter and tune out the rest. If you've met attention in Transformers (Track 9), this is the same mechanism, restricted to run only along the graph's edges. This lesson builds a GAT layer from scratch — including its hand-derived, gradient-checked backpropagation — and confirms it learns to attend to the right neighbours.

💡 Intuition: not all neighbours are equally worth hearing

Imagine deciding what to believe about a news event by asking the people around you. A GCN-style approach would average everyone's opinion equally — including the people who have no idea. Attention is what you actually do: you weight opinions by how relevant and trustworthy each person is, effectively ignoring the noise and focusing on the few who know. A GAT gives a node this skill. For each neighbour, it computes a relevance score from the two nodes' features, turns those scores into weights that add up to 1 (a softmax over the neighbours), and aggregates the neighbours using those weights instead of a flat average. The weights are learned end-to-end, so the network discovers, from the task, which kinds of neighbours to trust.

The recipe for node \(i\)'s attention over a neighbour \(j\):

\[ e_{ij} = \text{LeakyReLU}\big(\mathbf{a}^\top[\,W h_i \,\Vert\, W h_j\,]\big), \qquad \alpha_{ij} = \frac{\exp(e_{ij})}{\sum_{k\in\mathcal{N}(i)} \exp(e_{ik})}, \qquad h_i' = \sigma\!\Big(\sum_{j} \alpha_{ij}\, W h_j\Big) \] (3.1)

Piece by piece: \(W h_i\) and \(W h_j\) are the two nodes' features after a shared learnable transform; the \(\Vert\) means "stick them side by side," and \(\mathbf{a}\) (a learnable vector) scores how relevant \(j\) is to \(i\), with a LeakyReLU bend. That raw score \(e_{ij}\) is turned into a proper weight \(\alpha_{ij}\) by a softmax over node \(i\)'s neighbours — so the weights are all positive and sum to 1 (they compete for attention). Finally, node \(i\)'s new features are the attention-weighted sum of its neighbours. Compare with the GCN's \(H'=\sigma(\hat A H W)\): the only change is that the fixed \(\hat A\) weights become learned, data-dependent \(\alpha_{ij}\) weights.

✍️ Worked example: attention as a softmax over neighbours

A node has three neighbours with raw relevance scores \(e = [2.0,\ 0.5,\ -1.0]\). Turn them into attention weights and aggregate.

1
Softmax the scores. \(\exp(2.0)=7.39,\ \exp(0.5)=1.65,\ \exp(-1.0)=0.37\). Sum \(=9.41\).
2
Weights. \(\alpha=[7.39,\,1.65,\,0.37]/9.41=[0.79,\,0.17,\,0.04]\). They're positive and add to 1 — the first neighbour gets most of the attention, the third almost none.
3
Aggregate. The node's new features are \(0.79\,(Wh_1) + 0.17\,(Wh_2) + 0.04\,(Wh_3)\) — dominated by neighbour 1, exactly as a GCN's flat \([0.33,0.33,0.33]\) never could be.
4
Where the scores come from. \(e_{ij}\) is computed from both nodes' features via the learnable \(\mathbf a\) and \(W\), and training adjusts them so relevant neighbours get high scores. In gat.py we hand-derive the backprop for all of this, gradient-check it (analytic vs numeric match to 5 decimals), then train — reaching 100% node accuracy with average attention on same-community edges (0.134) clearly above cross-community (0.090). It learned to look the right way.

🛠️ From scratch: the GAT attention layer

M  = X @ W                          # shared transform of every node's features
e1 = M @ a1;  e2 = M @ a2           # split the attention vector a = [a1; a2]
Zraw = e1 + e2.T                    # additive score for every (i,j) pair
Zl   = leaky_relu(Zraw)
Zm   = np.where(edge_mask, Zl, -1e9) # only real neighbours compete for attention
alpha = softmax_rows(Zm)            # attention weights: each node's row sums to 1
O = alpha @ M                       # aggregate neighbours, weighted by attention
# backprop for W, a1, a2 is derived by hand and gradient-checked (see gat.py)

The masked softmax is the crux: writing scores for all pairs and setting non-edges to \(-\infty\) (which softmax turns into weight 0) lets us express the whole layer as clean matrix operations, so the aggregation \(O=\alpha M\) only ever mixes real neighbours. Because it's all standard matrix ops, the backward pass is derivable by hand — and we check it against numerical gradients so we know it's right, not just hope so.

Multi-head attention, again. Just like Transformers, GATs usually run several attention "heads" in parallel — each learns its own notion of relevance (one head might focus on same-community neighbours, another on high-degree hubs) — and their results are combined. It's the exact multi-head trick from Track 9, transplanted onto the graph. The deep connection: a Transformer is essentially a GAT on a fully-connected graph where every token attends to every other. Graphs and sequences meet in attention.

⚠️ Mistakes everyone makes here

  • Thinking GAT always beats GCN. Attention adds parameters and cost; when neighbours really are roughly equally useful, a GCN's flat weighting is just as good and cheaper. GAT wins when neighbour importance genuinely varies.
  • Forgetting the softmax is per-node. Each node's attention weights sum to 1 over its own neighbours — not globally. A high-degree node still splits one unit of attention among more neighbours.
  • Skipping the mask. Attention must be computed only over actual neighbours. Let a node attend to non-neighbours and you've silently turned the graph into a fully-connected one.
  • Trusting hand-derived gradients without checking. Attention backprop is fiddly (a softmax inside a sum). Always gradient-check: compare your analytic gradient to a finite-difference estimate — they should match to several decimals, as they do in gat.py.

🔑 Key results to remember

  • GAT learns a weight \(\alpha_{ij}\) per neighbour instead of the GCN's fixed degree-based weight.
  • Scores → softmax over a node's neighbours → weighted aggregate (eq 3.1); weights are positive and sum to 1.
  • It's Transformer attention on a graph; multi-head GAT runs several attentions in parallel.
  • Wins when neighbour importance varies; otherwise a GCN is simpler and just as good.
  • Always mask to real edges and gradient-check the attention backprop (analytic vs numeric).

🧩 Check your understanding
Answer from memory, then read why.

Q1. What is the core difference between a GAT and a GCN?

  • A GAT has no neighbours.
    It still aggregates neighbours — just with learned weights.
  • A GAT uses no weights at all.
    It adds attention weights on top of the usual transform.
  • A GAT learns a per-neighbour attention weight; a GCN uses a fixed degree-based weight.
    Correct. Attention makes the neighbour weighting data-dependent instead of fixed.
  • A GAT can't be trained.
    It trains end-to-end like any GNN.

Q2. The attention weights \(\alpha_{ij}\) for a given node \(i\)...

  • are positive and sum to 1 over \(i\)'s neighbours (a softmax).
    Correct. Each node distributes one unit of attention across its own neighbours.
  • can be any real numbers.
    The softmax constrains them to be positive and normalised.
  • sum to 1 across the whole graph.
    Normalisation is per-node, not global.
  • are fixed before training.
    They're computed from features and learned, not fixed.

Q3. When is a GAT most worth its extra cost over a GCN?

  • When the graph has no edges.
    With no edges there's nothing to attend to.
  • When all neighbours are equally useful.
    Then flat GCN weighting is just as good and cheaper.
  • When you want fewer parameters.
    GAT adds parameters; it's not the lighter option.
  • When some neighbours matter much more than others.
    Correct. Learned per-neighbour weights pay off exactly when importance varies.

Q4. Why gradient-check the GAT's backpropagation?

  • To make training faster.
    Gradient checking is about correctness, not speed (it's actually slow).
  • The attention backprop is error-prone, so comparing analytic vs numerical gradients confirms it's correct.
    Correct. A softmax inside a sum is easy to get subtly wrong; the finite-difference check catches mistakes.
  • To remove the need for a loss function.
    You still need a loss; the check verifies its gradient.
  • Because GATs can't use autograd.
    They can; we derive it by hand here for understanding and verify it.

✍️ Practice

1. (warm-up) In the interactive, slide from GCN (0) to GAT (100). Watch the centre node's estimate and the edge thicknesses. What does the fully-trained GAT do that the GCN can't?

Show solution

At 0 (GCN) all six edges are equally thick, so the three noisy neighbours drag the estimate away from the true value. As you slide toward GAT, the edges to the relevant neighbours thicken and the noisy ones thin to nearly nothing, and the estimate snaps to the correct value. The GAT learned to ignore the unhelpful neighbours — something a GCN, forced to weight everyone equally, structurally cannot do. That selective focus is the whole value of attention on graphs.

2. (transfer) A Transformer (Track 9) lets every token attend to every other token. Explain how that is a special case of a GAT.

Show solution

A Transformer is a GAT on a fully-connected graph: treat each token as a node and put an edge between every pair, so each token's attention is a softmax over all other tokens — exactly self-attention. The GAT's edge mask is what generalises it: restrict attention to a sparse graph's real edges and you get a GAT; make the graph complete and you recover the Transformer. This is why graph transformers (attention over all node pairs, plus positional/structural encodings) are a natural bridge between the two worlds, and why understanding one deeply illuminates the other.

3. (stretch) Attention weights are often held up as "explanations" ("the model focused on this neighbour"). Give one reason to be cautious about reading them that way.

Show solution

High attention on a neighbour doesn't guarantee that neighbour caused the prediction. Attention is one component of a deep, nonlinear computation; a neighbour with low attention can still influence the output through later layers, and different attention patterns can yield the same prediction (attention is not unique). Empirically, attention weights often correlate with importance but sometimes diverge from more rigorous attribution methods. So attention is a useful, cheap hint about what the model is using — worth inspecting — but not a faithful causal explanation on its own. This mirrors the broader interpretability caution from Track 23: a plausible-looking explanation is not automatically a correct one.

🚀 In the real world & at the frontier

GAT and its multi-head variants are standard tools wherever neighbour importance varies: molecular property prediction (some bonds matter more), recommendation (some interactions are more telling), and knowledge graphs. The bigger story is the convergence with Transformers: graph transformers now apply full attention over all node pairs with clever structural encodings, blurring the line between "GNN" and "Transformer." The same attention mechanism you first met for language turns out to be a general-purpose tool for reasoning over any set of related things — tokens, nodes, pixels, or objects. Attention is arguably the most important single idea in modern deep learning, and here you've seen it live on graphs.

Recap — say it to a friend

"A GAT is a GCN that learns how much to listen to each neighbour. It scores every neighbour from their features, softmaxes the scores into weights that sum to 1, and aggregates neighbours using those weights — so it can focus on the ones that matter and ignore noise. It's Transformer attention restricted to the graph's edges, and we verify its hand-derived gradients with a numerical check."
