Graph Convolutional Networks: message passing that learns

Take message passing, insert a weight matrix and a nonlinearity, stack two layers — and you have a GCN, the workhorse of graph learning. Train it on a handful of labelled nodes and the graph structure fills in the rest.

Track 14 · Lesson 2 Concept + code + interactive ~21 min Builds on: Lesson 1

Message passing (Lesson 1) spread a signal, but it could only shuffle the numbers it was given — it had no way to learn. The Graph Convolutional Network (GCN) fixes that with one small addition: after mixing each node with its neighbours, multiply by a learnable weight matrix and pass the result through a nonlinearity. That turns "average your neighbours" into "learn a useful transformation of your neighbourhood." Stack two such layers, attach a classifier, and train by ordinary gradient descent — the same backpropagation you've used since Track 4. The payoff is striking: because each layer pulls in information from further out on the graph, a GCN can be trained on just a few labelled nodes and still classify every node correctly, using the graph's structure to carry the labels where they need to go. It's the "hello world" of graph deep learning, and it works.

💡 Intuition: convolution, but on a graph

Recall a CNN (Track 7): it slides a small filter over an image, and each output pixel is a learned combination of a pixel and its grid neighbours. A GCN does the identical thing, except "neighbours" are defined by the graph's edges instead of a square grid. Each GCN layer says: for every node, gather your neighbours (message passing), apply a learned weight to the gathered features (the filter), and squash with a nonlinearity. Where a CNN filter learns "this pixel plus the ones around it, weighted like this, detects an edge," a GCN filter learns "this node plus its neighbours, weighted like this, detects a fraud ring / a molecule's reactive site / a user's taste." Same recipe — local aggregation + learned weights + nonlinearity — generalised from grids to arbitrary graphs.

One layer, written out, is a single line:

\[ H' = \sigma\big(\hat{A}\,H\,W\big) \] (2.1)

Three pieces, each already familiar: \(\hat{A}H\) is message passing — mix every node with its neighbours (Lesson 1). \(W\) is a learnable weight matrix — it transforms the mixed features into new ones, and it's what training adjusts. \(\sigma\) (sigma) is a nonlinearity like ReLU — the same "bend" that lets deep nets model non-straight relationships (Track 4). Do this twice — \(H_1=\sigma(\hat A H_0 W_1)\) then scores \(=\hat A H_1 W_2\) — and a softmax on the scores gives each node's predicted class. That two-layer stack is the entire GCN.

✍️ Worked example: shapes of a 2-layer GCN

Following gcn.py: 50 nodes, featureless (identity features), 2 classes, only 8 labelled nodes.

1
Inputs. \(\hat{A}\) is \(50\times50\) (the graph). \(H_0=X\) is \(50\times50\) (identity — each node its own one-hot, since there are no real features). \(W_1\) is \(50\times16\), \(W_2\) is \(16\times2\).
2
Layer 1. \(H_1=\text{ReLU}(\hat A X W_1)\) has shape \(50\times16\) — every node now holds a 16-number embedding built from itself + its 1-hop neighbours.
3
Layer 2. scores \(=\hat A H_1 W_2\) has shape \(50\times2\) — because \(\hat A\) mixes again, each node's 2 class-scores now depend on its 2-hop neighbourhood. Softmax turns scores into class probabilities.
4
Train & result. Cross-entropy loss on only the 8 labelled nodes, gradient descent through both layers (the gradient flows across the graph via \(\hat A\)). Result: 100% accuracy on all 50 nodes. Eight labels, plus structure, classified the entire graph — semi-supervised learning on a graph.

🛠️ From scratch: a 2-layer GCN

def relu(x): return np.maximum(0, x)
def softmax(z): z -= z.max(1, keepdims=True); e = np.exp(z); return e / e.sum(1, keepdims=True)

Ahat = normalised_adjacency(A)        # neighbour-mixing operator (Lesson 0)
for ep in range(300):
    pre1 = Ahat @ X @ W1;  H1 = relu(pre1)       # layer 1: mix, transform, bend
    scores = Ahat @ H1 @ W2;  P = softmax(scores) # layer 2: mix, transform -> class scores
    G = P.copy(); G[range(N), y] -= 1            # dLoss/dscores = P - onehot
    G[~mask] = 0; G /= mask.sum()                # ONLY labelled nodes drive the loss
    dW2 = (Ahat @ H1).T @ G                       # backprop through both layers...
    dH1 = Ahat @ G @ W2.T
    dW1 = (Ahat @ X).T @ (dH1 * (pre1 > 0))       # ...gradient flows across the graph via Â
    W2 -= 0.5 * dW2;  W1 -= 0.5 * dW1

Two matrix multiplies forward, two back — that's a GCN. The only graph-specific ingredient is \(\hat A\); strip it out (replace with the identity) and you're left with an ordinary MLP that ignores the graph. The mask is what makes it semi-supervised: the loss is computed on the handful of labelled nodes, but because \(\hat A\) couples every node to its neighbours, training those few nodes shapes the embeddings of all of them.

Why so few labels suffice. In a plain MLP, an unlabelled example contributes nothing to training. In a GCN, every unlabelled node is wired to labelled ones through the graph, so it both receives label information (during the forward pass) and shapes the gradient (during the backward pass). The graph acts as a scaffold that carries scarce labels across the whole node set — which is why GCNs are a natural fit for problems where labels are expensive but connections are plentiful (citation networks, social graphs, molecules).

⚠️ Mistakes everyone makes here

  • Confusing the GCN with a CNN. They share the "local aggregate + learned weights" idea, but a CNN's neighbours are fixed grid positions with ordered weights; a GCN's neighbours are graph edges and every neighbour shares the same weight (there's no "top-left vs bottom-right" on a graph).
  • Going too deep. Two or three layers is usually best. More layers over-smooth (Lesson 1) — node embeddings converge and accuracy falls. If you need more reach, other tricks (residuals, jumping knowledge) beat brute depth.
  • Forgetting the loss mask. In semi-supervised node classification you compute loss only on labelled nodes. Include the unlabelled ones (whose "labels" are unknown) and you're training on garbage.
  • Using raw \(A\) instead of \(\hat A\). Without the self-loops and degree normalisation, features blow up or wash out across layers. The \(\hat A\) normalisation is what keeps training stable.

🔑 Key results to remember

  • A GCN layer is \(H'=\sigma(\hat A H W)\): message passing (\(\hat A H\)) + learnable weight (\(W\)) + nonlinearity (\(\sigma\)).
  • It's convolution generalised to graphs: local aggregation with shared learned weights.
  • Stack ~2 layers so each node's output depends on its 2-hop neighbourhood; softmax the final scores for class probabilities.
  • Semi-supervised: loss on a few labelled nodes only, but \(\hat A\) spreads the signal — 8 labels classified all 50 nodes at 100%.
  • Keep it shallow (over-smoothing) and always use \(\hat A\), not raw \(A\) (stability).

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What does a GCN layer add on top of plain message passing?

  • Nothing — they're identical.
    Message passing alone can't learn; the GCN adds trainable parts.
  • A second adjacency matrix.
    It reuses the same \(\hat A\); the additions are elsewhere.
  • A learnable weight matrix \(W\) and a nonlinearity \(\sigma\).
    Correct. \(H'=\sigma(\hat A H W)\) — the \(W\) and \(\sigma\) turn fixed averaging into a trainable transformation.
  • It removes the neighbours.
    Neighbour aggregation (\(\hat A H\)) is retained; it's the core.

Q2. Why can a GCN classify all nodes from just a few labels?

  • \(\hat A\) couples every node to its neighbours, so scarce labels spread across the graph during training.
    Correct. The graph scaffolds the labels to unlabelled nodes — the essence of semi-supervised node classification.
  • Because it memorises the test set.
    No memorisation; it generalises via structure.
  • Because it uses thousands of labels internally.
    It genuinely uses only the few provided labels.
  • Because graphs are always small.
    GCNs scale to millions of nodes; size isn't the reason.

Q3. Roughly how many layers does a typical GCN use, and why?

  • Dozens, to maximise reach.
    Deep GCNs over-smooth; dozens of layers usually hurt.
  • Exactly one, always.
    One layer only sees 1-hop neighbours; that's often too little.
  • Zero — GCNs have no layers.
    A GCN is made of layers; it can't have none.
  • About 2–3, balancing reach against over-smoothing.
    Correct. A couple of hops reach most of a connected graph; more layers blur nodes together.

Q4. In semi-supervised node classification, which nodes contribute to the loss?

  • All nodes.
    Unlabelled nodes have no target, so they can't be in the loss.
  • Only the labelled nodes (via a mask).
    Correct. The loss is masked to labelled nodes; unlabelled ones still influence via message passing, not the loss.
  • Only the unlabelled nodes.
    You can't compute a loss without targets, which only labelled nodes have.
  • A random subset each step.
    The labelled set is fixed, not randomly resampled.

✍️ Practice

1. (warm-up) In the interactive, set the label budget to 1 per community and run the GCN a few times with new seeds. Is accuracy always perfect? What does the occasional dip tell you about which node you label?

Show solution

With just one label per side it's usually very good but not always perfect — occasionally a poorly-placed seed (a node near the boundary or weakly connected) leaves part of its community mislabelled. This mirrors Track 13's lesson: which nodes you label matters, not just how many. A well-connected, central node spreads its label further and gives higher accuracy — which is exactly the kind of insight active learning (Track 13, Lesson 4) formalises. Add a second label and the redundancy almost always fixes it.

2. (transfer) If you replace \(\hat A\) with the identity matrix \(I\) in \(H'=\sigma(\hat A H W)\), what model do you get, and how would it perform on featureless node classification?

Show solution

With \(\hat A = I\) there's no neighbour mixing — each node is transformed independently, so it becomes a plain MLP applied to each node's own features. On featureless node classification (identity features, no per-node signal) it would fail: with nothing but an arbitrary one-hot per node and no way to see the graph, there's no information to separate the classes — it can only memorise the labelled nodes and guesses randomly on the rest. This is the clean demonstration that a GCN's power comes entirely from \(\hat A\): the structure is the signal when features are weak.

3. (stretch) A GCN gives every neighbour the same importance (a fixed degree-based weight). Describe a situation where that's a real limitation, and name what fixes it.

Show solution

When some neighbours are far more relevant than others. Example: in a citation network, one cited paper might be the key influence and ten others incidental; a fraud account's single suspicious contact matters more than its many normal ones. A GCN blends all neighbours with the same (degree-based) weight, so it can't emphasise the important ones or ignore the noise. The fix is attention — letting the model learn a different weight for each neighbour — which is precisely the Graph Attention Network in the next lesson. GCN is the fixed-weight baseline; GAT makes the weights learnable and data-dependent.

🚀 In the real world & at the frontier

The GCN paper (Kipf & Welling, 2017) kicked off the modern GNN era, and the 2-layer GCN remains a strong, standard baseline everywhere: classifying papers in citation networks, users in social graphs, and products in recommendation systems. Industrial variants like GraphSAGE scale the same idea to billions of nodes by sampling neighbours instead of using the full \(\hat A\). The open problems you'll hear about — over-smoothing, over-squashing, limited expressive power, scaling to giant graphs — are all being actively researched, and each has spawned architectures (residual GCNs, graph transformers, and more). But the humble \(H'=\sigma(\hat A H W)\) is the foundation they all build on. Get it, and you understand the core of graph deep learning.

Recap — say it to a friend

"A GCN is message passing with a brain: mix each node with its neighbours (\(\hat A H\)), apply a learned weight (\(W\)), bend with a nonlinearity (\(\sigma\)). Stack two layers and softmax the output to classify nodes. Because \(\hat A\) links every node to its neighbours, you can train on a few labels and classify the whole graph — 8 labels got 100% on 50 nodes. Keep it to 2–3 layers or it over-smooths."
