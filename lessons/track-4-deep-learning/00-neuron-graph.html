The neuron & the computational graph

Everything you've built — vectors, dot products, gradients, loss — now snaps together into the atom of deep learning: the neuron. And the way we'll string neurons into trainable networks is an idea of startling generality: the computational graph.

The word neuron sounds like biology, and that scares people off. It shouldn't. An artificial neuron is one of the simplest ideas in this whole course: take some numbers, multiply each by an importance, add them up, add a baseline, and then gently bend the result. That's it. In this lesson we build that neuron, and then we meet the humble bookkeeping structure — the computational graph — that turns a pile of these neurons into something a computer can train. Get these two ideas and the rest of deep learning is detail.

💡 Intuition: a neuron is a "should I?" decision

Suppose you're deciding should I bike to work today? You weigh a few facts. Nice temperature pushes you toward yes; rain pushes you toward no; how much time you have matters too. Each fact has an importance to you — rain might matter a lot, temperature only a little. You mentally add up "fact × how much it matters" for everything, tack on your own baseline mood (some mornings you just feel like biking), and if the running total is high enough, you go.

That is exactly a neuron. The facts are the inputs. Each importance is a weight. Your baseline mood is the bias. The running total is the weighted sum. And the final "high enough → go, otherwise don't" squeeze is the activation function — it turns a raw score into a smooth decision. Nothing here is more complicated than a weighted average with an on/off dial at the end.

📐 The neuron, one symbol at a time

Let's write it down. A neuron takes an input vector \(\mathbf{x}\) (all the facts for one example, lined up as numbers), pairs each input with a weight from a weight vector \(\mathbf{w}\), sums up every "weight × input" — that sum is exactly the dot product \(\mathbf{w}\cdot\mathbf{x}\) you learned in Track 1 — then adds the bias \(b\) and passes the result through an activation \(f\):

\[ z = \mathbf{w}\cdot\mathbf{x} + b = \sum_i w_i x_i + b, \qquad y = f(z). \] (0.1)

Read every symbol in plain words: \(\mathbf{x}\) is the input (the numbers describing one example); \(\mathbf{w}\) is the weights (how much each input counts — big weight, big influence); \(b\) is the bias (a baseline nudge that shifts the whole decision up or down, independent of any input); \(z\) is the pre-activation or raw score (the weighted sum plus bias); \(f\) is the activation (the bend that keeps outputs in a sane range and, crucially, is nonlinear); and \(y\) is the neuron's output. The symbol \(\sum_i w_i x_i\) just means "add up \(w_i x_i\) over every input \(i\)" — the long-hand of the dot product.

A common first activation is \(\tanh\), which squashes any number into the range \(-1\) to \(+1\): very negative scores flatten to \(-1\), very positive scores flatten to \(+1\), and scores near zero pass through almost unchanged. So the weights and bias decide where on that S-curve you land, and \(\tanh\) reports back a soft decision.

🧩 The computational graph: one big formula, many tiny steps

Now the second idea, which is what makes training possible. Any calculation — even a whole network with millions of operations — can be broken into a chain of tiny steps, where each step does exactly one thing: an add, or a multiply, or a single activation. Draw those steps as boxes (called nodes) connected by arrows that carry numbers, and you have a computational graph. It's the recipe of the calculation, written so each instruction is dead simple.

Here is a tiny one. Take the formula \(d = a\times b + c\). Instead of doing it in one gulp, split it into two nodes: first a multiply node computes \(e = a\times b\), then an add node computes \(d = e + c\). Filling in each node's value from left to right — inputs first, result last — is called the forward pass. With \(a=2,\ b=-3,\ c=10\): the multiply node gives \(e = 2\times(-3) = -6\), and the add node gives \(d = -6 + 10 = 4\).

\[ e = a\times b, \qquad d = e + c. \] (0.2)

Why bother splitting a one-line formula into a graph? Because each little node is so simple that we know its derivative by heart — a multiply, an add, a \(\tanh\). Next lesson we'll walk backward through this exact graph and let those simple derivatives hand us the gradient of the output with respect to every input, automatically. The graph is the scaffolding that makes that possible. A neuron is just a small graph; a network is a big one.

✍️ Worked example: run a neuron, then a graph, by hand

First a three-input neuron. Inputs \(\mathbf{x}=[2,\,0,\,-1]\), weights \(\mathbf{w}=[-3,\,1,\,0.5]\), bias \(b=6\), activation \(\tanh\).

1
Weighted sum (the dot product). Multiply each input by its weight and add: \((-3)(2) + (1)(0) + (0.5)(-1) = -6 + 0 - 0.5 = -6.5\).
2
Add the bias. \(z = -6.5 + 6 = -0.5\). This raw score is slightly negative — the neuron is leaning "no", but only a little.
3
Bend it. \(y = \tanh(-0.5) \approx -0.462\). A soft, mild "no". Change the bias to \(6.5\) and \(z\) would be exactly \(0\), giving \(y=0\) — perfectly on the fence. That's the bias doing its job: sliding the decision.
4
Now the graph for \(d = a\times b + c\) with \(a=2,\ b=-3,\ c=10\). Forward pass, left to right: the multiply node gives \(e = 2\times(-3) = -6\); the add node gives \(d = -6 + 10 = 4\). Every value now sits on its node, ready for the backward pass next lesson. You just executed a computational graph — the same thing PyTorch does billions of times a second.

🛠️ From scratch: a neuron and a tiny graph

Both ideas in a few lines of Python. The neuron is one dot product plus a bias plus an activation; the graph is just naming each intermediate step so it has a home.

neuron_forward.py
import numpy as np

def neuron(x, w, b, activation=np.tanh):
    z = np.dot(w, x) + b          # weighted sum + bias (a dot product, Track 1)
    return activation(z)

x = np.array([2.0, 0.0, -1.0])    # inputs
w = np.array([-3.0, 1.0, 0.5])    # weights
b = 6.0                           # bias
z = np.dot(w, x) + b              # -3*2 + 1*0 + 0.5*-1 + 6 = -0.5
print("z =", z, "  y = tanh(z) =", round(np.tanh(z), 4))   # y ~ -0.4621

# A tiny computational graph, built by hand: e = a*b, then d = e + c
a, b2, c = 2.0, -3.0, 10.0
e = a * b2          # multiply node
d = e + c           # add node
print("e =", e, " d =", d)        # -6, 4

⚠️ Mistakes everyone makes here

  • Thinking a neuron is biologically complicated. It is multiply, add, bend — a weighted average with a squashing dial. The brain analogy is loose inspiration, not the math.
  • Treating the bias as optional. Without \(b\), the decision boundary is forced through the origin. The bias is what lets a neuron say "lean yes even when every input is zero." Drop it and you throw away a whole degree of freedom.
  • Confusing \(z\) with \(y\). \(z\) is the raw pre-activation score (any real number); \(y\) is the output after the activation (here, squashed into \(-1..1\)). They are different numbers with different jobs.
  • Believing the activation is cosmetic. Remove the bend and a stack of neurons collapses into a single straight-line map — no matter how many layers. The nonlinearity is the entire reason deep networks can learn curves (proved in Lesson 3).
  • Skipping the graph because the formula "fits on one line." The point of the graph isn't the forward value — it's that it records every tiny step so gradients can flow back through it. That recording is what training runs on.

🔑 Key results to remember

  • A neuron is \(y = f(\mathbf{w}\cdot\mathbf{x} + b)\): weighted sum of inputs, plus a bias, through an activation.
  • Weights = importance of each input; bias = baseline shift; activation = the nonlinear bend that turns a score into a decision.
  • The weighted sum is a dot product — everything from Track 1 applies directly.
  • A computational graph breaks any calculation into tiny add / multiply / activation nodes; the forward pass fills in values left to right.
  • The graph is the scaffolding for training: because each node's derivative is trivial, gradients can flow backward through it (Lesson 1).

🧩 Quiz

🧩 Check your understanding
Answer from memory, then read why.

Q1. What role does the bias \(b\) play in a neuron?

  • It rescales every input by the same factor.
    No — that's closer to what a shared weight would do. The bias is added, not multiplied, and it doesn't depend on the inputs.
  • It shifts the raw score up or down independently of the inputs, moving the decision threshold.
    Correct. \(b\) is a constant added to the weighted sum, so it slides the whole decision even when all inputs are zero.
  • It is the neuron's output after the activation.
    That's \(y\). The bias is a parameter inside the sum, not the output.
  • It makes the neuron nonlinear.
    No — adding a constant is still linear. The activation \(f\) provides the nonlinearity.

Q2. With \(\mathbf{w}=[2,-1]\), \(\mathbf{x}=[3,1]\), \(b=-1\), what is the pre-activation \(z\)?

  • \(z = 8\).
    Check the signs: \((2)(3)+(-1)(1) = 6-1 = 5\), then \(-1\).
  • \(z = 6\).
    That forgets the bias. \(5 + (-1) = 4\), not 6.
  • \(z = 4\).
    Correct. \((2)(3) + (-1)(1) + (-1) = 6 - 1 - 1 = 4\).
  • \(z = 2\).
    Recompute: the weighted sum is \(6-1=5\), plus the bias \(-1\) gives \(4\).

Q3. In the graph for \(d = a\times b + c\), what does the forward pass do?

  • Computes the gradient of \(d\) with respect to \(a\).
    That's the backward pass (next lesson). Forward only fills in values.
  • Randomly initializes the weights.
    There are no weights here, and initialization is a separate step; forward just evaluates.
  • Nothing useful — it's only for drawing.
    The forward pass produces the actual output; it's the real computation, not decoration.
  • Fills in each node's value from inputs to output: \(e=a\times b\), then \(d=e+c\).
    Correct. Forward = evaluate the graph left to right, storing each intermediate value.

Q4. Why do we bother splitting a formula into a computational graph of tiny nodes?

  • Each tiny node has a trivial known derivative, so gradients can flow back through the whole thing automatically.
    Correct. Simple local pieces + the chain rule = automatic gradients (Lessons 1–2). That's the whole payoff.
  • Small nodes make the forward value more accurate.
    The forward value is identical however you group it; accuracy isn't the reason.
  • Graphs run faster than formulas.
    Not inherently — it's the same arithmetic. The benefit is differentiability, not raw speed.
  • It's required by the tanh function.
    tanh has nothing to do with it; any calculation can be graphed, with or without tanh.

✍️ Practice

Warm-up

1. A neuron has \(\mathbf{w}=[1,\,-2]\), \(b=0.5\), and \(\tanh\) activation. Compute \(z\) and \(y\) for the input \(\mathbf{x}=[1,\,1]\).

Show solution

Weighted sum: \((1)(1) + (-2)(1) = 1 - 2 = -1\). Add the bias: \(z = -1 + 0.5 = -0.5\). Bend it: \(y = \tanh(-0.5) \approx -0.462\). A mild "no" — same arithmetic as the worked example, just with different numbers. You can check it against the interactive by setting w1=1, w2=−2, b=0.5 (the inputs there are 1 and −1, so the number differs, but the mechanics are identical).

Transfer

2. You want a single-input neuron (one weight \(w\), one bias \(b\), \(\tanh\) activation) whose output is exactly \(0\) when the input is \(x = 4\). Give one pair \((w, b)\) that works, and explain why the bias acts like a threshold.

Show solution

We need \(z = w\cdot 4 + b = 0\) because \(\tanh(0)=0\). Any \((w,b)\) with \(b = -4w\) works, e.g. \(w=1,\ b=-4\): then \(z = x - 4\), which is \(0\) at \(x=4\), positive above, negative below. The bias \(-4\) sets the tipping point of the decision: it says "fire once the input exceeds 4." That's why bias is often read as a (negative) threshold — it decides where the input has to reach before the neuron leans yes.

Stretch

3. Replace \(\tanh\) with the identity activation \(f(z)=z\), and feed one neuron's output into a second identity neuron. Show that the two-neuron chain is still just a single linear function of the input — and say what this implies about stacking neurons.

Show solution

First neuron: \(y_1 = w_1 x + b_1\). Second neuron reads \(y_1\): \(y_2 = w_2 y_1 + b_2 = w_2(w_1 x + b_1) + b_2 = (w_2 w_1)\,x + (w_2 b_1 + b_2)\). That has the form \(W x + B\) — a single weight and a single bias. Two linear layers collapse into one; a hundred would too. Implication: without a nonlinear activation between them, extra layers buy you nothing — the whole stack can only draw straight lines. The activation's bend is what breaks this collapse and lets depth actually add power. This is precisely the argument we make rigorous in Lesson 3.

🚀 In the real world & at the frontier

The neuron you just built (1943 as a concept, 1958 as the perceptron) is unchanged at the core of a 2020s frontier model — GPT-scale networks are, quite literally, hundreds of billions of these weighted-sum-then-bend units wired together. What changed is scale and the plumbing around them. And the computational graph is the load-bearing idea of every modern framework: PyTorch, JAX, and TensorFlow all build a graph as your code runs, then differentiate it automatically. When people say a model has "175 billion parameters," they mean 175 billion of the \(w\)'s and \(b\)'s in equation (0.1). Everything else in this track is about filling those numbers with good values.

Recap — say it to a friend

"A neuron just multiplies each input by an importance, adds them up with a baseline, and bends the result into a decision — and if you write any calculation as a graph of tiny add/multiply/bend steps, a computer can later run gradients backward through it and learn the best weights."
