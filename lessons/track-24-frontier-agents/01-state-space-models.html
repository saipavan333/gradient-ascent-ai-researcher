State-space models: linear-time sequences

Transformers are powerful but their attention costs grow with the square of the sequence length — brutal for long inputs. State-space models like Mamba process sequences in linear time with a running state, while still remembering far into the past.

Track 20 · Lesson 1 Concept + code + interactive ~19 min Builds on: Track 8

The Transformer (Track 9) conquered sequence modeling with attention — every position looking at every other — but that superpower has a cost: comparing all pairs of positions is \(O(n^2)\) in the sequence length \(n\). Double the length and attention costs quadruple; for very long sequences (a whole book, a genome, high-resolution audio) it becomes prohibitive. State-space models (SSMs), and especially the Mamba architecture, are a leading challenger that attacks this wall. The idea is old and elegant: process the sequence like a recurrent network, carrying a compact running state forward one step at a time — \(h_t = a\,h_{t-1} + b\,x_t\), \(y_t = c\,h_t\) — which is \(O(n)\) time and uses \(O(1)\) memory per step, no matter how long the sequence. You saw this recurrence in Track 8's RNNs, which had two problems: they forgot quickly (vanishing gradients) and couldn't be parallelized. Modern SSMs fix both. They keep long memory by choosing the decay \(a\) very close to 1 (the state barely fades), and they can be computed in parallel with a clever "scan." Mamba's key addition is selectivity: it lets \(a\) and \(b\) depend on the input, so the model can choose what to remember and what to ignore — recovering much of attention's flexibility at linear cost. This lesson builds the core recurrence and shows it carrying information across a very long sequence.

💡 Intuition: a running summary instead of re-reading

Imagine reading a long novel two ways. The Transformer way: to understand each new sentence, flip back and re-scan every previous sentence — thorough but impossibly slow for a long book. The state-space way: keep a running mental summary that you update with each new sentence, never flipping back. The summary is a fixed-size "state" that compresses everything you've read so far. Updating it is cheap and constant per sentence, so reading a long book costs time proportional to its length, not its length squared. The trick is making the summary good — retaining what matters over long stretches (a state that decays slowly) and, in Mamba's case, deciding on the fly what's worth keeping in the summary versus forgetting.

The linear recurrence and its cost:

\[ h_t = a\,h_{t-1} + b\,x_t, \qquad y_t = c\,h_t \qquad\Rightarrow\qquad O(n)\ \text{time},\ \ O(1)\ \text{state} \ \ (\text{vs attention's } O(n^2)) \] (1.1)

Read it: the new state \(h_t\) is the old state \(h_{t-1}\) scaled by a decay \(a\), plus the new input \(x_t\) scaled by \(b\); the output \(y_t\) reads off the state via \(c\). Because each step does a constant amount of work and only the single state \(h\) is carried forward, processing the whole sequence is linear in its length and needs no growing memory. The magic parameter is \(a\): if \(a\) is close to 1, old information persists for a very long time (the state remembers); if \(a\) is small, it fades in a few steps (the state forgets).

🛠️ From scratch: the linear-recurrence scan

def ssm_scan(x, a, b, c):
    h = 0.0; ys = []
    for t in range(len(x)):
        h = a * h + b * x[t]      # carry one state forward — O(1) per step
        ys.append(c * h)
    return ys                     # whole sequence in O(n) time

# a=0.995: the sign of a pulse at t=0 survives to t=200 (long memory)
# a=0.5  : it decays away in ~20 steps (short memory)

This looks sequential, but the recurrence is linear, which means it can be computed with a parallel scan (an associative prefix-sum) — so it runs efficiently on GPUs, unlike a nonlinear RNN. That combination — linear-time and parallelizable and long-memory — is what makes modern SSMs a real alternative to attention.

Mamba's key idea: selectivity. A plain SSM has fixed \(a, b, c\) — it treats every input the same, which limits it. Mamba makes these parameters functions of the input: at each step, the model looks at \(x_t\) and decides how much to remember (\(a\)) and how much of the new input to absorb (\(b\)). This is like attention's ability to focus, but achieved within the linear recurrence. It lets Mamba selectively remember a name mentioned 10,000 tokens ago while ignoring filler — recovering much of what made attention powerful, at linear cost. That selectivity is why Mamba matches or beats Transformers on long-sequence tasks while scaling far better.

⚠️ Mistakes everyone makes here

  • Thinking SSMs are just old RNNs. They share the recurrence, but modern SSMs add long-memory parameterization, parallel scans, and (in Mamba) input-selectivity — fixing the very problems that sank RNNs.
  • Assuming linear cost means less capable. On long-sequence tasks, SSMs match or beat Transformers; the linear cost is a pure win there, not a compromise.
  • Ignoring the decay's role. The memory length is set by \(a\): too small and it can't do long-range, too close to 1 and it may never forget irrelevant things. Selectivity is what makes this adaptive.
  • Believing SSMs have replaced Transformers. They're a strong, growing alternative and often combined with attention (hybrid models), but Transformers remain dominant. It's an active competition, not a settled result.

🔑 Key results to remember

  • Attention is \(O(n^2)\); state-space models are \(O(n)\) time, \(O(1)\) state per step — far cheaper for long sequences.
  • Linear recurrence \(h_t=a\,h_{t-1}+b\,x_t\) (eq 1.1) carries a running summary; a decay \(a\) near 1 gives long memory.
  • Parallelizable via a scan (unlike nonlinear RNNs), so it's GPU-efficient.
  • Mamba adds selectivity: \(a,b\) depend on the input, so it chooses what to remember — attention-like focus at linear cost.
  • A leading alternative/complement to Transformers for long-context modeling.

✍️ Practice

1. (warm-up) In the interactive, set \(a=0.5\), then \(a=0.99\). How far into the sequence does the pulse survive in each case, and why?

Show solution

At \(a=0.5\) the state halves every step, so the pulse decays to near-nothing within about 10–20 steps — it's forgotten almost immediately. At \(a=0.99\) it decays by only 1% per step, so it persists for hundreds of steps (retaining \(0.99^t\), still ~0.13 after 200 steps) — long-range memory. The reason is simply the geometry of \(a^t\): the memory half-life is roughly \(0.7/(1-a)\) steps, so as \(a\) approaches 1 the half-life grows without bound. This is the whole mechanism of long-range memory in a linear SSM — push the decay close to 1 and the state becomes a long-lived running summary, all at \(O(n)\) cost. (Mamba then makes \(a\) input-dependent so it can hold a decay near 1 for important signals and drop it for noise.)

2. (transfer) A fixed decay \(a\) forces the same forgetting rate for every input. Give a task where that's a problem, and explain how selectivity helps.

Show solution

Consider reading a document where a key fact appears early ("the patient is allergic to penicillin") followed by pages of routine filler. With a fixed decay you're stuck: set \(a\) high enough to remember the allergy across all that filler, and you also stubbornly remember every irrelevant word; set \(a\) low to forget the filler, and you lose the allergy too. There's no single rate that both retains the important early fact and discards the noise. Selectivity (Mamba) solves this by letting \(a\) and \(b\) depend on the current input: when the model sees an important token it sets a near-1 decay to lock it into the state and a large \(b\) to absorb it; when it sees filler it sets a lower decay / small \(b\) to let it pass without cluttering the state. So the model dynamically remembers what matters and forgets what doesn't, rather than applying one blanket rate — which is exactly the content-dependent focus that made attention powerful, now achieved within a linear-time recurrence.

3. (stretch) Transformers and SSMs both model sequences but scale differently. When would you pick each, and why are hybrids appealing?

Show solution

Pick a Transformer when sequences are moderate-length and you want attention's proven, flexible any-to-any mixing — its \(O(n^2)\) cost is acceptable and it excels at tasks needing rich pairwise interactions (and it has the most mature tooling and pretrained models). Pick an SSM/Mamba when sequences are very long (long documents, audio, genomics, high-resolution signals) where \(O(n^2)\) is prohibitive but \(O(n)\) with long memory shines, or when you need fast, constant-memory streaming inference (an SSM carries a fixed state, so generating token by token doesn't grow a cache the way attention's KV-cache does). Hybrids are appealing because they can get the best of both: use cheap SSM layers to handle long-range context efficiently and sprinkle in a few attention layers where precise pairwise mixing helps most, keeping overall cost near-linear while retaining attention's strengths. Several strong recent models are exactly such hybrids, reflecting that this is an active, unsettled frontier rather than a winner-take-all — the practical answer is increasingly "combine them," matching each mechanism to what it does best.

🚀 In the real world & at the frontier

State-space models, led by Mamba, are one of the most exciting recent developments in sequence modeling — a serious challenger to the Transformer's decade-long dominance, especially for very long sequences where quadratic attention breaks down. They're being applied to language, audio, genomics, and time series, and hybrid architectures that interleave SSM and attention layers are an active and promising direction. The broader significance is that the field is actively searching for what comes after the Transformer, and SSMs prove that the quadratic-attention wall is not fundamental — you can have long memory and efficient scaling with a fundamentally different mechanism. Whether SSMs, hybrids, or something new wins out is one of the open questions at the frontier, and you now understand the core idea driving the contest.
