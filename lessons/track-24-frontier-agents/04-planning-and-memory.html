Planning & memory: agents that tackle the long haul

A single reason-act loop handles simple tasks. But truly complex, multi-step goals need more: the ability to plan ahead — search for a strategy before acting — and to remember across many steps. These are what turn a reactive agent into a capable one, and they close the course.

Track 20 · Lesson 4 Concept + code + interactive ~19 min Builds on: Lesson 3

The tool-using agent of Lesson 3 reacts step by step — great for tasks a few actions long. But ask an agent to write a whole program, plan a research project, or complete a task with dozens of interdependent steps, and pure step-by-step reaction breaks down: it makes a locally-sensible move that turns out to be a dead end, or it forgets what it decided ten steps ago. Two capabilities fix this, and they're the finale of the course. Planning is the ability to think ahead — to consider possible sequences of actions and find one that reaches the goal, rather than greedily grabbing whatever looks best right now. Memory is the ability to retain and recall information across the whole task — what's been tried, what was learned, what the current state is — beyond what fits in the model's immediate context window. Together, planning and memory let an agent handle long-horizon, complex tasks: decompose a big goal into sub-goals, search for a workable strategy, remember progress and intermediate results, and recover from mistakes. This is the current frontier of agent research, and building it — even in miniature — is a fitting capstone. This lesson shows planning solving what greedy reaction cannot, backed by memory of where it's been.

💡 Intuition: think before you leap, and take notes

Consider navigating a maze. The greedy strategy — always step toward the exit — gets you stuck at the first wall that requires briefly moving away from the goal. To solve a maze you must plan: mentally explore paths, including ones that detour, until you find one that reaches the end — and you must remember which dead ends you've already hit, so you don't wander in circles forever. That's planning plus memory. Planning is the mental search over possible action sequences before committing; memory is the record of what you've explored (so you don't repeat it) and what you've learned along the way. An agent without planning is a hiker who only ever walks downhill and gets trapped in the first valley; an agent without memory is one with amnesia who keeps re-treading the same ground. Real problem-solving needs both: look ahead, and remember where you've been.

Concretely: a greedy agent picks the immediately-best action; a planning agent searches over action sequences (using memory of visited states) to find one that reaches the goal:

\[ \text{greedy: } a_t = \arg\max_a \, \text{looks-best-now}(a) \qquad\text{vs}\qquad \text{plan: } \text{search sequences } (a_1,\dots,a_k) \text{ s.t. } \text{state}_k = \text{goal} \] (4.1)

Read it: the greedy agent commits to whatever single action looks best at the moment — no lookahead. The planner instead searches over multi-step sequences of actions to find one that actually reaches the goal, using memory (a record of visited states) to avoid re-exploring and looping. When reaching the goal requires a step that doesn't look immediately best (a detour), only the planner can find it — which is exactly when greedy fails.

✍️ Worked example: greedy fails, planning wins

1
Greedy. Always take the op that lands closest to 23. It commits to locally-best moves, overshoots or gets stuck, and returns None — no solution found.
2
Planner: search. Breadth-first search explores sequences of actions, level by level, from the start.

Planner: memory. A "visited" set (the agent's memory) records every state already seen, so the search never re-expands a state or loops forever.
4
Result. The planner finds [+3, +3, +3, ×2, +3]: 1→4→7→10→20→23. Executing it reaches exactly 23. Looking ahead with memory solved what step-by-step reaction could not.

🛠️ From scratch: planning with memory

def planner(start, target, ops):
    queue = deque([(start, [])]);  seen = {start}      # 'seen' = the agent's MEMORY
    while queue:
        x, path = queue.popleft()
        if x == target: return path                    # goal reached — return the plan
        for op in ops:                                 # SEARCH: try every next action
            nx = op(x)
            if nx not in seen:                          # memory prevents revisiting / loops
                seen.add(nx); queue.append((nx, path + [op.__name__]))
    return None

# greedy (no lookahead): None       |     planner: [+3, +3, +3, ×2, +3]  -> reaches 23

This is breadth-first search — the simplest planner — but the structure is what matters: explore possible action sequences (planning) while remembering visited states (memory). Real LLM agents plan in richer ways (decomposing goals into sub-tasks, using the model to propose and evaluate steps, sometimes searching over "trees of thought"), and use external memory stores (databases, vector search over past steps) that vastly exceed the model's context window. The skeleton — look ahead, and remember — is the same.

How real agents plan and remember. Modern agent systems implement these ideas at scale. For planning: task decomposition (break a goal into ordered sub-goals), and search over reasoning paths — "Tree of Thoughts" explores multiple reasoning branches and picks the best, a direct descendant of the search you built. For memory: since the model's context window is finite, agents use external memory — storing past observations, results, and reflections in a database and retrieving the relevant pieces when needed (the same retrieval idea as RAG). Some agents even keep a running "scratchpad" and periodically summarize it. These let an agent work on tasks far longer and more complex than a single prompt could hold — the difference between answering a question and completing a project.

⚠️ Mistakes everyone makes here

  • Relying on greedy reaction for complex tasks. Without lookahead, an agent commits to locally-good moves that lead to dead ends. Long-horizon tasks need planning.
  • Planning without memory. Search that doesn't remember visited states loops forever or re-does work. Memory (visited set, scratchpad, external store) is what makes search tractable.
  • Assuming the context window is enough memory. Long tasks generate more information than fits in context; you need external memory with retrieval, or the agent "forgets" earlier steps.
  • Ignoring the cost of search. Planning explores many possibilities, which is expensive. Real systems balance how much to plan versus act, and use the LLM to prune the search smartly.

🔑 Key results to remember

  • Greedy reaction fails on tasks needing a step that isn't immediately best (a detour) — no lookahead.
  • Planning searches over action sequences to find one that reaches the goal (eq 4.1).
  • Memory (visited states / scratchpad / external store) prevents loops and retains progress beyond the context window.
  • Real agents: task decomposition + search (Tree of Thoughts) for planning; retrieval-based external memory for recall.
  • Together they enable long-horizon tasks — the frontier of agent capability.

✍️ Practice

1. (warm-up) In the interactive, find a target where greedy fails but planning succeeds. What does greedy do wrong, and what does the planner do differently?

Show solution

Greedy fails whenever reaching the target requires a step that temporarily moves away from it — for example, needing to ×2 past the target and then... no; more precisely, needing a sequence where the locally-closest op at some point leads to a dead end. Greedy always picks the op landing nearest the target right now, so it commits to a path with no lookahead and gets stuck (or overshoots) with no way to back up. The planner instead explores all action sequences breadth-first, remembering visited states so it never loops, until it finds one that actually reaches the goal — even if that path includes steps that didn't look best at the time. The difference is lookahead plus memory: the planner considers the whole route to the goal, while greedy only ever sees one step. This is the core reason complex, multi-step tasks need planning, not just reaction.

2. (transfer) "Tree of Thoughts" has an LLM generate several possible next reasoning steps, evaluate them, and explore the promising ones — like a search. How is that the planning idea from this lesson, applied to reasoning?

Show solution

It's exactly the search-over-sequences idea, but the "actions" are reasoning steps instead of arithmetic ops, and the "states" are partial solutions/thoughts. Standard chain-of-thought is greedy: the model commits to one reasoning path and follows it, so a wrong early step dooms the answer. Tree of Thoughts instead treats reasoning as a search tree — at each point the LLM proposes several possible next thoughts (branching), a scoring step evaluates how promising each partial solution is, and the search explores the best branches (and can backtrack from dead ends), just like the BFS planner explores and prunes action sequences. The LLM plays two roles the toy planner hard-coded: it generates the candidate next steps (instead of a fixed op list) and evaluates them (instead of a simple goal check). So planning generalizes from "search over discrete actions" to "search over reasoning," letting the model deliberate — explore alternatives and choose — rather than blurting the first path. This deliberate, search-based reasoning is one of the most effective ways to boost LLM performance on hard multi-step problems, and it's a direct scaling-up of the planning principle you just built.

3. (capstone) You've reached the end of the course. Using planning and memory as the lens, describe what still separates today's agents from a reliable human assistant — and connect it to the arc of everything you've learned.

Show solution

Today's agents can plan and remember in limited ways — decompose tasks, search over some steps, retrieve from external stores — but they remain brittle on long-horizon work: errors compound over many steps, plans go stale as situations change, memory retrieval misses relevant context, and there's no robust self-correction when things go wrong. A reliable human assistant maintains a coherent goal over days, notices and recovers from its own mistakes, knows when it's uncertain and asks, and — crucially — can be trusted to act safely. Closing that gap draws on the entire course: the foundations (linear algebra, probability, optimization) that make any of it possible; the architectures (deep nets, CNNs, Transformers, and the frontier ones here) that provide the raw capability; learning paradigms (self-/semi-/few-shot, meta-learning) for adapting with little data; probabilistic methods and calibration so the agent knows what it doesn't know; causal reasoning so it can act rather than just predict; efficiency so the system is affordable to run; and safety, privacy, and interpretability so it can be trusted with real actions and real data. An agent is where all of these meet — perception, reasoning, memory, action, and the judgment to do it safely. The honest state of the art is impressive but unfinished, and the people who will push it forward are exactly those who understand it from the ground up.
